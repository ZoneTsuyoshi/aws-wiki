# IAM とルートユーザー の問題集

対象の解説: [IAM](../../../services/iam.md)、[ID とディレクトリ](../../../services/identity-directory.md)、[クラウドの基礎](../../../services/cloud-foundations.md)

### 問1 {#q1}

EC2 上のアプリから S3 のファイルを読みたいと考えています。認証情報の渡し方として最も適切なものはどれですか。

- A. IAM ユーザーのアクセスキーをサーバーの設定ファイルに書く
- B. EC2 にロールを割り当て、一時的な認証情報を使う
- C. ルートユーザーのアクセスキーを環境変数に設定する
- D. パスワードをアプリのソースコードに書いて使う

??? success "答えと解説"
    **正解: B**

    ロールは一時的な認証情報を受け取ります。アプリや AWS サービスに向いています。

    - A: 誤り。長期の認証情報を置くことになり、漏えいの恐れがある。
    - B: 正しい。
    - C: 誤り。ルートのアクセスキーは作らない。
    - D: 誤り。コードに認証情報を書かない。

    **スキル:** [IAM の要素](../domain2.md#t2-3-iam) / **参照:** [プリンシパルと権限の定義](../../../services/iam.md#principals)

### 問2 {#q2}

新しく入社した 10 人の開発者に、同じ権限をまとめて与えたいと考えています。最も適切な方法はどれですか。

- A. 全員にルートユーザーのパスワードを渡す
- B. 10 人それぞれに同じインラインポリシーを書く
- C. グループを作って権限を付け、ユーザーを追加する
- D. 全員で 1 つの IAM ユーザーを共有して使う

??? success "答えと解説"
    **正解: C**

    グループはユーザーの集まりで、まとめて権限を与えられます。

    - A: 誤り。ルートは日常の作業に使わない。
    - B: 誤り。管理が煩雑になり、変更の漏れも起きやすい。
    - C: 正しい。
    - D: 誤り。誰が操作したか追跡できなくなる。

    **スキル:** [IAM の要素](../domain2.md#t2-3-iam) / **参照:** [プリンシパルと権限の定義](../../../services/iam.md#principals)

### 問3 {#q3}

IAM の要素の説明として正しいものはどれですか。（2つ選択）

- A. ユーザーは一時的な認証情報だけを持つ主体である
- B. ポリシーはユーザーのパスワードの長さだけを決める
- C. ポリシーは権限を JSON で定義する
- D. ロールは一時的な認証情報を受け取る
- E. グループは他のアカウントからサインインするための ID である

??? success "答えと解説"
    **正解: C, D**

    ユーザー、グループ、ロール、ポリシーの役割を区別します。

    - A: 誤り。ユーザーは長期の認証情報を持つ主体。
    - B: 誤り。パスワードの条件はパスワードポリシーで決める。
    - C: 正しい。
    - D: 正しい。
    - E: 誤り。グループはユーザーの集まりで、それ自体でサインインしない。

    **スキル:** [IAM の要素](../domain2.md#t2-3-iam) / **参照:** [プリンシパルと権限の定義](../../../services/iam.md#principals)

### 問4 {#q4}

最小権限の原則の説明として正しいものはどれですか。

- A. 作業に必要な権限だけを与える
- B. 利用者ごとに同じ AWS 管理ポリシーを必ず付ける
- C. 後で困らないように、最初に管理者の権限を与える
- D. 権限をすべて拒否して、誰にも作業させない

??? success "答えと解説"
    **正解: A**

    最小権限は、作業に必要な権限だけを与える原則です。

    - A: 正しい。
    - B: 誤り。既製のポリシーは広めになりやすく、必要な権限に絞れるとは限らない。
    - C: 誤り。必要以上の権限で、原則に反する。
    - D: 誤り。作業に必要な権限は与える。

    **スキル:** [最小権限とポリシーの種類](../domain2.md#t2-3-least-privilege) / **参照:** [最小権限](../../../services/iam.md#least-privilege)

### 問5 {#q5}

ある作業に必要な操作と対象を具体的に絞り、複数のロールで使い回したいと考えています。最も適切なポリシーはどれですか。

- A. インラインポリシー
- B. AWS 管理ポリシー
- C. サービスコントロールポリシー
- D. カスタマー管理ポリシー

??? success "答えと解説"
    **正解: D**

    カスタマー管理ポリシーは必要な権限に絞れて、複数に付けられます。

    - A: 誤り。1 つのユーザーやロールに埋め込むので、使い回しに向かない。
    - B: 誤り。すぐ使えるが広めの権限になりやすく、利用者は内容を変更できない。
    - C: 誤り。組織で使える操作の上限を決めるもので、権限を与えるものではない。
    - D: 正しい。

    **スキル:** [最小権限とポリシーの種類](../domain2.md#t2-3-least-privilege) / **参照:** [管理ポリシーとインラインポリシー](../../../services/iam.md#managed-vs-inline)

ポリシーの種類と特徴の組み合わせとして正しいものはどれですか。

- A. インラインポリシー: 複数のユーザーに同時に付けられる
- B. AWS 管理ポリシー: AWS が作成し、すぐ使える
- C. カスタマー管理ポリシー: AWS が作成し、内容を更新する
- D. AWS 管理ポリシー: 利用者が自由に内容を書き換えられる

??? success "答えと解説"
    **正解: B**

    作成者と使い回しやすさで区別します。

    - A: 誤り。1 つのユーザーやロールに直接埋め込む。
    - B: 正しい。
    - C: 誤り。利用者が作成して管理する。
    - D: 誤り。AWS 管理ポリシーの内容は AWS が管理する。

    **スキル:** [最小権限とポリシーの種類](../domain2.md#t2-3-least-privilege) / **参照:** [管理ポリシーとインラインポリシー](../../../services/iam.md#managed-vs-inline)
