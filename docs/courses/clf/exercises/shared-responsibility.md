# 責任共有モデル の問題集

対象の解説: [クラウドの基礎](../../../services/cloud-foundations.md)

### 問1 {#q1}

責任共有モデルで、AWS と利用者の担当を表す言葉の組み合わせとして正しいものはどれですか。

- A. AWS と利用者は、どちらも「クラウド全体のセキュリティ」を同じ範囲で担当する
- B. AWS が契約の時点で、すべてのセキュリティの責任を引き受ける
- C. AWS は「クラウドのセキュリティ」、利用者は「クラウドの中のセキュリティ」
- D. AWS は「クラウドの中のセキュリティ」、利用者は「クラウドのセキュリティ」

??? success "答えと解説"
    **正解: C**

    AWS は基盤を、利用者はその上に置くデータや設定を守ります。

    - A: 誤り。担当の範囲は分かれている。
    - B: 誤り。利用者の担当が残る。
    - C: 正しい。
    - D: 誤り。担当が逆。

    **スキル:** [モデルの全体像](../domain2.md#t2-1-model) / **参照:** [責任共有モデル](../../../services/cloud-foundations.md#shared-responsibility)

### 問2 {#q2}

責任共有モデルが分担の対象とするものはどれですか。

- A. 請求と支払いの方法
- B. 性能の目標と値引きの率
- C. サポートの窓口と契約の期間
- D. セキュリティとコンプライアンス

??? success "答えと解説"
    **正解: D**

    責任共有モデルは、セキュリティとコンプライアンスの分担を示します。

    - A: 誤り。分担の対象ではない。
    - B: 誤り。分担の対象ではない。
    - C: 誤り。分担の対象ではない。
    - D: 正しい。

    **スキル:** [モデルの全体像](../domain2.md#t2-1-model) / **参照:** [責任共有モデル](../../../services/cloud-foundations.md#shared-responsibility)

### 問3 {#q3}

責任共有モデルの理解として正しいものはどれですか。

- A. AWS は基盤を守るが、利用者が置いたデータと設定は利用者が守る
- B. マネージドサービスを使えば、利用者の責任はなくなる
- C. どのサービスを使っても、利用者の担当範囲は完全に同じである
- D. AWS がデータの中身を確認して、公開してよいかどうかを利用者の代わりに判断する

??? success "答えと解説"
    **正解: A**

    担当の境界はサービスで変わりますが、データと権限はどのサービスでも利用者の担当です。

    - A: 正しい。
    - B: 誤り。データや権限の責任は残る。
    - C: 誤り。サービスの種類で担当範囲が変わる。
    - D: 誤り。利用者のデータの扱いは利用者が決める。

    **スキル:** [モデルの全体像](../domain2.md#t2-1-model) / **参照:** [責任共有モデル](../../../services/cloud-foundations.md#shared-responsibility)

### 問4 {#q4}

責任共有モデルで、利用者の責任に当たるものはどれですか。（2つ選択）

- A. S3 バケットの公開の設定
- B. ハードウェアの故障した部品の交換
- C. 仮想化層のパッチの適用
- D. IAM の権限の設定
- E. データセンターの入退室の管理

??? success "答えと解説"
    **正解: A, D**

    データ、権限、暗号化の設定、ネットワークのアクセス制御、アプリは利用者の担当です。

    - A: 正しい。
    - B: 誤り。ハードウェアは AWS の担当。
    - C: 誤り。仮想化層は AWS の担当。
    - D: 正しい。
    - E: 誤り。物理施設は AWS の担当。

    **スキル:** [利用者の責任](../domain2.md#t2-1-customer) / **参照:** [責任共有モデル](../../../services/cloud-foundations.md#shared-responsibility)

### 問5 {#q5}

S3 バケットを誤って公開にして、顧客情報が漏えいしました。責任共有モデルでは誰の責任ですか。

- A. AWS と利用者が必ず半分ずつ負う
- B. そのバケットの設定を行った利用者
- C. 通信回線の事業者
- D. ストレージを提供している AWS

??? success "答えと解説"
    **正解: B**

    バケットのアクセス設定は利用者の担当です。

    - A: 誤り。このような分担の定めはない。
    - B: 正しい。
    - C: 誤り。回線の問題ではなく、公開の設定の問題。
    - D: 誤り。AWS が設定を代わりに判断することはない。

    **スキル:** [利用者の責任](../domain2.md#t2-1-customer) / **参照:** [責任共有モデル](../../../services/cloud-foundations.md#shared-responsibility)

### 問6 {#q6}

EC2 上のアプリで、通信を許可するポートをセキュリティグループで決める作業の担当はどれですか。

- A. AWS Trust & Safety
- B. 利用者
- C. AWS Support
- D. AWS

??? success "答えと解説"
    **正解: B**

    ネットワークのアクセス制御の設定は利用者の担当です。

    - A: 誤り。悪用の報告の窓口で、利用者の設定は行わない。
    - B: 正しい。
    - C: 誤り。サポートは相談の窓口で、設定の責任は負わない。
    - D: 誤り。AWS はセキュリティグループのルールの中身を決めない。

    **スキル:** [利用者の責任](../domain2.md#t2-1-customer) / **参照:** [責任共有モデル](../../../services/cloud-foundations.md#shared-responsibility)

### 問8 {#q8}

Lambda 関数を動かす基盤のサーバーのセキュリティ対策の担当はどれですか。

- A. AWS
- B. AWS と AWS Partner の共同
- C. 利用者
- D. 関数を呼び出した外部のユーザー

??? success "答えと解説"
    **正解: A**

    マネージドサービスの基盤は AWS の担当です。

    - A: 正しい。
    - B: 誤り。パートナーはこの責任を負わない。
    - C: 誤り。利用者は基盤のサーバーを管理しない。コードや権限が担当。
    - D: 誤り。呼び出す側は基盤に責任を負わない。

    **スキル:** [AWS の責任](../domain2.md#t2-1-aws) / **参照:** [責任共有モデル](../../../services/cloud-foundations.md#shared-responsibility)

### 問10 {#q10}

パッチ管理の分担として正しいものはどれですか。

- A. どのサービスでも、AWS がすべてのパッチを適用する
- B. AWS はゲスト OS とアプリ、利用者はインフラを担当する
- C. AWS はインフラ、利用者はゲスト OS とアプリを担当する
- D. どのサービスでも、利用者がすべてのパッチを適用する

??? success "答えと解説"
    **正解: C**

    パッチ管理は共有の項目で、それぞれが自分の層を担当します。

    - A: 誤り。EC2 のゲスト OS などは利用者の担当。
    - B: 誤り。担当が逆。
    - C: 正しい。
    - D: 誤り。インフラのパッチは AWS の担当。

    **スキル:** [共有する責任](../domain2.md#t2-1-shared) / **参照:** [責任共有モデル](../../../services/cloud-foundations.md#shared-responsibility)

### 問12 {#q12}

セキュリティの教育について、責任共有モデルに沿った説明はどれですか。

- A. AWS が利用者の従業員の教育をすべて引き受ける
- B. 教育は責任共有モデルの対象にまったく含まれない
- C. AWS は自社の従業員を、利用者は自社の従業員を教育する
- D. 利用者が AWS の従業員の教育の内容を決めて、代わりに実施する

??? success "答えと解説"

    教育は共有の項目で、それぞれが自社の従業員を担当します。

    - A: 誤り。自社の従業員の教育は利用者の担当。
    - B: 誤り。共有の項目に含まれる。
    - C: 正しい。
    - D: 誤り。AWS の従業員の教育は AWS の担当。

### 問13 {#q13}

EC2 にデータベースを自分で入れる構成から Amazon RDS に変えました。担当が利用者から AWS に移るものはどれですか。

- A. データベースにアクセスする権限の管理
- B. データベースに保存するデータの管理
- C. テーブルの設計と SQL の内容
- D. 基盤のゲスト OS のパッチの適用

??? success "答えと解説"
    **正解: D**

    RDS では OS のパッチは AWS の担当になります。

    - A: 誤り。権限はどちらでも利用者の担当。
    - B: 誤り。データはどちらでも利用者の担当。
    - C: 誤り。スキーマと SQL は RDS でも利用者の担当。
    - D: 正しい。

    **スキル:** [サービスによる責任の変化](../domain2.md#t2-1-by-service) / **参照:** [サービスごとの違い](../../../services/cloud-foundations.md#responsibility-by-service)

### 問14 {#q14}

Lambda で利用者の担当として残るものはどれですか。（2つ選択）

- A. 実行するサーバーの OS のパッチ
- B. 関数のコード
- C. 実行基盤の物理的なセキュリティ
- D. 関数に与える権限
- E. 仮想化層の保守

??? success "答えと解説"
    **正解: B, D**

    Lambda では基盤と OS は AWS が担当し、コード、データ、権限は利用者が担当します。

    - A: 誤り。AWS の担当。
    - B: 正しい。
    - C: 誤り。AWS の担当。
    - D: 正しい。
    - E: 誤り。AWS の担当。

    **スキル:** [サービスによる責任の変化](../domain2.md#t2-1-by-service) / **参照:** [サービスごとの違い](../../../services/cloud-foundations.md#responsibility-by-service)

### 問15 {#q15}

EC2、RDS、Lambda のうち、利用者がゲスト OS のパッチを担当するものはどれですか。

- A. RDS だけ
- B. EC2 だけ
- C. Lambda だけ
- D. 3 つすべて

??? success "答えと解説"
    **正解: B**

    抽象度が高いサービスほど利用者の担当は減ります。EC2 のゲスト OS は利用者の担当です。

    - A: 誤り。RDS の OS のパッチは AWS の担当。
    - B: 正しい。
    - C: 誤り。Lambda の OS は AWS の担当。
    - D: 誤り。RDS と Lambda の OS は AWS の担当。

    **スキル:** [サービスによる責任の変化](../domain2.md#t2-1-by-service) / **参照:** [サービスごとの違い](../../../services/cloud-foundations.md#responsibility-by-service)

### 問16 {#q16}

抽象度が高いサービスを選んだときの変化として正しいものはどれですか。

- A. 利用者の担当は減るが、データと権限の担当は残る
- B. 利用者の担当が増え、OS のパッチまで利用者が行う
- C. AWS の担当が減り、物理施設は利用者が守る
- D. 利用者の担当がすべてなくなり、設定の責任もなくなる

??? success "答えと解説"
    **正解: A**

    データと権限は、どのサービスでも利用者の担当です。

    - A: 正しい。
    - B: 誤り。逆に減る。
    - C: 誤り。物理施設は常に AWS の担当。
    - D: 誤り。データや権限は残る。

    **スキル:** [サービスによる責任の変化](../domain2.md#t2-1-by-service) / **参照:** [サービスごとの違い](../../../services/cloud-foundations.md#responsibility-by-service)
