# 分野1: Knowledge Bases の文書の準備

RAG の精度は取り込みの段階で決まります。パーサー、チャンク、メタデータを文書に合わせて選びます。

## 問われるスキル {#skills}

| スキル | 内容 |
|---|---|
| [1.2.7](../../domain1.md#skill-1-2-7) | RAG 向けの文書の準備 |

## 学習の順番 {#study-order}

1. [取り込みの流れ](../../../../services/genai-apps.md#kb-ingestion): パーサーの違いと料金を確認します。
2. [チャンク化](../../../../services/genai-apps.md#chunking): 戦略ごとの向いている文書を覚えます。
3. [メタデータ](../../../../services/genai-apps.md#kb-metadata): ファイル名の決まりと `faiss` の条件を押さえます。

## 覚える値 {#values}

| 項目 | 値 | 判断のポイント |
|---|---|---|
| 既定のチャンク | 約 300 トークン | 文の境界を保つ |
| 固定サイズの `maxTokens` | 1〜8,192 | モデルの入力上限を超えない |
| メタデータのファイル名 | `<ファイル名>.metadata.json` | 拡張子まで揃える |

## こう問われたらこう考える {#decisions}

| 状況 | 判断 |
|---|---|
| 表や図を含む PDF | BDA か FM のパーサー |
| 章と節の構造を持つ規定集 | 階層 |
| 話題が途中で変わる文書 | セマンティック（追加料金） |
| FAQ など独自の構造 | なし + Lambda |
| 部署や更新日で絞る | メタデータ |

## 引っかかりやすい点 {#traps}

- 既定のパーサーは図の内容を取り出せません。BDA や FM を選ぶと、文字だけの PDF にも適用されて課金されます。
- 階層チャンクは、返る件数が指定より少なくなります。
- `nmslib` のインデックスでは、メタデータファイルが無視されます。
