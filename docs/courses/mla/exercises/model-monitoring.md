# モデルの監視とテストの問題集

対象の解説: [Model Monitor](../../../services/sagemaker.md#model-monitor)、[ドリフトの種類](../../../services/sagemaker.md#drift)、[デプロイとテストの戦略](../../../services/sagemaker.md#deployment-strategies)

### 問1 {#q1}

半年で精度が落ちましたが、入力の分布はほとんど変わっていません。どのドリフトですか。

- A. 集団別の指標を比べるバイアスドリフト
- B. コンセプトドリフト
- C. データドリフト
- D. 出力の分布だけが変わる予測ドリフト

??? success "答えと解説"
    **正解: B**

    コンセプトドリフトは入力と正解の関係の変化です。正解ラベルとの比較で検出します。

    - A: 誤り。集団間の差の変化です。
    - B: 正しい。
    - C: 誤り。入力の分布の変化で、この症状とは合いません。
    - D: 誤り。出力の分布の変化を指し、入力と正解の関係の変化を示しません。

    **スキル:** [2.3.2](../domain2.md#skill-2-3-2) / **参照:** [ドリフトの種類](../../../services/sagemaker.md#drift)

### 問2 {#q2}

既に SageMaker Model Monitor を使っているチームが、データ品質を監視します。流れとして正しいものはどれですか。

- A. ベースラインを作り、キャプチャとスケジュールで比較する
- B. データキャプチャで取得し、再学習してからベースラインを作る
- C. スケジュールは作らず、問題が起きてから全件を手で比較する運用にする
- D. CloudTrail で入力を取得し、ベースラインなしで比較する

??? success "答えと解説"
    **正解: A**

    ベースラインの統計と制約を作り、データキャプチャで本番のデータを取り、スケジュールで比較して、結果を CloudWatch に出します。

    - A: 正しい。
    - B: 誤り。本番と比べるベースラインは学習時のデータから先に作ります。
    - C: 誤り。継続の監視になりません。
    - D: 誤り。CloudTrail は API の記録で、入力の分布を取得しません。

    **スキル:** [2.3.2](../domain2.md#skill-2-3-2) / **参照:** [Model Monitor](../../../services/sagemaker.md#model-monitor)

### 問3 {#q3}

新規の顧客がドリフトの監視を作ります。Model Monitor は新規の受付を終了しています。公式の移行先に沿った構成はどれですか。

- A. Debugger の組み込みルールで本番のエンドポイントの入力を定期的に監視する
- B. Bedrock Guardrails で入力の分布を比較する
- C. Processing で Evidently AI を動かし、EventBridge Scheduler で定期実行する
- D. Macie の検出ジョブを EventBridge Scheduler で毎日実行し、結果を SNS で通知する

??? success "答えと解説"
    **正解: C**

    移行後の構成は、Processing で Evidently AI を動かし、EventBridge Scheduler で定期実行し、SNS で通知します。

    - A: 誤り。学習中の問題の検出の機能で、新規の受付も終了しています。
    - B: 誤り。安全策の機能で、分布の監視の機能ではありません。
    - C: 正しい。
    - D: 誤り。機密データの検出で、分布を比較しません。

    **スキル:** [2.3.2](../domain2.md#skill-2-3-2) / **参照:** [Model Monitor](../../../services/sagemaker.md#model-monitor)

### 問4 {#q4}

新しいモデルの遅延と安定性を、利用者に影響を与えずに本番のトラフィックで確かめます。どの方式ですか。

- A. All at once のブルー/グリーンデプロイ
- B. Canary デプロイ
- C. A/B テスト
- D. シャドウテスト

??? success "答えと解説"
    **正解: D**

    シャドウテストはリクエストのコピーを新しいバリアントに送り、応答は利用者に返しません。

    - A: 誤り。全トラフィックが新しいモデルへ移ります。
    - B: 誤り。一部の利用者に新しいモデルの応答が返ります。
    - C: 誤り。利用者が新しいモデルの応答を受け取ります。
    - D: 正しい。

    **スキル:** [2.3.3](../domain2.md#skill-2-3-3) / **参照:** [デプロイとテストの戦略](../../../services/sagemaker.md#deployment-strategies)

### 問5 {#q5}

シャドウテストで比べる項目の組み合わせとして適切なものはどれですか。

- A. `ModelLatency`、エラー率、インスタンスの使用率
- B. 利用者のクリック率と売上、カートへの追加の件数だけ
- C. CI と DPL だけ
- D. `BLEU`、`ROUGE`、`BERTScore` だけ

??? success "答えと解説"
    **正解: A**

    シャドウでは `ModelLatency`、エラー率、インスタンスの使用率を比べます。正解は後から届くので、精度を見るならログを保存して結合します。

    - A: 正しい。
    - B: 誤り。シャドウの応答は利用者に返らないので、業務指標は測れません。
    - C: 誤り。学習データのバイアスの指標です。
    - D: 誤り。応答の文の評価で、シャドウの遅延と安定性を見ていません。

    **スキル:** [2.3.3](../domain2.md#skill-2-3-3) / **参照:** [デプロイとテストの戦略](../../../services/sagemaker.md#deployment-strategies)、[CloudWatch のメトリクス](../../../services/sagemaker.md#cloudwatch-metrics)

### 問6 {#q6}

シャドウテストで新しいモデルの精度も確かめます。正解のラベルは数日後に届きます。どうしますか。

- A. 正解は使わず、エラー率が低ければ精度も高いと判断する
- B. シャドウの応答を利用者に返して反応を見る
- C. 応答のログを保存して、届いた正解と結合する
- D. `ModelLatency` を精度の代わりにする

??? success "答えと解説"
    **正解: C**

    正解が後から届くなら、応答のログを保存して結合します。

    - A: 誤り。エラー率は精度と別の指標です。
    - B: 誤り。シャドウではなくなり、利用者に影響します。
    - C: 正しい。
    - D: 誤り。遅延の指標で、精度を示しません。

    **スキル:** [2.3.3](../domain2.md#skill-2-3-3) / **参照:** [デプロイとテストの戦略](../../../services/sagemaker.md#deployment-strategies)

### 問7 {#q7}

Bedrock のアプリ全体を、モデルの呼び出し、ナレッジベース、ガードレール、ツールまで通して監視します。プロンプトをエンドツーエンドで追います。どの機能ですか。

- A. X-Ray のサービスマップ
- B. AWS Config の適合パックと修復のアクション
- C. 呼び出しログを Logs Insights で手で集計する
- D. CloudWatch の生成 AI オブザーバビリティ

??? success "答えと解説"
    **正解: D**

    CloudWatch の生成 AI オブザーバビリティは、呼び出し、エージェント、ナレッジベース、ガードレール、ツールを通して見られます。

    - A: 誤り。サービス間の遅い箇所を探す機能で、ガードレールやナレッジベースまでプロンプト単位では追いません。
    - B: 誤り。設定の記録です。
    - C: 誤り。ログの内容は見られますが、ナレッジベースやツールまで通した追跡の画面になりません。
    - D: 正しい。

    **スキル:** [4.1.1](../domain4.md#skill-4-1-1) / **参照:** [生成 AI オブザーバビリティ](../../../services/genai-apps.md#genai-observability)

### 問8 {#q8}

FM の回答の品質を本番のダッシュボードに出します。`AWS/Bedrock` の運用の指標に品質の指標はありません。どうしますか。

- A. `InvocationLatency` を品質の指標とする
- B. 評価の結果をカスタムメトリクスとして送る
- C. X-Ray のサービスマップで品質を見る
- D. `Invocations` が多ければ品質が高いと判断する

??? success "答えと解説"
    **正解: B**

    品質は運用の指標には出ないので、Bedrock Evaluations などの結果をカスタムメトリクスとして送ります。

    - A: 誤り。遅延の指標で、品質を示しません。
    - B: 正しい。
    - C: 誤り。遅い箇所を探す機能です。
    - D: 誤り。呼び出しの回数で、品質を示しません。

    **スキル:** [4.1.1](../domain4.md#skill-4-1-1) / **参照:** [生成 AI オブザーバビリティ](../../../services/genai-apps.md#genai-observability)、[Bedrock のメトリクス](../../../services/ai.md#bedrock-metrics)

### 問9 {#q9}

不正検知の本番のモデルで、精度を監視します。正解は数週間後に届きます。監視の組み合わせとして適切なものを選んでください。（2つ選択）

- A. 届いた正解と予測を結合して、モデル品質を見る
- B. `Invocation4XXErrors` が 0 なら精度も問題ないと判断する
- C. 正解が届くまで何も監視しない
- D. 届くまでの間は入力の分布を見る
- E. 入力の分布が変わらなければ精度も必ず保たれると判断する

??? success "答えと解説"
    **正解: A, D**

    正解が遅れて届くなら、まず入力の分布を見ます。正解が届いたら結合して精度を監視します。

    - A: 正しい。精度の低下を直接確かめられます。
    - B: 誤り。クライアントのエラーで、精度とは別です。
    - C: 誤り。問題に気付くのが遅れます。
    - D: 正しい。精度の低下より先に分かる兆候です。
    - E: 誤り。コンセプトドリフトは分布の監視では検出できません。

    **スキル:** [4.1.1](../domain4.md#skill-4-1-1), [4.1.3](../domain4.md#skill-4-1-3) / **参照:** [Model Monitor](../../../services/sagemaker.md#model-monitor)、[ドリフトの種類](../../../services/sagemaker.md#drift)

### 問10 {#q10}

データキャプチャで、本番のリクエストの 20% を S3 に保存します。設定する項目はどれですか。

- A. `CaptureOptions` を 20 にする
- B. `InitialVariantWeight` を 0.2 にする
- C. `InitialSamplingPercentage` を 20 にする
- D. `DestinationS3Uri` に 20 を指定する

??? success "答えと解説"
    **正解: C**

    データキャプチャの割合は `InitialSamplingPercentage` で決めます。

    - A: 誤り。入力と出力のどちらを保存するかの設定です。
    - B: 誤り。トラフィックの配分の設定です。
    - C: 正しい。
    - D: 誤り。保存先の S3 の場所の設定です。

### 問13 {#q13}

エンドポイントに 2 つの本番バリアントがあります。作り直さずに、新しいモデルへの配分を 10% から 50% に変えます。どの API ですか。

- A. `UpdateEndpointWeightsAndCapacities`
- B. `CreateModelPackage`
- C. `UpdateInferenceComponent`
- D. `CreateEndpoint` で新しい配分のエンドポイントを別に作る

??? success "答えと解説"
    **正解: A**

    `UpdateEndpointWeightsAndCapacities` なら、エンドポイントを作り直さずに配分を変えられます。

    - A: 正しい。
    - B: 誤り。Model Registry の登録です。
    - C: 誤り。推論コンポーネントのコピーや資源を変える API で、本番バリアントの配分を変えません。
    - D: 誤り。新しいエンドポイントの作成で、要件に合いません。

    **スキル:** [4.1.4](../domain4.md#skill-4-1-4) / **参照:** [デプロイとテストの戦略](../../../services/sagemaker.md#deployment-strategies)

### 問15 {#q15}

新しいレコメンドのモデルが遅延では勝ちました。導入の判断の進め方として適切なものはどれですか。

- A. 10% だけ流し、コンバージョン率を比べて増やす
- B. 遅延が勝ったので、全トラフィックを移して終わりにする
- C. `Invocations` が多いほうを勝ちにする
- D. シャドウの結果だけで売上が上がると判断する

??? success "答えと解説"
    **正解: A**

    先にシャドウで安定性を確かめ、次に一部へ流して業務指標を比べ、結果を見て増やします。

    - A: 正しい。
    - B: 誤り。業務指標への影響を見ていません。
    - C: 誤り。配分で決まる値で、モデルのよさを示しません。
    - D: 誤り。シャドウの応答は利用者に返らないので、業務指標を測れません。

    **スキル:** [4.1.4](../domain4.md#skill-4-1-4) / **参照:** [デプロイとテストの戦略](../../../services/sagemaker.md#deployment-strategies)
