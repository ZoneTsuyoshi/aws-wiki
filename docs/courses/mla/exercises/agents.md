### 問1 {#q1}

2026 年後半に新しいエージェントを作ります。LangGraph の独自コードをそのまま動かし、セッションごとに分離します。どれを選びますか。

- A. Bedrock Agents（Agents Classic）を新規に作る
- B. AgentCore Harness で独自のコードを動かす
- C. SageMaker AI のバッチ変換
- D. AgentCore Runtime

??? success "答えと解説"
    **正解: D**

    独自のフレームワークやコードは AgentCore Runtime で動かします。セッションごとに microVM で分離します。

    - A: 誤り。2026-07-30 から新規の受付を終了しています。
    - B: 誤り。モデル、プロンプト、ツールを指定するだけの場面の選択で、独自のコードの実行なら Runtime です。
    - C: 誤り。データセット全体の推論の方式で、エージェントの実行基盤ではありません。
    - D: 正しい。

    **スキル:** [3.1.6](../domain3.md#skill-3-1-6) / **参照:** [Runtime の選び方](../../../services/genai-apps.md#agentcore-runtime)、[Agents Classic](../../../services/genai-apps.md#agents-classic)

AgentCore Runtime で動かすサーバーの種類と、既定の提供ポートの組み合わせとして正しいものを選んでください。（2つ選択）

### 問4 {#q4}

同じ Runtime のエージェントを複数の利用者が使います。AgentCore Memory で別の利用者の記憶が混ざりました。最初に確認する設定はどれですか。

- A. `actorId` を利用者ごとに分けているか
- B. `sessionId` を利用者ごとに分けているか
- C. 長期のストラテジーの数を増やしたか
- D. `idleRuntimeSessionTimeout` を最大にしたか

??? success "答えと解説"
    **正解: A**

    `actorId` を利用者ごとに分けないと、別の利用者の記憶が混ざります。

    - A: 正しい。
    - B: 誤り。会話のセッションを区別する値で、利用者の記憶を分けるのは `actorId` です。
    - C: 誤り。利用者の分離の問題は解決しません。
    - D: 誤り。セッションの生存の設定で、記憶の分離とは別です。

    **スキル:** [3.2.9](../domain3.md#skill-3-2-9) / **参照:** [Memory の設計](../../../services/genai-apps.md#agentcore-memory)、[AgentCore の構成要素と設定](../../../services/ai.md#agentcore-components)

### 問5 {#q5}

問い合わせのエージェントで、30 分ぶりの再開時に会話の文脈が失われます。Runtime のアイドルは既定のままで、メモリ上の変数に保存しています。対応として適切なものを選んでください。（2つ選択）

- A. `maxLifetime` を 8 時間に延ばす
- B. AgentCore Memory に残す
- C. エージェントのバージョンを毎回作る
- D. `idleRuntimeSessionTimeout` を延ばす
- E. `maxTokens` を増やす

??? success "答えと解説"
    **正解: B, D**

    アイドルの既定は 900 秒です。30 分おきなら毎回新しい microVM になり、メモリ上の文脈が消えます。

    - A: 誤り。セッション全体の上限で、アイドルの 900 秒が先に効きます。
    - B: 正しい。microVM が変わっても文脈を読めます。
    - C: 誤り。新しいバージョンを作っても文脈は残りません。
    - D: 正しい。既定の 900 秒を超えて microVM を残せます。
    - E: 誤り。応答の長さの設定です。

    **スキル:** [3.2.9](../domain3.md#skill-3-2-9) / **参照:** [AgentCore の構成要素と設定](../../../services/ai.md#agentcore-components)

既存の基盤を使ってエージェントの状態を自前で管理します。会話履歴と長期の知識の置き場所の組み合わせはどれですか。

- A. 会話履歴は Step Functions の実行履歴、長期の知識は DynamoDB
- B. 会話履歴は S3、長期の知識は RDS の文字列検索
- C. 会話履歴は DynamoDB、長期の知識はベクトルストア
- D. 会話履歴はベクトルストアだけ、長期の知識は Lambda のメモリ

??? success "答えと解説"

    - B: 誤り。S3 は 1 件ごとの頻繁な更新に向かず、文字列検索では意味の近い知識を探せません。
    - C: 正しい。
    - D: 誤り。Lambda のメモリは残りません。
