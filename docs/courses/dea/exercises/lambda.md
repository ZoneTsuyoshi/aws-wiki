# Lambdaの問題集

対象の解説: [AWS Lambda](../../../services/lambda.md)、[Lambda](../../../services/storage.md#efs-lambda)

### 問1 {#q1}

Lambda の処理で、毎回 S3 クライアントを作り直しているため遅いです。コード上の改善はどれですか。

- A. 依存ライブラリをすべてレイヤーに移し、毎回の起動時に読み直す
- B. `/tmp` にクライアントのオブジェクトを保存し、次の実行で読み直す
- C. SDK のクライアントをハンドラーの中で 2 回作り、片方を予備として持つ
- D. SDK のクライアントをハンドラーの外で作り、実行環境の再利用で使い回す

??? success "答えと解説"
    **正解: D**

    ハンドラーの外の初期化は、実行環境の再利用で引き継がれます。

    - A: 誤り。実行ごとに作り直す問題は解決しません。
    - B: 誤り。クライアントは再利用すれば十分で、ファイル化の必要はありません。
    - C: 誤り。作成の時間が増えます。
    - D: 正しい。

    **スキル:** [1.4.1](../domain1.md#skill-1-4-1) / **参照:** [コードの最適化](../../../services/lambda.md#code-optimization)

### 問2 {#q2}

Spark のジョブで全パーティションを読んだ後に日付で絞っており、時間がかかります。コードの最適化として適切なものはどれですか。（2つ選択）

- A. 必要な列だけを選択する
- B. 小さなテーブルの結合をやめ、大きなテーブル同士の結合に揃える
- C. 全テーブルをキャッシュしてから毎回フィルターを適用する
- D. ワーカー数を 2 倍にして、読み込み後の絞り込みを維持する
- E. `push_down_predicate` で読み込み前に絞る

??? success "答えと解説"
    **正解: A, E**

    早い段階でデータを減らすのが基本です。

    - A: 正しい。列指向なら読む列も減ります。
    - B: 誤り。シャッフルが増えます。
    - C: 誤り。メモリを消費し、読む量も減りません。
    - D: 誤り。費用が増え、コードの非効率は残ります。
    - E: 正しい。読む量そのものが減ります。

    **スキル:** [1.4.1](../domain1.md#skill-1-4-1) / **参照:** [DPU とワーカータイプ](../../../services/data-engineering.md#glue-dpu)、[速く、安くするコツ](../../../services/streaming.md#athena-performance)

### 問3 {#q3}

実行時間を短くする書き換えとして正しいものはどれですか。

- A. Athena の特定列の `SELECT` を `SELECT *` に変える
- B. Redshift への `INSERT` の繰り返しを、S3 からの `COPY` に変える
- C. パーティション列の条件をなくし、全範囲を読む SQL に変える
- D. Kinesis の `PutRecords` を `PutRecord` の繰り返しに変える

??? success "答えと解説"
    **正解: B**

    バッチの API や大量ロードの仕組みを使います。

    - A: 誤り。スキャン量が増えます。
    - B: 正しい。
    - C: 誤り。スキャン量が増えます。
    - D: 誤り。呼び出しが増えます。

    **スキル:** [1.4.1](../domain1.md#skill-1-4-1) / **参照:** [COPY と UNLOAD](../../../services/data-engineering.md#redshift-copy)、[エラーと監視](../../../services/streaming.md#kinesis-errors)

### 問4 {#q4}

CPU を多く使う変換の関数が遅いです。Lambda で CPU を増やす設定はどれですか。

- A. タイムアウトの値を増やす
- B. エフェメラルストレージを増やす
- C. メモリの設定を増やす
- D. 予約済み同時実行を増やす

??? success "答えと解説"
    **正解: C**

    CPU はメモリに比例して増えます。

    - A: 誤り。時間の上限で、CPU は増えません。
    - B: 誤り。`/tmp` の容量で、CPU は増えません。
    - C: 正しい。
    - D: 誤り。同時に動く数の枠で、1 回の CPU は増えません。

    **スキル:** [1.4.2](../domain1.md#skill-1-4-2) / **参照:** [メモリ](../../../services/lambda.md#memory)、[メモリと CPU の最適化](../../../services/lambda.md#memory-tuning)

### 問5 {#q5}

書き込み先のデータベースが耐えられるのは同時 50 接続です。関数がこれを超えないようにします。最も直接的な設定はどれですか。

- A. 関数の予約済み同時実行を 50 にする
- B. Provisioned Concurrency を 50 にし、上限は設定しない
- C. アカウントの同時実行の上限を 50 まで下げるよう依頼する
- D. 関数のメモリを 50 MB ごとに下げ、接続を減らす

??? success "答えと解説"
    **正解: A**

    予約済み同時実行は枠の確保と同時に上限になります。

    - A: 正しい。
    - B: 誤り。事前の初期化で、超えた分はオンデマンドで動きます。
    - C: 誤り。他の関数まで制限されます。
    - D: 誤り。同時実行数は変わりません。

    **スキル:** [1.4.2](../domain1.md#skill-1-4-2) / **参照:** [予約済みと Provisioned の違い](../../../services/lambda.md#reserved-provisioned)、[同時実行とスケーリング](../../../services/lambda.md#concurrency)

### 問6 {#q6}

レイテンシに敏感な API の関数で、コールドスタートを抑えます。費用は許容します。どの設定ですか。

- A. タイムアウトを最大の 900 秒にする
- B. 予約済み同時実行を設定する
- C. Provisioned Concurrency を設定する
- D. エフェメラルストレージを 10,240 MB にする

??? success "答えと解説"
    **正解: C**

    Provisioned Concurrency は実行環境を事前に初期化します。

    - A: 誤り。時間の上限で、初期化は減りません。
    - B: 誤り。枠の確保で、事前の初期化はしません。
    - C: 正しい。
    - D: 誤り。`/tmp` の容量で、初期化は減りません。

    **スキル:** [1.4.2](../domain1.md#skill-1-4-2) / **参照:** [スロットリング](../../../services/lambda.md#throttling)、[予約済みと Provisioned の違い](../../../services/lambda.md#reserved-provisioned)

### 問7 {#q7}

関数が S3 から 3 GB のファイルを取得して変換します。別の関数と共有はしません。最も簡単な置き場はどれですか。

- A. 関数を VPC に接続して EFS をマウントし、アクセスポイントも作成する
- B. エフェメラルストレージを 4,096 MB にして `/tmp` を使う
- C. 環境変数に Base64 で格納する
- D. レイヤーにファイルを入れて、関数の実行時に書き込む

??? success "答えと解説"
    **正解: B**

    `/tmp` は 512〜10,240 MB で指定できます。

    - A: 誤り。共有しないなら構成が過剰です。
    - B: 正しい。
    - C: 誤り。環境変数のサイズの上限を超えます。
    - D: 誤り。レイヤーは読み取り専用です。

    **スキル:** [1.4.7](../domain1.md#skill-1-4-7) / **参照:** [エフェメラルストレージ](../../../services/lambda.md#ephemeral-storage)

### 問8 {#q8}

複数の関数で共有する大きなモデルファイルを置きます。関数の設定で必要なものはどれですか。

- A. 各関数のエフェメラルストレージを同じパスに揃えて共有する
- B. 関数を VPC の外に置き、EFS のファイルシステム ID を環境変数に書いて接続先にする
- C. コンテナイメージに書き込み可能なボリュームとして EFS を含める
- D. 関数を VPC に接続し、EFS アクセスポイントを `/mnt/` で始まるパスにマウントする

??? success "答えと解説"
    **正解: D**

    EFS は関数の間で共有でき、`FileSystemConfigs` で指定します。

    - A: 誤り。`/tmp` は実行環境ごとで共有されません。
    - B: 誤り。関数は VPC に接続する必要があります。
    - C: 誤り。イメージは読み取り専用のコードで、EFS は含められません。
    - D: 正しい。

    **スキル:** [1.4.7](../domain1.md#skill-1-4-7) / **参照:** [Lambda](../../../services/storage.md#efs-lambda)、[エフェメラルストレージ](../../../services/lambda.md#ephemeral-storage)

### 問9 {#q9}

関数から EFS へのマウントがタイムアウトします。確認すべきものはどれですか。（2つ選択）

- A. マウントターゲットのセキュリティグループが、関数のセキュリティグループから 2049 番を許可しているか
- B. 関数の `/tmp` が 10,240 MB に設定されているか
- C. 関数のサブネットから到達できるマウントターゲットがあるか
- D. 関数のメモリが EFS の容量以上か
- E. 関数に Provisioned Concurrency が設定されているか

??? success "答えと解説"
    **正解: A, C**

    接続できないときは 2049 番とマウントターゲットを確認します。

    - A: 正しい。NFS のポートです。
    - B: 誤り。EFS の接続とは別の設定です。
    - C: 正しい。接続先が必要です。
    - D: 誤り。メモリと EFS の容量は関係しません。
    - E: 誤り。マウントの接続に関係しません。

    **スキル:** [1.4.7](../domain1.md#skill-1-4-7) / **参照:** [Lambda](../../../services/storage.md#efs-lambda)、[セキュリティグループのルール](../../../services/networking.md#security-group-rules)

### 問10 {#q10}

S3 に CSV が届いたら形式を検証し、問題なければ Glue ジョブを起動します。検証は数秒です。運用は最小にします。どの実装が適切ですか。

- A. S3 のイベントで Lambda を起動し、検証の後に `start_job_run` を呼ぶ
- B. Lambda を 15 分ごとに起動し、全ファイルを読み直して検証し、毎回 Glue ジョブも起動する
- C. EC2 で常駐プログラムを動かし、1 分ごとにバケットを一覧する
- D. EMR のクラスターを常時起動し、新しいファイルを検知する

??? success "答えと解説"
    **正解: A**

    Lambda は起動と小さな処理に向きます。

    - A: 正しい。
    - B: 誤り。無駄な読み取りが増え、到着に連動しません。
    - C: 誤り。運用が増えます。
    - D: 誤り。過剰で費用もかかります。

    **スキル:** [3.1.8](../domain3.md#skill-3-1-8) / **参照:** [呼び出しの種類](../../../services/lambda.md#invocation-types)、[S3 イベント通知](../../../services/messaging.md#s3-events)

### 問11 {#q11}

Firehose が S3 へ配信する前に、各レコードの個人情報の列を消します。Lambda の変換の説明として正しいものはどれですか。

- A. 変換はレコード 1 件ごとに必ず 1 回の呼び出しで、バッファはされない
- B. Firehose がバッファしたレコードを同期で渡し、関数は結果を返す
- C. 関数は S3 へ直接書き込み、Firehose には何も返さない
- D. Firehose が非同期で関数を起動し、関数の完了は待たずに配信する

??? success "答えと解説"
    **正解: B**

    返す `result` は `Ok`、`Dropped`、`ProcessingFailed` のいずれかです。

    - A: 誤り。レコードはバッファしてまとめて渡します。
    - B: 正しい。
    - C: 誤り。結果は Firehose へ返します。
    - D: 誤り。同期で呼び、結果を配信します。

    **スキル:** [3.1.8](../domain3.md#skill-3-1-8) / **参照:** [Lambda による変換](../../../services/streaming.md#firehose-transform)、[ほぼリアルタイムのデータ処理](../../../services/lambda.md#near-real-time)

### 問12 {#q12}

Lambda によるデータ処理の自動化で、適切でないものはどれですか。

- A. Step Functions の 1 ステップとして、ファイルの件数を検証する
- B. Kinesis のレコードを変換して DynamoDB へ書き込む
- C. 数百 GB のファイルの結合を、1 つの関数で数時間かけて実行する
- D. EventBridge Scheduler で毎日起動し、Athena のパーティションを追加する

??? success "答えと解説"
    **正解: C**

    上限は 15 分で、`/tmp` もメモリも 10,240 MB までです。

    - A: 誤り。短い処理で、適切です。
    - B: 誤り。関数の代表的な用途で、適切です。
    - C: 正しい。
    - D: 誤り。小さな定期処理で、適切です。

    **スキル:** [3.1.8](../domain3.md#skill-3-1-8) / **参照:** [メモリ](../../../services/lambda.md#memory)、[変換エンジン](../../../services/data-engineering.md#choosing-transform)
