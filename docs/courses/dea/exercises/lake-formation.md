# Lake Formation と認可の方式の問題集

対象の解説: [AWS Lake Formation](../../../services/data-engineering.md#lake-formation)

### 問1 {#q1}

Lake Formation でテーブルに列の権限を付けましたが、IAM で S3 の権限を持つ人が全列を読めます。S3 パスは登録済みです。原因はどれですか。

- A. データレイク管理者に `Super` を付与していない
- B. テーブルに LF タグを割り当てていない
- C. S3 パスの登録に、カスタムの IAM ロールではなくサービスリンクロールを使っている
- D. `IAMAllowedPrincipals` に `Super` が残っている

??? success "答えと解説"
    **正解: D**

    これが残っていると IAM だけで制御されます。

    - A: 誤り。管理者の設定で、読み手の制限とは別です。
    - B: 誤り。名前付きリソースの付与でも権限は効きます。
    - C: 誤り。登録に使うロールの種類は読み手の制限と別です。
    - D: 正しい。

    **スキル:** [4.2.4](../domain4.md#skill-4-2-4) / **参照:** [始めるときの設定](../../../services/data-engineering.md#lake-formation-setup)

### 問2 {#q2}

既存のクエリを止めずに、選んだ主体だけ Lake Formation の権限へ移します。何を使いますか。

- A. S3 パスをハイブリッドアクセスモードで登録し、選んだ主体をオプトインする
- B. 全テーブルの `IAMAllowedPrincipals` を一度に外して様子を見る方法
- C. 全テーブルに LF タグを付け、IAM のアクセスを自動で止める方法
- D. 別のアカウントへ全データをコピーして移す方法

??? success "答えと解説"
    **正解: A**

    既存の IAM のアクセスを保ちながら移行します。

    - A: 正しい。
    - B: 誤り。既存のアクセスが止まる恐れがあります。
    - C: 誤り。タグを付けるだけでは IAM のアクセスは変わりません。
    - D: 誤り。要件に対して過剰です。

    **スキル:** [4.2.4](../domain4.md#skill-4-2-4) / **参照:** [始めるときの設定](../../../services/data-engineering.md#lake-formation-setup)

### 問3 {#q3}

アナリストには `ssn` を除く列を、英国の担当者には `country = 'UK'` の行だけで `address` を除いて見せます。どの機能ですか。

- A. `INSERT` の権限にデータフィルターを付ける方法
- B. バケットポリシーの `aws:SourceVpce` で行を指定する方法
- C. データフィルター（列とセルのレベル）を `SELECT` の付与に使う
- D. IAM ポリシーの `s3:prefix` の条件で列を指定する方法

??? success "答えと解説"
    **正解: C**

    列、行、セルで制限できます。

    - A: 誤り。フィルターは `SELECT` の付与にだけ使えます。
    - B: 誤り。列や行は制御できません。
    - C: 正しい。
    - D: 誤り。列や行は制御できません。

    **スキル:** [4.2.4](../domain4.md#skill-4-2-4) / **参照:** [権限](../../../services/data-engineering.md#lake-formation-permissions)

### 問4 {#q4}

Lake Formation の始め方で、次の手順を忘れたときの症状の組み合わせで正しいものはどれですか。（2つ選択）

- A. `IAMAllowedPrincipals` を外すと、データレイク管理者が消える
- B. データレイク管理者を指定すると、IAM のロールが使えなくなる
- C. S3 パスを登録しないと、S3 のオブジェクトがすべて削除される
- D. データレイク管理者を指定しないと、権限を一元的に管理する主体がいない
- E. S3 パスを登録しないと、基盤データのアクセスを管理できない

??? success "答えと解説"
    **正解: D, E**

    手順と症状を対応づけます。

    - A: 誤り。関係しません。
    - B: 誤り。関係しません。
    - C: 誤り。データは削除されません。
    - D: 正しい。権限を管理する主体が要ります。
    - E: 正しい。配下も対象になります。

    **スキル:** [4.2.4](../domain4.md#skill-4-2-4) / **参照:** [始めるときの設定](../../../services/data-engineering.md#lake-formation-setup)、[権限](../../../services/data-engineering.md#lake-formation-permissions)

### 問5 {#q5}

Lake Formation の権限が効く範囲の説明で正しいものはどれですか。

- A. EC2 上の自作プログラムからの読み取りにも行のフィルターが自動で効く
- B. 統合エンジンが権限を守り、統合していないエンジンには効かない
- C. 非構造データの PDF にも行と列のフィルターが自動で効く
- D. どのエンジンから S3 を読んでも、S3 の API のレベルで常に行と列のフィルターが効く

??? success "答えと解説"
    **正解: B**

    統合エンジンで権限が守られます。

    - A: 誤り。統合していないエンジンには効きません。
    - B: 正しい。
    - C: 誤り。非構造データには S3 Access Grants を検討します。
    - D: 誤り。統合エンジンが守ります。

    **スキル:** [4.2.4](../domain4.md#skill-4-2-4) / **参照:** [AWS Lake Formation](../../../services/data-engineering.md#lake-formation)

### 問6 {#q6}

テーブルが数千あり、新しいテーブルの度に権限の付与が必要です。どの方式に変えますか。

- A. 主体ごとの S3 バケットポリシーへ、テーブルのパスを追記する
- B. 列のデータフィルターをテーブルごとに作って付与する
- C. LF タグをリソースに割り当て、タグの式で主体に付与する
- D. テーブルごとの名前付きリソースの付与

??? success "答えと解説"
    **正解: C**

    新しいテーブルはタグを付けるだけで対象になります。

    - A: 誤り。行や列の権限を扱えません。
    - B: 誤り。テーブルごとの作業が残ります。
    - C: 正しい。
    - D: 誤り。今の方式で、作業が残ります。

    **スキル:** [4.2.5](../domain4.md#skill-4-2-5) / **参照:** [LF タグ](../../../services/data-engineering.md#lake-formation-lf-tags)

### 問7 {#q7}

LF タグと IAM タグの説明で正しいものはどれですか。

- A. IAM ポリシーの条件 `aws:ResourceTag` で LF タグを評価できる
- B. 同じものなので、IAM のタグを付ければ LF タグの権限も効く
- C. LF タグは IAM ユーザーだけに付け、テーブルには付けられない
- D. 別物で、IAM ポリシーの条件に LF タグは使えない

    - C: 誤り。Data Catalog のリソースに割り当てます。

### 問8 {#q8}

チームとプロジェクトが増え続けます。ロールを増やさず、プリンシパルのタグとリソースのタグの一致で S3 の権限を決めます。どの方式ですか。

- A. 属性ベース（ABAC）で `aws:PrincipalTag` を条件に使う
- B. ロールベース（RBAC）でチームごとにロールとポリシーを増やして管理する
- C. 名前付きのリソースの付与で、バケットを 1 つずつ追加する
- D. LF タグの式で、IAM のロールの権限を直接書き換える

??? success "答えと解説"
    **正解: A**

    属性を条件で比べます。

    - A: 正しい。
    - B: 誤り。チームが増えるたびに増えます。
    - C: 誤り。増えるたびに作業が要ります。
    - D: 誤り。LF タグは別の仕組みです。

    **スキル:** [4.2.5](../domain4.md#skill-4-2-5) / **参照:** [条件とアクセス制御](../../../services/iam.md#conditions)、[セッションタグ](../../../services/iam.md#session-tags)

### 問9 {#q9}

組織の要件と方式の組み合わせで正しいものはどれですか。（2つ選択）

- A. チームが増えるなら、チームごとにロールとポリシーを増やし続ける
- B. テーブルが多いなら、名前付きリソースの付与を増やし続ける
- C. 行と列の制限が要るなら、S3 のバケットポリシーで絞る
- D. 職務が明確で少ないなら、Redshift のロールなどの RBAC
- E. テーブルが多いなら、LF タグのタグベース

??? success "答えと解説"
    **正解: D, E**

    規模と変化で方式を選びます。

    - A: 誤り。増えるなら ABAC が向きます。
    - B: 誤り。多いなら LF タグが向きます。
    - C: 誤り。バケットポリシーでは行と列を制限できません。
    - D: 正しい。職務のロールに権限を付けます。
    - E: 正しい。タグで付与します。

    **スキル:** [4.2.5](../domain4.md#skill-4-2-5) / **参照:** [暗号化とセキュリティ](../../../services/data-engineering.md#redshift-security)、[LF タグ](../../../services/data-engineering.md#lake-formation-lf-tags)

### 問10 {#q10}

データレイクの `email` 列を、データをコピーせず特定のロールから隠します。何を使いますか。

- A. Redshift の動的データマスキングを S3 のテーブルに設定する
- B. Lake Formation の列レベルの権限かデータフィルターで列を除く
- C. Macie の機密データ検出ジョブで `email` 列を隠す
- D. ETL で別のバケットへマスク済みのコピーを作り、ロールの参照先を変える方法

??? success "答えと解説"
    **正解: B**

    データはそのままで見える範囲を制限します。

    - A: 誤り。Redshift のテーブルの機能です。
    - B: 正しい。
    - C: 誤り。検出の機能で、列は隠しません。
    - D: 誤り。コピーを作ります。

    **スキル:** [4.3.1](../domain4.md#skill-4-3-1) / **参照:** [権限](../../../services/data-engineering.md#lake-formation-permissions)
