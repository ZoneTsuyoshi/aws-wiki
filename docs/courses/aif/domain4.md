# 分野4: 責任ある AI

配点は **14%** です。公平性や安全性などの観点、偏りの見つけ方、透明で説明できるモデルの選び方が中心です。枠組みの策定や実装は求められません。

## タスク 4.1: 責任ある AI システムの開発を説明する {#task-4-1}

### 4.1.1 責任ある AI の特徴 {#obj-4-1-1}

| 特徴 | 意味 | 例 |
|---|---|---|
| バイアス | 特定の集団に不利な偏りがないか | 採用スコアが性別で偏らない |
| 公平性 | 集団ごとの影響を考える | 地域で融資の承認率が不当に違わない |
| 包摂性 | 多様な人が使えて、代表されている | 方言や多様な肌の色でも動く |
| 堅牢性 | 予期しない入力でも正しく動く | 誤字や敵対的な入力のテスト |
| 安全性 | 有害な出力や悪用を防ぐ | 危険な手順を答えない |
| 正確性（veracity） | 出力が正しく、真実である | 根拠のない回答を減らす |

AWS は、責任ある AI を公平性、説明可能性、プライバシーとセキュリティ、安全性、制御可能性、正確性と堅牢性、ガバナンス、透明性の 8 つの観点で整理しています。

詳細: [AWS の 8 つの観点](../../services/ai-fundamentals.md#rai-dimensions)

### 4.1.2 責任ある AI のツール {#obj-4-1-2}

**Amazon Bedrock Guardrails** は、入力と出力をモデルの外で検査します。

| 要件 | 使う機能 | 動作 |
|---|---|---|
| 暴力や差別などの有害な内容を止める | コンテンツフィルター | 強度を選んでブロックする |
| ジェイルブレイクを防ぐ | プロンプト攻撃 | ブロックする |
| 投資助言のような話題を避ける | 拒否トピック | ブロックする |
| 競合の社名を出さない | ワードフィルター | ブロックする |
| 氏名やメールアドレスを隠す | 機密情報フィルター | ブロックまたはマスクする |
| 応答が参照元に基づくか確かめる | コンテキストグラウンディング | スコアがしきい値を下回るとブロックする |
| 規定と論理的に矛盾しないか確かめる | Automated Reasoning | 検証結果と理由を返す |

**具体例:** 銀行のチャットで投資の助言をさせず、口座番号も隠したいなら、拒否トピックと機密情報フィルターを組み合わせます。

Guardrails は実行時の防御です。導入の前にモデルの有害性や偏りを測るには、[Bedrock の評価](domain3.md#obj-3-4-1)を使います。

詳細: [Guardrails](../../services/ai.md#guardrails)、[フィルターの種類](../../services/ai.md#guardrail-filters)、[Guardrails の実践](../../services/genai-apps.md#guardrails-depth)

### 4.1.3 責任あるモデルの選択 {#obj-4-1-3}

性能と費用に加えて、環境への影響も考えます。計算資源を減らすことは、費用と環境負荷の両方に効きます。

| 実践 | 例 |
|---|---|
| 足りる範囲で小さなモデルを選ぶ | 単純な分類に最大のモデルを使わない |
| 不要な学習を避ける | 既存のモデルと RAG で足りるなら再学習しない |
| モデルを効率化する | 蒸留で小さなモデルにする |
| 使用率を上げる | サーバーレスやマネージドのサービスを使う |

AWS の Well-Architected Framework には、サステナビリティの柱があります。Generative AI Lens も、学習、調整、ホスティング、データ処理、保存の計算資源を最小にすることを挙げています。

詳細: [モデル選びの観点](../../services/ai-fundamentals.md#fm-lifecycle)、[Well-Architected Framework](../../services/cloud-foundations.md#well-architected)

### 4.1.4 生成 AI の法的なリスク {#obj-4-1-4}

| リスク | 例 | 対応 |
|---|---|---|
| 知的財産の侵害の主張 | 生成物が他者の著作物に似る | ライセンスの確認、人の確認 |
| 偏ったモデルの出力 | 差別的な結果で訴えられる | 公平性の評価 |
| 顧客の信頼の喪失 | 誤回答が公開されて批判される | Guardrails、レビュー |
| 利用者への危険 | 誤った医療の助言で損害が出る | 免責の明示、専門家への誘導 |
| ハルシネーション | 誤情報で判断を誤る | 根拠の提示 |

詳細: [法的なリスク](../../services/ai-fundamentals.md#legal-risks)

### 4.1.5 データセットの特徴 {#obj-4-1-5}

| 特徴 | 意味 | 足りないと |
|---|---|---|
| 包摂性 | 影響を受ける人々を含む | 一部の人で性能が落ちる |
| 多様性 | 属性、地域、状況に幅がある | 想定外の入力に弱くなる |
| 出所の確かなデータ | 権利と品質を確認している | 法的なリスクや誤りが増える |
| 均衡 | クラスや集団の量に大きな差がない | 多数派に最適化される |

詳細: [バイアスと公平性](../../services/ai-fundamentals.md#fairness)、[データ品質と不均衡](../../services/ai-fundamentals.md#data-quality)

### 4.1.6 バイアスとバリアンスの影響 {#obj-4-1-6}

| 状態 | 原因 | 影響 |
|---|---|---|
| 高バイアス（過少適合） | モデルが単純すぎる | 学習データでも検証データでも不正確 |
| 高バリアンス（過学習） | 学習データを暗記した | 学習データでは正確だが、新しいデータで不正確 |
| 集団への影響 | データや学習の偏り | 特定の集団だけ精度が低く、不利な判定を受ける |

**具体例:** ある地域のデータばかりで学習した与信モデルは、他の地域の申請者に不正確な判定を出すことがあります。全体の精度が高くても、集団ごとに見ないと気づきません。

統計のバイアスと、公平性のバイアスは別の意味です。問題文の文脈で見分けます。

詳細: [過学習、バイアス、バリアンス](../../services/ai-fundamentals.md#overfitting)

### 4.1.7 バイアス、信頼性、真実性を検出し監視するツール {#obj-4-1-7}

| 手法 | 内容 | 見つかるもの |
|---|---|---|
| ラベル品質の分析 | 複数の判定者の一致度などを見る | 判定者の偏見、ラベルの誤り |
| 人の監査 | 人が出力を抜き取って確認する | 指標に出にくい問題 |
| サブグループ分析 | 集団ごとに精度を比較する | 特定の集団での性能の低下 |
| Bedrock の評価 | Stereotyping、Harmfulness、Correctness、Faithfulness などを測る | FM の偏り、有害性、誤り |
| 本番の監視 | バイアスドリフト、ハルシネーションの割合を追う | 時間とともに起きる変化 |

SageMaker Clarify は、学習前後のバイアスの検出と SHAP による説明を行う機能です。新規顧客の受付は終了しています（[状況](domain1.md#obj-1-3-4)）。

詳細: [バイアスと公平性](../../services/ai-fundamentals.md#fairness)、[Clarify](../../services/sagemaker.md#clarify)、[Bedrock Evaluations](../../services/genai-apps.md#bedrock-evaluations)、[本番での監視](../../services/ai-fundamentals.md#production-monitoring)

## タスク 4.2: 透明で説明可能なモデルの重要性を認識する {#task-4-2}

### 4.2.1 透明で説明可能なモデルとそうでないモデルの違い {#obj-4-2-1}

| 区分 | 例 | 特徴 |
|---|---|---|
| 解釈しやすいモデル | 線形回帰、決定木 | 判断を追える。精度は控えめなことがある |
| ブラックボックス | 深層学習、FM | 高精度なことが多いが内部が見えない |

**透明性**は、モデルの仕組みや限界、使われるデータについて情報が開示されていることです。**説明可能性**は、個々の出力の理由を理解できることです。

詳細: [説明可能性と透明性](../../services/ai-fundamentals.md#explainability)

### 4.2.2 透明で説明可能なモデルを見分けるツール {#obj-4-2-2}

| ツール、情報 | 分かること |
|---|---|
| SageMaker Model Cards | モデルの用途、学習データ、評価、リスクの記録 |
| Bedrock の評価 | モデルごとの品質と安全性の比較 |
| オープンソースのモデル | 公開されたコードや重みを調べられる |
| データ | 学習データの内容や出所が公開されているか |
| ライセンス | 商用利用などの条件 |
| AI サービスカード | AWS の AI サービスの用途と制約 |
| SHAP、部分依存プロット | 特徴量と予測の関係 |

オープンソースでも、学習データまで公開されているとは限りません。モデル、データ、ライセンスを別々に確認します。

詳細: [説明可能性と透明性](../../services/ai-fundamentals.md#explainability)、[Model Cards](../../services/sagemaker.md#model-cards)、[Bedrock Evaluations](../../services/genai-apps.md#bedrock-evaluations)

### 4.2.3 安全性と透明性のトレードオフ {#obj-4-2-3}

| トレードオフ | 内容 | 判断の例 |
|---|---|---|
| 解釈しやすさと性能 | 解釈しやすいモデルは精度が下がることがある | 融資は精度が少し下がっても解釈しやすさを選ぶ |
| 透明性と安全性 | 公開しすぎると安全策の回避方法を教えてしまう | Guardrails の設定やプロンプトの詳細は公開しない |

どちらを優先するかは、用途の影響の大きさで決めます。測れるように、解釈しやすさと性能の両方を基準に入れて比較します。

詳細: [説明可能性と透明性](../../services/ai-fundamentals.md#explainability)、[人による監督](../../services/ai-fundamentals.md#human-oversight)

### 4.2.4 説明可能な AI の人間中心の設計 {#obj-4-2-4}

| 原則 | 内容 | 例 |
|---|---|---|
| 利用者のフィードバックの仕組み | 誤りを報告でき、改善に使う | 回答ごとの評価ボタン |
| AI の判断の透明性 | AI の使用と判断の理由を示す | 「AI の回答です」の表示、引用の提示 |
| 人による確認 | 影響の大きい判断は人が決める | 否決の前に担当者が確認する |

詳細: [説明可能性と透明性](../../services/ai-fundamentals.md#explainability)、[透明性と公平性](../../services/genai-apps.md#transparency-fairness)、[利用者からの評価](../../services/genai-apps.md#user-feedback)

## 確認問題 {#self-check}

??? question "問1: 採用の書類選考モデルの全体の精度は 92% ですが、特定の年齢層から不満が出ています。まず何をしますか。"
    サブグループ分析です。年齢層ごとに精度や通過率を比較します。全体の精度だけでは、特定の集団での性能の低下を見つけられません。差があれば、データの偏りやラベルの品質を調べます。

??? question "問2: 保険会社のチャットボットで、医療の助言を答えさせず、電話番号を出力でマスクしたいです。Guardrails のどの機能を使いますか。"
    拒否トピックと機密情報フィルターです。医療の助言を話題として拒否し、電話番号はマスク（`ANONYMIZE`）します。ワードフィルターは指定した語句の一致を見るので、話題全体を止めるのには向きません。

??? question "問3: モデルの精度が学習データでは 99%、新しいデータでは 68% でした。この状態と原因はどれですか。"
    過学習で、高バリアンスの状態です。学習データを暗記して、新しいデータに一般化できていません。両方とも低いなら、過少適合で高バイアスです。

??? question "問4: 病院が診断の補助モデルを選びます。候補 A は精度が少し高いものの判断の理由が分かりません。候補 B は精度が少し低いものの判断の理由を示せます。医師への説明が必須の場合はどちらを選びますか。"
    候補 B です。影響の大きい判断では説明責任が重要なので、性能が少し下がっても解釈しやすさを優先します。最終判断は医師が行います。

??? question "問5: 監査に備えて、社内のモデルの用途、学習データ、評価結果、リスクを 1 か所に記録したいです。どの機能が適切ですか。"
    SageMaker Model Cards です。モデルの情報を記録して共有するための機能です。CloudTrail は API の操作の記録で、モデルの用途やリスクを説明するものではありません。

??? question "問6: 画像生成 AI で作った広告が、他社の作品に酷似していると指摘されました。これはどのリスクで、どう備えますか。"
    知的財産の侵害の主張のリスクです。モデルのライセンスや利用条件を確認し、公開の前に人が確認する手順を入れます。顧客の信頼の喪失にもつながるので、社外に出す生成物は特に確認します。
