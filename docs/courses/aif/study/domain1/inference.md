応答の速さと入力の大きさで推論の種類を選びます。あわせて、FM をどこから入手し、本番でどう動かすかを問います。

## 学習の順番 {#study-order}

1. [推論の種類](../../../../services/ai-fundamentals.md#inference-types): 4 種類の向いている場面を表で覚えます。
2. [エンドポイントと推論](../../../../services/sagemaker.md#endpoints): SageMaker AI の目安の値を確認します。
3. [FM のライフサイクル](../../../../services/ai-fundamentals.md#fm-lifecycle): FM の入手元と本番での使い方の区分を押さえます。
4. [JumpStart](../../../../services/sagemaker.md#jumpstart): Bedrock との違いを、運用と課金で理解します。

## 覚える値 {#values}

| 項目 | 値 | 判断のポイント |
|---|---|---|
| リアルタイム | 入力は数十 MB 以内、通常 60 秒 | 常時起動で低遅延 |
| 非同期 | 入力 1 GB、1 時間 | キューで処理する |
| サーバーレス | 待機のコンピュート費用なし | コールドスタートあり |
| バッチ | ジョブの間だけ起動 | データセットを一括で処理する |

## こう問われたらこう考える {#decisions}

| 状況 | 判断 |
|---|---|
| 画面表示中に低遅延で返す | リアルタイム推論 |
| 1 日に数回の呼び出しで、最初が遅くてもよい | サーバーレス推論 |
| 数百 MB の入力を数分かけて処理する | 非同期推論 |
| 毎晩まとめてスコアを計算する | バッチ推論 |
| インスタンスを管理せず FM を使う | Bedrock のマネージド API |
| 独自のモデルを細かく制御する | SageMaker AI のエンドポイント |
| 公開モデルを自分のアカウントにデプロイする | JumpStart |

## 引っかかりやすい点 {#traps}

- JumpStart のエンドポイントはインスタンスの起動時間で課金されます。呼び出しがなくても費用がかかります。
- ゼロからの学習は費用が最大で、ほとんどの場合は不要です。
- サーバーレス推論にはコールドスタートがあります。
