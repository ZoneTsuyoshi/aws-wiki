# 分野1: AI/ML のユースケース

AI を使うべきかどうかと、使うならどの手法かを判断します。「使わない」が正解になる問題もあります。

| スキル | 内容 |

## 学習の順番 {#study-order}

1. [ユースケースの選定と優先順位](../../../../services/ai-fundamentals.md#use-case-prioritization): 価値が高く実現しやすいものから始める考え方を確認します。
2. [AI を使わない判断](../../../../services/ai-fundamentals.md#when-not-ai): 表の 5 つの場面を覚えます。
3. [問題の種類](../../../../services/ai-fundamentals.md#problem-types): 出力の形で手法を見分けます。
4. [従来の ML と FM の使い分け](../../../../services/ai-fundamentals.md#ml-vs-fm): 規制、説明可能性、運用の制約で使い分けます。

## こう問われたらこう考える {#decisions}

| 状況 | 判断 |
|---|---|
| 大量のレビューの感情の集計 | AI の拡張性が生きる |
| 税額の計算 | 通常のプログラム |
| 規則を書き切れ、常に同じ結果が必要 | ルールベース |
| 効果より費用が大きい | 実施しない |
| 出力が数値 | 回帰 |
| 出力がクラス | 分類 |
| 正解なしでグループを作る | クラスタリング |
| 融資の審査で否決の理由が必要 | 解釈しやすい従来の ML |
| 資料の要約、対話 | FM |

## 引っかかりやすい点 {#traps}

- ML の出力は予測です。確定した結果が必要な処理には向きません。
- データが少ない、質が低いときは、モデルを変えるより先にデータを整備します。
- FM は応答がぶれるので、規制の厳しい判定は補助に留めます。
