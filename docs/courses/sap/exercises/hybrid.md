# ハイブリッドの統合の問題集

対象の解説: [ネットワーク接続](../../../services/network-connectivity.md)、[移行](../../../services/migration.md)、[クラウドの基礎](../../../services/cloud-foundations.md)

### 問1 {#q1}

証券の基幹システムは、オンプレミスと AWS の接続に 99.99% の SLA を求めています。データセンター、ロケーション、機器、回線のいずれか 1 つが壊れても通信を続けます。費用は二の次です。どの構成を選びますか。

- A. 1 つのロケーションで別のデバイスに 2 つの接続を作り、VPN をバックアップにする
- B. 2 つのロケーションに 1 つずつ接続を作る
- C. 1 つのロケーションに 4 つの接続を作って LAG にまとめる
- D. 2 つのロケーションに、それぞれ別のデバイスで 2 つずつ接続を作る

??? success "答えと解説"
    **正解: D**

    Maximum resiliency の構成で、99.99% の SLA に対応します。

    - A: 誤り。1 つのロケーションの障害には VPN へ頼ることになり、99.99% の SLA のモデルにならない。
    - B: 誤り。High resiliency で、SLA は 99.9% である。
    - C: 誤り。ロケーションの障害に耐えられない。
    - D: 正しい。

    **スキル:** [1.3.1](../domain1.md#skill-1-3-1) / **参照:** [回復性のモデル](../../../services/network-connectivity.md#dx-resiliency)

### 問2 {#q2}

製造業は、200 の VPC を複数のリージョンで Transit Gateway につないでいます。主経路は Direct Connect で、コストを抑えるためバックアップは Site-to-Site VPN にします。切り替えは自動で行います。必要な構成を選んでください。（2つ選択）

- A. トランジット VIF と Direct Connect ゲートウェイを Transit Gateway に関連付ける
- B. 各 VPC にプライベート VIF を作り、VGW に接続する
- C. Transit Gateway に VPN の添付を作り、BGP で同じプレフィックスを広告する
- D. Transit Gateway の VPN の経路を静的にして、DX の経路より優先されるようにする
- E. Route 53 のヘルスチェックで DX の障害を検知し、VPC のルートテーブルを Lambda で書き換える

??? success "答えと解説"
    **正解: A, C**

    多数の VPC にはトランジット VIF と Direct Connect ゲートウェイを使います。VPN も動的に経路を交換すれば、DX が優先され、障害時に自動で切り替わります。

    - A: 正しい。
    - B: 誤り。200 の VPC に VIF を作るのは現実的でない。
    - C: 正しい。
    - D: 誤り。静的な経路は伝播した経路に勝つので、平常時も VPN を使ってしまう。
    - E: 誤り。経路の切り替えは BGP で自動にでき、独自の仕組みは要らない。

    **スキル:** [1.3.1](../domain1.md#skill-1-3-1) / **参照:** [DX を主、VPN を従にする](../../../services/network-connectivity.md#bgp-dx-vpn)

### 問3 {#q3}

規制の要件で、オンプレミスから Transit Gateway までの通信を暗号化します。Direct Connect を使っていて、公開 IP アドレスは使えません。アプリは変更せず、第三者の VPN 製品の追加も避けます。どれが最も適切ですか。

- A. プライベート IP VPN を Direct Connect の上に作る
- B. Direct Connect の接続で MACsec を有効にする
- C. 公開 VIF を作り、その上で公開 IP を使う Site-to-Site VPN を張る
- D. 各アプリで TLS を有効にし、Direct Connect はそのまま使って通信を保護する

??? success "答えと解説"
    **正解: A**

    プライベート IP VPN は、公開 IP アドレスを使わず Direct Connect の上に IPsec を張ります。

    - A: 正しい。
    - B: 誤り。MACsec はロケーションの機器までのレイヤー 2 の暗号化で、Transit Gateway までではない。
    - C: 誤り。公開 IP アドレスを使わないという条件に反する。
    - D: 誤り。アプリの変更が必要になる。

    **スキル:** [1.3.1](../domain1.md#skill-1-3-1) / **参照:** [オンプレミスとの接続](../../../services/network-connectivity.md#choosing-hybrid)

### 問4 {#q4}

映像制作の会社が、100 Gbps の専用接続で大容量のデータを送っています。監査の結果、データセンターのルーターと AWS のロケーションの機器の間の暗号化が求められました。VPC までの暗号化は求められていません。IPsec では帯域が足りません。どれを選びますか。

- A. Site-to-Site VPN を複数本作り、Transit Gateway の ECMP で帯域を束ねる
- B. プライベート IP VPN を Direct Connect の上に複数本作る
- C. 対応するロケーションで MACsec を有効にする
- D. ホスト接続に切り替え、パートナーのネットワークの暗号化に任せる

??? success "答えと解説"
    **正解: C**

    MACsec は専用接続の 10、100、400 Gbps で使えるレイヤー 2 の暗号化です。ルーターとロケーションの機器の区間を保護します。

    - A: 誤り。IPsec で帯域が足りないという前提に合わない。
    - B: 誤り。これも IPsec で、帯域の問題は残る。
    - C: 正しい。
    - D: 誤り。帯域が下がるおそれがあり、要件の区間の暗号化を保証できない。

    **スキル:** [1.3.1](../domain1.md#skill-1-3-1) / **参照:** [Direct Connect](../../../services/network-connectivity.md#direct-connect)

### 問5 {#q5}

オンプレミスの NAS にある 200 TB のファイルを Amazon EFS へ移します。切り替えまでの 2 か月間は業務でファイルが更新されるので、差分を夜間に同期します。切り替え後はオンプレミスの NAS を廃止します。帯域の制限と検証の機能も欲しいです。どれが適切ですか。

- A. S3 File Gateway をオンプレミスに置き、利用者の接続先を切り替えてから S3 から EFS へコピーする
- B. DataSync のエージェントを置き、帯域制限と検証を設定したタスクをスケジュールで夜間に実行する
- C. Transfer Family の SFTP サーバーを作り、夜間にスクリプトでアップロードする
- D. 各サーバーで rsync を夜間に実行し、Direct Connect 経由で EC2 上の EFS マウントへコピーする

??? success "答えと解説"
    **正解: B**

    DataSync は移行と定期的な同期のサービスです。差分の転送、スケジュール、帯域制限、データの検証に対応します。

    - A: 誤り。継続利用のためのサービスで、1 回限りの移行には過剰である。
    - B: 正しい。
    - C: 誤り。SFTP は取引先との転送に向き、大量の移行には向かない。
    - D: 誤り。動くが、並列化、検証、失敗の処理を自分で作ることになる。

    **スキル:** [1.3.2](../domain1.md#skill-1-3-2) / **参照:** [DataSync](../../../services/migration.md#datasync)

### 問6 {#q6}

工場の検査装置は、結果を NFS で書き込みます。装置の設定は変更できず、工場で続けて使います。データは AWS の分析基盤から S3 で読み、頻繁に読むファイルは工場で低遅延に読めるようにします。どれを選びますか。

- A. DataSync のエージェントを工場に置き、1 時間ごとに S3 へコピーする
- B. Transfer Family の SFTP サーバーを作り、装置から直接アップロードさせる
- C. S3 File Gateway を工場に置く
- D. Volume Gateway の保管型ボリュームを iSCSI で装置へ接続し、スナップショットを S3 に保存する

??? success "答えと解説"
    **正解: C**

    S3 File Gateway は NFS や SMB で受け、ファイルを S3 のオブジェクトとして保存し、ローカルにキャッシュします。オンプレミスで継続して使う用途です。

    - A: 誤り。1 時間の遅れがあり、頻繁に読むファイルのローカルキャッシュの機能もない。
    - B: 誤り。装置の設定を変更できないので、SFTP へ変えられない。
    - C: 正しい。
    - D: 誤り。ブロックのアクセスで、NFS の装置に合わず、S3 からファイルとして読めない。

    **スキル:** [1.3.2](../domain1.md#skill-1-3-2) / **参照:** [Storage Gateway](../../../services/migration.md#storage-gateway)

### 問7 {#q7}

物流の会社は、毎日 300 社の取引先から SFTP と AS2 でファイルを受け取っています。取引先の手順は変更させません。受け取ったデータは S3 に置き、サーバーの運用をやめます。どのサービスを選びますか。

- A. DataSync で、取引先のサーバーを定期的に読みに行く

- C. EC2 の Auto Scaling グループで SFTP と AS2 のサーバーを動かし、ファイルを S3 へコピーする

    - A: 誤り。取引先の手順と権限の変更が必要で、AS2 の受信にも対応しない。
    - B: 誤り。取引先の手順の変更が必要になる。

### 問11 {#q11}

- A. 新しいシステムを完成させてから、Route 53 の DNS を週末に一括で切り替える

### 問15 {#q15}

`example.com` の公開ホストゾーンと、同じ名前のプライベートホストゾーンを VPC に関連付けました。社内向けに `app.example.com` をプライベート側に登録したところ、VPC の中から公開の `www.example.com` を引けなくなりました。外からは引けています。どう対処しますか。

- A. アウトバウンドの転送ルールを作り、`example.com` を公開の DNS へ転送する
- B. プライベートホストゾーンに `www.example.com` のレコードも登録する
- C. 公開ホストゾーンの優先度を上げて、プライベートに一致がなければ公開を返すようにする
- D. VPC の `enableDnsHostnames` を無効にする

??? success "答えと解説"
    **正解: B**

    一致するプライベートホストゾーンがあってレコードがなければ NXDOMAIN を返し、公開 DNS へは流れません。内部で引く公開の名前もプライベート側に登録します。

    - A: 誤り。プライベートホストゾーン全体より転送ルールが優先され、`app.example.com` を引けなくなる。
    - B: 正しい。
    - C: 誤り。そのような優先度の設定はない。
    - D: 誤り。ホスト名の付与の設定で、問題を解決しないうえ、プライベートホストゾーンの利用に必要である。

### 問16 {#q16}

VPC に `corp.example.com` のプライベートホストゾーンを関連付け、`api.corp.example.com` を登録しました。別のチームが同じ `corp.example.com` をオンプレミスへ送る VPC Resolver の転送ルールを VPC に関連付けました。すると、VPC の中から `api.corp.example.com` が解決できなくなりました。ゾーンの内容に誤りはありません。原因はどれですか。

- A. 転送ルールがプライベートホストゾーンより優先されている
- B. プライベートホストゾーンのレコードの TTL が切れている
- C. インバウンドエンドポイントが VPC に存在していない
- D. 転送ルールの作成で `enableDnsSupport` が無効になった

??? success "答えと解説"
    **正解: A**

    - A: 正しい。
    - B: 誤り。TTL が切れれば再度解決するだけで、解決できなくなる理由にはならない。
    - C: 誤り。インバウンドはオンプレミスから VPC への方向で、この問題とは関係しない。
    - D: 誤り。転送ルールの作成で VPC の設定は変わらない。
