# データ保護の問題集

対象の解説: [データ保護](../../../services/kms.md)

### 問1 {#q1}

RDS のパスワードを 30 日ごとに自動で変更します。ローテーションの Lambda は VPC の中にあり、失敗しています。CloudWatch Logs に Secrets Manager への接続のタイムアウトが出ています。何を直しますか。

- A. シークレットの KMS キーを AWS 管理キーへ変更して、キーポリシーの確認を不要にする
- B. Secrets Manager の VPC エンドポイントか NAT の経路を用意する
- C. Lambda のセキュリティグループの受信で、Secrets Manager からの 443 番を許可する
- D. ローテーションの間隔を 30 日から 7 日に短くして、失敗の後の再実行を増やす

??? success "答えと解説"
    **正解: B**

    ローテーションの関数がデータベースと Secrets Manager の両方に届く経路が必要です。

    - A: 誤り。接続のタイムアウトの原因ではない。
    - B: 正しい。
    - C: 誤り。関数から外へ接続するので受信の許可は要らず、経路の問題も残る。
    - D: 誤り。間隔を変えても経路の問題は残る。

    **スキル:** [ローテーション](../domain6.md#t6-1-rotation) / **参照:** [ローテーション](../../../services/secrets.md#rotation)、[ローテーションのスケジュール](../../../services/secrets.md#rotation-schedule)

### 問2 {#q2}

ローテーションの後、一部のアプリがしばらくデータベースの認証エラーになります。Secrets Manager の値はアプリの起動時に 1 度だけ読んでいます。適切な修正はどれですか。

- A. ローテーションの間隔を 1 年に延ばして頻度を減らす
- B. 認証エラーのときに再取得するか、TTL の短いキャッシュの更新の処理を入れる
- C. `AWSPENDING` の値をアプリに読ませ、切り替えの前に新しい値へ移す
- D. シークレットを環境変数へコピーして、起動時に Secrets Manager を読まなくする

??? success "答えと解説"
    **正解: B**

    キャッシュしているアプリは古い値のままになります。再取得するように作ります。

    - A: 誤り。問題の発生の回数が減るだけで、原因は残る。
    - B: 正しい。
    - C: 誤り。`AWSPENDING` はローテーションの途中の値で、完了の前は認証に使えないことがある。
    - D: 誤り。古いままの問題が残る。

    **スキル:** [ローテーション](../domain6.md#t6-1-rotation) / **参照:** [Lambda ローテーションの動き](../../../services/secrets.md#lambda-rotation-steps)、[取得とクライアント側キャッシュ](../../../services/secrets.md#retrieval-caching)

### 問3 {#q3}

次の機械の ID の認証情報を整理します。自動ローテーションの方法の組み合わせはどれですか。(1) 外部の SaaS の API キー。(2) EC2 のアプリから AWS を呼ぶ権限。(3) 廃止できない古いアクセスキーの期限の検出。

- A. (1) KMS の自動ローテーション、(2) Cognito、(3) Macie
- B. (1) IAM ロール、(2) Secrets Manager、(3) Inspector
- C. (1) Parameter Store の自動ローテーション、(2) IAM ユーザーのキー、(3) GuardDuty
- D. (1) Secrets Manager の Lambda のローテーション関数、(2) IAM ロール、(3) Config の `access-keys-rotated`

??? success "答えと解説"
    **正解: D**

    独自のサービスの API キーは Lambda のローテーション関数です。ロールの認証情報は一時的です。

    - A: 誤り。どれも目的が違う。
    - B: 誤り。(1) と (2) が逆で、Inspector は目的が違う。
    - C: 誤り。Parameter Store に自動ローテーションはなく、キーも残る。
    - D: 正しい。

    **スキル:** [ローテーション](../domain6.md#t6-1-rotation) / **参照:** [ローテーション](../../../services/secrets.md#rotation)、[アクセスキーの扱い](../../../services/iam.md#access-key-handling)

### 問4 {#q4}

組織のデータ保護の方針を実装します。次の工程と手段の組み合わせとして正しいものはどれですか。(1) 分類、(2) 暗号化のキーの権限をアカウントをまたいで制御、(3) ログの機密情報のマスク。

- A. (1) Config、(2) S3 の ACL、(3) Athena の列の暗号化
- B. (1) Inspector、(2) SCP でのキーの作成、(3) KMS の暗号化
- C. (1) GuardDuty、(2) AWS 管理キーのポリシーの編集、(3) ログの保持の短縮
- D. (1) Macie とタグ、(2) カスタマー管理キーのキーポリシー、(3) データ保護ポリシー

??? success "答えと解説"
    **正解: D**

    工程ごとに手段を対応させます。

    - A: 誤り。いずれも工程の手段として不適切。
    - B: 誤り。Inspector は分類せず、KMS の暗号化はマスクではない。
    - C: 誤り。GuardDuty は分類せず、AWS 管理キーのポリシーは編集できない。
    - D: 正しい。

    **スキル:** [データ管理](../domain6.md#t6-2-data-management) / **参照:** [データ分類](../../../services/secrets.md#data-classification)、[KMS キーの種類](../../../services/kms.md#key-types)

### 問5 {#q5}

キーの管理の方針の見直しです。担当者の理解のうち、正しいものを選んでください。（2つ選択）

- A. 非対称キーの自動ローテーションが既定で有効である
- B. キーの削除は待機期間なしで即時に実行される
- C. AWS 管理キーのキーポリシーは自由に編集できる
- D. 自動ローテーションで既存のデータは再暗号化されない
- E. マルチリージョンキーは別のリージョンで再暗号化なしに復号できる

??? success "答えと解説"
    **正解: D, E**

    ローテーションは古い鍵素材を保持します。マルチリージョンキーの用途も押さえます。

    - A: 誤り。自動ローテーションの対象は対称のカスタマー管理キーなど。
    - B: 誤り。待機期間がある。
    - C: 誤り。編集できない。
    - D: 正しい。
    - E: 正しい。

    **スキル:** [データ管理](../domain6.md#t6-2-data-management) / **参照:** [キーのローテーション](../../../services/kms.md#key-rotation)、[マルチリージョンキー](../../../services/kms.md#multi-region-keys)

### 問6 {#q6}

S3 のデータレイクを Athena で分析します。列のレベルで部署ごとにアクセスを制御します。1 つのテーブルを部署ごとにコピーする運用はなくします。データの機密の分類はタグで管理します。適切な組み合わせはどれですか。

- A. 部署ごとの IAM ポリシーで S3 のプレフィックスを分け、列の制御は Athena のビューで行う
- B. Lake Formation の権限と、分類のタグ
- C. バケットを部署ごとに分けて、列のアクセスは ACL で管理する
- D. Glue データカタログのリソースポリシーで、列ごとの権限を部署へ許可する

??? success "答えと解説"
    **正解: B**

    データレイクの細かいアクセス制御は Lake Formation です。

    - A: 誤り。S3 の権限は列を制御できず、元のファイルを読まれるとビューの制限を回避できる。
    - B: 正しい。
    - C: 誤り。ACL で列の制御はできない。
    - D: 誤り。カタログのリソースポリシーは列ごとの権限の仕組みではない。

    **スキル:** [データ管理](../domain6.md#t6-2-data-management) / **参照:** [クロスアカウントアクセス](../../../services/iam.md#cross-account)、[タグ戦略](../../../services/governance.md#tagging-strategy)、[AWS Lake Formation](../../../services/data-engineering.md#lake-formation)

### 問7 {#q7}

500 個の S3 バケットを持つ組織で、機密データの傾向を費用を抑えて継続的に把握します。一方、四半期の監査の対象のバケットは確実に全件を調べます。適切な組み合わせはどれですか。

- A. GuardDuty の S3 保護を有効にして、結果を担当者が目で見る
- B. 全バケットを Athena で毎月スキャンする処理を自作する
- C. 自動の機密データ検出で全体を見て、監査対象は検出ジョブで調べる
- D. 全バケットを対象に Macie の検出ジョブを毎月全件で実行し、費用は予算アラートで監視する

??? success "答えと解説"
    **正解: C**

    自動の検出はサンプリングで継続的に傾向を見ます。確実に調べるならジョブです。

    - A: 誤り。GuardDuty は脅威の検出で、機密データを検出しない。
    - B: 誤り。標準の機能で足りる。
    - C: 正しい。
    - D: 誤り。費用を抑えるという条件に反する。

    **スキル:** [Macie](../domain6.md#t6-2-macie) / **参照:** [検出の方法](../../../services/threat-detection.md#macie-discovery)、[Macie](../../../services/threat-detection.md#macie)

### 問8 {#q8}

社員番号 `EMP-` で始まる 8 桁の値を検出したいのですが、Macie のマネージドの識別子で見つかりません。また、テスト用のダミーのカード番号で誤検知が多くなっています。適切な組み合わせはどれですか。（2つ選択）

- A. マネージドの識別子をすべて有効にして、社員番号も検出できるようにする
- B. Macie のサービスクォータを引き上げる
- C. 抑制ルールで、カード番号の検出結果をすべて非表示にする
- D. カスタムのデータ識別子で社員番号の形式を定義する
- E. 許可リストでダミーのカード番号を除く

??? success "答えと解説"
    **正解: D, E**

    独自の形式はカスタムの識別子、誤検知の除外は許可リストです。

    - A: 誤り。社内独自の形式はマネージドの識別子の対象にならない。
    - B: 誤り。識別の問題を解決しない。
    - C: 誤り。本物のカード番号の検出結果まで隠れる。
    - D: 正しい。
    - E: 正しい。

    **スキル:** [Macie](../domain6.md#t6-2-macie) / **参照:** [識別子と許可リスト](../../../services/threat-detection.md#macie-identifiers)

### 問9 {#q9}

委任管理者で Macie を組織に有効にしました。機密データの検出結果が出たら、担当へ通知し、バケットにタグを付けて、外部への共有をブロックします。適切な構成はどれですか。

- A. 検出結果の EventBridge イベントから SNS と Lambda を動かす
- B. 検出結果を Security Hub CSPM へ送り、週次のレポートで担当者が確認してタグを付ける
- C. Macie の検出結果を S3 のイベント通知で受ける
- D. CloudTrail の `GetObject` のデータイベントを全件集めて、Athena で担当者が毎日確認する

??? success "答えと解説"
    **正解: A**

    検出結果は EventBridge に流れるので、タグの付与や隔離を自動化できます。

    - A: 正しい。
    - B: 誤り。手作業で遅く、ブロックの自動化にならない。
    - C: 誤り。検出結果は EventBridge に流れる。
    - D: 誤り。機密データの検出の結果の流れではない。

    **スキル:** [Macie](../domain6.md#t6-2-macie) / **参照:** [検出結果](../../../services/threat-detection.md#macie-findings)、[ルールとイベントパターン](../../../services/messaging.md#eventbridge-rules)

### 問10 {#q10}

規制で、鍵の管理を自社の担当者だけが行う FIPS の専有の HSM が必須です。ただし S3 や EBS の AWS の統合も使います。適切な構成はどれですか。

- A. KMS のカスタマー管理キーで、キーポリシーを自社の担当者だけに限定する
- B. CloudHSM のクラスターと KMS の CloudHSM キーストア
- C. CloudHSM のクラスターを作り、S3 や EBS には SSE-C で鍵を渡す
- D. KMS に自社の鍵素材をインポートして、AWS 管理の HSM で使う

??? success "答えと解説"
    **正解: B**

    専有の HSM は CloudHSM です。AWS サービスとの統合は KMS の CloudHSM キーストア経由です。

    - A: 誤り。標準のキーストアは AWS が運用する HSM で、専有の要件に合わない。
    - B: 正しい。
    - C: 誤り。EBS に SSE-C はなく、AWS のサービスの統合にならない。
    - D: 誤り。鍵素材を自社で用意しても、専有の HSM にならない。

    **スキル:** [暗号化](../domain6.md#t6-2-encryption) / **参照:** [KMS との比較](../../../services/identity-directory.md#cloudhsm-vs-kms)、[KMS の CloudHSM キーストア](../../../services/identity-directory.md#cloudhsm-key-store)

### 問11 {#q11}

組織の基準を強制します。(1) S3 への HTTP のアクセスを拒否する。(2) 新しい EBS ボリュームを必ず暗号化する。適切な組み合わせはどれですか。

- A. (1) ブロックパブリックアクセス、(2) アカウントのデフォルト暗号化
- B. (1) バケットのデフォルト暗号化、(2) Config の `encrypted-volumes` の検出
- C. (1) バケットポリシーの `aws:SecureTransport`、(2) Config の `encrypted-volumes` の検出
- D. (1) バケットポリシーの `aws:SecureTransport`、(2) アカウントのデフォルト暗号化

??? success "答えと解説"
    **正解: D**

    HTTPS の強制は `aws:SecureTransport`、EBS はアカウントのデフォルト暗号化です。

    - A: 誤り。公開の防止で、HTTP のアクセスの拒否にならない。
    - B: 誤り。保存時の暗号化で HTTP を拒否せず、(2) も検出だけで強制しない。
    - C: 誤り。(2) は検出だけで、暗号化を強制しない。
    - D: 正しい。

    **スキル:** [暗号化](../domain6.md#t6-2-encryption) / **参照:** [バケットのデフォルト暗号化とポリシーによる強制](../../../services/s3.md#enforcing-encryption)、[EBS の暗号化](../../../services/storage.md#ebs-encryption)

### 問12 {#q12}

医療データを扱うチームの要件です。(1) ロードバランサーから利用者まで TLS で通信する。(2) AWS に平文を見せない形で S3 に保存する。適切な組み合わせはどれですか。

- A. (1) ACM の証明書と HTTPS リスナー、(2) SSE-KMS
- B. (1) ACM の証明書と HTTPS リスナー、(2) クライアント側の暗号化
- C. (1) セキュリティグループの 443 番の許可、(2) バケットポリシーの `aws:SecureTransport`
- D. (1) WAF のマネージドルール、(2) SSE-S3

??? success "答えと解説"
    **正解: B**

    ロードバランサーで TLS を終端します。AWS に平文を見せないならクライアント側の暗号化です。

    - A: 誤り。(1) はよいが、SSE-KMS は S3 が平文を受け取ってから暗号化する。
    - B: 正しい。
    - C: 誤り。どちらも保存時の暗号化の手段ではない。
    - D: 誤り。WAF は暗号化の手段ではなく、SSE-S3 は S3 が平文を受け取る。

    **スキル:** [暗号化](../domain6.md#t6-2-encryption) / **参照:** [転送時の TLS](../../../services/certificates.md#tls-in-transit)、[クライアント側とサーバー側の暗号化](../../../services/kms.md#client-vs-server-side)
