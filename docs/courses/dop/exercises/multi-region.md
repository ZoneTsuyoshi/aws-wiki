# 複数リージョンの問題集

対象の解説: [複数リージョン](../../../services/resilience.md#write-patterns)

### 問1 {#q1}

次の説明のうち、RDS の Multi-AZ DB インスタンス構成とリードレプリカの違いを正しく述べているものはどれですか。アプリの読み取りの負荷を下げ、同時に AZ 障害からの自動の復旧も求められる状況で判断します。

- A. リードレプリカは同期なので、Multi-AZ の代わりに RPO 0 で使える
- B. 読み取りの負荷はリードレプリカ、自動の復旧は Multi-AZ で担う
- C. Multi-AZ は別のリージョンへ自動で切り替わる機能である
- D. Multi-AZ のスタンバイは読み取りに使えるので、これだけで読み取りの負荷を下げられる

??? success "答えと解説"
    **正解: B**

    目的が違います。両方が必要なら組み合わせます。

    - A: 誤り。リードレプリカは非同期で、昇格も手動。
    - B: 正しい。
    - C: 誤り。Multi-AZ は同じリージョンの中の仕組み。
    - D: 誤り。DB インスタンス構成のスタンバイは読み取りに使えない。

    **スキル:** [複製と切り替え](../domain3.md#t3-1-replication) / **参照:** [リードレプリカと Multi-AZ](../../../services/databases.md#read-replicas)

### 問2 {#q2}

東京のプライマリと大阪のセカンダリを持つ Aurora Global Database があります。(1) 東京のメンテナンスのため、データを失わずに大阪へ計画的に移す。(2) 東京のリージョン障害で今すぐ大阪を使う。それぞれの操作の組み合わせはどれですか。

- A. (1) セカンダリの削除、(2) `reboot-db-instance --force-failover`
- B. (1) `failover-db-cluster`、(2) クロスリージョンのリードレプリカの昇格
- C. (1) `switchover-global-cluster`、(2) `failover-global-cluster`
- D. (1) 手動のスナップショットの復元、(2) スイッチオーバー

??? success "答えと解説"
    **正解: C**

    計画的な移動はスイッチオーバーでデータを失いません。障害時はフェイルオーバーです。RPO は複製の遅延に左右されます。

    - A: 誤り。再起動はリージョン内の操作で、リージョンをまたがない。
    - B: 誤り。前者はリージョン内の切り替え。
    - C: 正しい。
    - D: 誤り。スナップショットは時間がかかり、障害のときにスイッチオーバーは使えない。

    **スキル:** [複製と切り替え](../domain3.md#t3-1-replication) / **参照:** [Aurora グローバルデータベース](../../../services/databases.md#aurora-global-database)、[グローバルデータベースの切り替え](../../../services/databases-specialized.md#aurora-global-switchover)

### 問3 {#q3}

S3 のデータを別のリージョンへ複製し、誤削除やランサムウェアによる破壊に備えたいと考えています。担当者は CRR だけで十分だと主張しています。適切な指摘はどれですか。（2つ選択）

- A. CRR は暗号化されたオブジェクトに対応しないので、SSE-KMS をやめる
- B. CRR を設定すれば、既存のオブジェクトも自動ですべて複製される
- C. 両方のバケットでバージョニングを有効にする必要がある
- D. レプリケーションは破損も複製するので、時点へ戻せるバックアップを別に持つ
- E. CRR は同期なので、書き込みの遅延が大きくなる

??? success "答えと解説"
    **正解: C, D**

    レプリケーションは削除や破損も伝わることがあるので、時点復旧の手段を別に用意します。CRR にはバージョニングが必要です。

    - A: 誤り。SSE-KMS のオブジェクトも設定すれば複製できる。
    - B: 誤り。既定では設定後に作られたものが対象で、既存には Batch Replication などを使う。
    - C: 正しい。
    - D: 正しい。
    - E: 誤り。CRR は非同期で、書き込みの遅延にならない。

    **スキル:** [複製と切り替え](../domain3.md#t3-1-replication) / **参照:** [レプリケーション](../../../services/s3.md#replication)、[書き込みの戦略](../../../services/resilience.md#write-patterns)

### 問4 {#q4}

東京とフランクフルトで同じ Web アプリを動かし、各リージョンで低遅延に読み書きします。同じ項目の更新の競合は、後の書き込みを優先してよいと決めました。データベースの管理の手間は最小にします。何を使いますか。

- A. RDS のクロスリージョンリードレプリカを両方のリージョンへ置く
- B. DynamoDB グローバルテーブル（既定の MREC）の各リージョンで読み書きする
- C. Aurora Global Database の書き込み転送を両方のリージョンで使う
- D. DynamoDB の Streams と Lambda で、2 つのテーブルの同期を自作する

??? success "答えと解説"
    **正解: B**

    グローバルテーブルは全リージョンで書き込めます。既定の MREC は競合を後勝ちで解決します。

    - A: 誤り。レプリカは読み取りだけで、各リージョンの書き込みに使えない。
    - B: 正しい。
    - C: 誤り。実際の書き込みはプライマリで処理され、低遅延の読み書きにならない。
    - D: 誤り。同じことを標準の機能でできるのに、自作の運用が増える。

    **スキル:** [リージョンをまたぐ機能](../domain3.md#t3-1-cross-region) / **参照:** [グローバルテーブル](../../../services/dynamodb.md#global-tables)、[書き込みの戦略](../../../services/resilience.md#write-patterns)

### 問5 {#q5}

CloudFront で S3 のオリジンを 2 つのリージョンに持ちます。画像の取得はプライマリの 5xx で別のリージョンへ切り替わりますが、API の POST はプライマリのエラーのままです。担当者は不具合だと考えています。正しい説明はどれですか。

- A. オリジングループに含めるオリジンの数が足りないので、3 つに増やす
- B. オリジンフェイルオーバーは GET、HEAD、OPTIONS が対象で、書き込みは切り替わらない
- C. Route 53 の `Evaluate Target Health` を有効にすれば、POST も別のオリジンへ切り替わる
- D. キャッシュの TTL が長いので、0 に変更すれば POST も切り替わる

??? success "答えと解説"
    **正解: B**

    オリジンフェイルオーバーは読み取りのリクエストが対象です。書き込みの切り替えには Route 53 などを使います。

    - A: 誤り。数を増やしても POST は切り替わらない。
    - B: 正しい。
    - C: 誤り。Route 53 の設定で、CloudFront のオリジングループに関係しない。
    - D: 誤り。TTL の問題ではない。

    **スキル:** [リージョンをまたぐ機能](../domain3.md#t3-1-cross-region) / **参照:** [オリジンフェイルオーバー](../../../services/networking.md#origin-failover)

### 問6 {#q6}

カスタマー管理キーで暗号化された RDS の東京のインスタンスから、大阪へリードレプリカを作ります。作成で KMS のエラーになりました。適切な対応はどれですか。

- A. Secrets Manager のレプリカを大阪に作り、キーを共有する
- B. 東京のキー ID を指定し直す。KMS キーは全リージョンで共通の ID を持つ
- C. 暗号化を外してレプリカを作り、作成後にレプリカだけ暗号化する
- D. 大阪のカスタマー管理キーを `--kms-key-id` に指定して作成する

??? success "答えと解説"
    **正解: D**

    KMS キーはリージョンごとのリソースです。レプリカのリージョンのキーを指定します。

    - A: 誤り。シークレットの複製で、RDS の KMS キーの問題を解決しない。
    - B: 誤り。通常のキーはリージョンごと。
    - C: 誤り。暗号化の状態は作成の後に変えられず、規則の面でも適切でない。
    - D: 正しい。

    **スキル:** [リージョンをまたぐ機能](../domain3.md#t3-1-cross-region) / **参照:** [マルチリージョンキー](../../../services/kms.md#multi-region-keys)、[リードレプリカと Multi-AZ](../../../services/databases.md#read-replicas)

### 問7 {#q7}

各国の利用者を、(1) 法規によりその国のデータがあるリージョンへ必ず送る、(2) 法規の対象外のサービスは最も遅延の少ないリージョンへ送る、という 2 つのサービスがあります。Route 53 のルーティングの組み合わせはどれですか。

- A. (1) 重み付け、(2) 複数値回答
- B. (1) 位置情報、(2) レイテンシーベース
- C. (1) レイテンシーベースのレコード、(2) 位置情報のレコード
- D. (1) フェイルオーバー、(2) シンプル

??? success "答えと解説"
    **正解: B**

    利用者の場所でリージョンを決めるなら位置情報、遅延で決めるならレイテンシーベースです。

    - A: 誤り。どちらも地理や遅延を条件にしない。
    - B: 正しい。
    - C: 誤り。法規の要件には地理の条件が必要で、配置が逆。
    - D: 誤り。地理の条件にも遅延の条件にも合わない。

    **スキル:** [グローバルなスケール](../domain3.md#t3-2-global) / **参照:** [ルーティングポリシー](../../../services/networking.md#routing-policies)

### 問8 {#q8}

世界中の利用者へ配信します。(1) 動画と画像はキャッシュして配信する。(2) ゲームの UDP の通信を固定 IP で AWS のネットワークへ素早く入れる。適切な組み合わせはどれですか。

- A. (1) API Gateway のキャッシュ、(2) Route 53 の位置情報
- B. (1) Global Accelerator、(2) CloudFront
- C. (1) S3 のマルチパートアップロード、(2) NLB を 1 つのリージョンに置く
- D. (1) CloudFront、(2) Global Accelerator

??? success "答えと解説"
    **正解: D**

    キャッシュは CloudFront、固定 IP と TCP、UDP の経路の改善は Global Accelerator です。

    - A: 誤り。動画の配信に向かず、固定 IP も得られない。
    - B: 誤り。役割が逆で、CloudFront は UDP のゲーム通信に向かない。
    - C: 誤り。キャッシュ配信にならず、世界からの経路の改善もしない。
    - D: 正しい。

    **スキル:** [グローバルなスケール](../domain3.md#t3-2-global) / **参照:** [Global Accelerator](../../../services/network-connectivity.md#global-accelerator)、[CloudFront](../../../services/networking.md#cloudfront)

### 問9 {#q9}

同じ Web アプリを 4 つのリージョンへ展開します。読み取りは各リージョンで低遅延に行い、書き込みは 1 か所で十分です。リレーショナルのデータです。インフラの展開も揃えます。適切な組み合わせはどれですか。

- A. RDS の単一の DB と CloudFront のキャッシュ、手動の EC2 の起動
- B. S3 の CRR と Beanstalk の環境の手動のクローン
- C. Aurora Global Database と StackSets
- D. DynamoDB グローバルテーブルとネストされたスタック

??? success "答えと解説"
    **正解: C**

    書き込みは 1 か所、読み取りは各地なら Aurora Global Database です。同じ構成の展開には StackSets を使います。

    - A: 誤り。書き込みの少ない読み取りのデータでも、展開が揃わず動的なデータに対応しない。
    - B: 誤り。リレーショナルのデータの置き場にならない。
    - C: 正しい。
    - D: 誤り。リレーショナルの要件に合わず、ネストされたスタックはリージョンをまたげない。

    **スキル:** [グローバルなスケール](../domain3.md#t3-2-global) / **参照:** [StackSets の設定](../../../services/iac.md#stacksets-settings)、[Aurora グローバルデータベース](../../../services/databases.md#aurora-global-database)

### 問10 {#q10}

東京とオレゴンの S3 バケットに同じデータを置き、アプリは 1 つのエンドポイントから近いほうを使います。東京の障害のときは、アプリの設定を変えずにオレゴンへ切り替えます。データは双方向に複製します。適切な構成はどれですか。

- A. CloudFront のオリジングループで 2 つのバケットをまとめ、PUT も含めて切り替える運用
- B. 片方向の CRR と、アプリの設定ファイルに書いたバケット名を障害時に手で書き換える運用
- C. 双方向の CRR と Multi-Region Access Points のフェイルオーバーの設定
- D. 1 つのバケットに S3 Transfer Acceleration を有効にして、エッジ経由で読み書きする運用

??? success "答えと解説"
    **正解: C**

    Multi-Region Access Points は 1 つのエンドポイントで複数のバケットへ振り分け、フェイルオーバーを制御できます。

    - A: 誤り。オリジンフェイルオーバーの対象は読み取りで、書き込みは切り替わらない。
    - B: 誤り。アプリの設定の変更が必要で、双方向にもならない。
    - C: 正しい。
    - D: 誤り。転送の高速化で、リージョン障害に備える仕組みではない。

    **スキル:** [リージョンをまたぐ機能](../domain3.md#t3-1-cross-region) / **参照:** [レプリケーション](../../../services/s3.md#replication)、[Multi-Region Access Points](../../../services/storage-advanced.md#mrap)
