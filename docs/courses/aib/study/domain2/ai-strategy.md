# 分野2: AI 戦略と優先順位

事業の目標から逆算してユースケースを選び、拡大、一時停止、中止を判断します。AI を使わない判断も問われます。

## 問われるスキル {#skills}

| スキル | 内容 |
|---|---|
| [2.1.1](../../domain2.md#skill-2-1-1) | 効果の大きいユースケース |
| [2.1.3](../../domain2.md#skill-2-1-3) | 優先順位（拡大、一時停止、中止） |
| [2.1.4](../../domain2.md#skill-2-1-4) | AI が適切でない場合 |

## 学習の順番 {#study-order}

1. [ユースケースの選定と優先順位](../../../../services/ai-fundamentals.md#use-case-prioritization): 業務領域と用途の対応、優先順位の 4 つの軸を覚えます。
2. [AI を使わない判断](../../../../services/ai-fundamentals.md#when-not-ai): 5 つの場面と、選ぶものを確認します。
3. [KPI と ROI](../../../../services/ai-fundamentals.md#kpi-roi): 効果と費用の比較から、実施の判断につなげます。

## 覚える値 {#values}

| 項目 | 値 | 判断のポイント |
|---|---|---|
| 優先順位の 4 軸 | ビジネス価値、実現性、サステナビリティ、戦略との整合 | 価値が高く実現しやすいものから |

## こう問われたらこう考える {#decisions}

| 状況 | 判断 |
|---|---|
| 「AI で何かできないか」と言われた | 業務の課題と目標から始める |
| KPI を達成し、運用の体制もある | 拡大 |
| 価値はあるが、データや規制の確認が先 | 一時停止 |
| 見込みがなく、戦略からも外れた | 中止 |
| 税額のように正確な値が必要 | 通常のプログラム |
| データが少なく質も低い | まずデータ整備 |
| 効果より費用が大きい | 実施しない |
| 原因が手順の無駄にある | 業務プロセスの見直し |

## 引っかかりやすい点 {#traps}

- 投資済みの額は判断に入れません（サンクコスト）。
- 透明性は責任ある AI の観点で、優先順位の 4 軸には入りません。
- RAG で税法を検索させても、計算の正確さは保証されません。
