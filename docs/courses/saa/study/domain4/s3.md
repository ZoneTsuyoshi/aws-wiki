## 学習の順番 {#study-order}

1. [ストレージクラス](../../../../services/s3.md#storage-classes)と[S3 Glacier のデータ取得](../../../../services/s3.md#glacier-retrieval): クラスごとの最小保存期間と取得の時間を覚えます。
2. [ライフサイクル](../../../../services/s3.md#lifecycle)と[ライフサイクルのルール要素](../../../../services/s3.md#lifecycle-elements): 移行と失効のルールを確認します。
3. [片付けの設定](../../../../services/s3.md#abort-multipart)と[マルチパートアップロード](../../../../services/s3.md#multipart-upload): 未完了のパートの片付けと、大きなファイルの扱いを押さえます。
4. [リクエスタ支払い](../../../../services/s3.md#requester-pays): 費用の負担先を確認します。
5. [スナップショット](../../../../services/storage.md#ebs-snapshots)と[バックアッププランとルール](../../../../services/resilience.md#backup-plans): スナップショットの費用とプランを確認します。

## 覚える値 {#values}

| 項目 | 値 | 判断のポイント |
|---|---|---|
| Standard-IA、One Zone-IA | 最小 30 日、最小課金 128 KB | 小さなものは不利 |
| Glacier Instant、Flexible | 最小 90 日 | ミリ秒か、分から時間か |
| Deep Archive | 最小 180 日。12 時間以内、Bulk は 48 時間以内 | 最も安い |
| `PUT` の上限 | 5 GB | 超えるならマルチパート |
| Snapshots Archive | 最大 75% 削減 | 90 日以上の保持 |

## こう問われたらこう考える {#decisions}

| 状況 | 判断 |
|---|---|
| 傾向が読めない | Intelligent-Tiering |
| 傾向が分かっている | ライフサイクルルール |
| 古いバージョンの費用 | `NoncurrentVersionExpiration` |
| 未完了のパートの費用 | `AbortIncompleteMultipartUpload` |
| ダウンロードの費用を利用者に | リクエスタ支払い |
| 小さなログを大量に置く | Firehose でまとめる |

## 引っかかりやすい点 {#traps}

- 移行は低コスト側への一方向です。
- リクエスタ支払いでも、ストレージの費用は所有者です。匿名アクセスはできません。
- 128 KB 未満のオブジェクトは、既定では移行されません。
