# ストレージの問題集

対象の解説: [ストレージ](../../../services/storage.md)、[ストレージの応用](../../../services/storage-advanced.md)

### 問1 {#q1}

スケールアウトする Linux の Web サーバーで、アップロードされたファイルを全台で共有します。どれを選びますか。

- A. インスタンスストアに保存して、再起動で消えないようにする
- B. EFS をマウントして共有する
- C. 各インスタンスの EBS に保存して、定期的にコピーする
- D. 1 つの EBS を全台で使う

??? success "答えと解説"
    **正解: B**

    EFS は複数のサーバーでマウントして共有できます。

    - A: 誤り。停止や終了で消える。
    - B: 正しい。
    - C: 誤り。共有にならず、コピーの間は差が出る。
    - D: 誤り。EBS は 1 つの AZ で、通常 1 台。

    **スキル:** [ストレージの種類](../domain2.md#t2-1-storage-types) / **参照:** [比較](../../../services/storage.md#comparison)

### 問2 {#q2}

大量の画像を HTTPS で世界中に配信します。容量の管理はしません。どの種類のストレージですか。

- A. ブロック（EBS）
- B. ファイル（FSx for Windows File Server）
- C. ブロック（インスタンスストア）
- D. オブジェクト（S3）

??? success "答えと解説"
    **正解: D**

    S3 は HTTPS の API で、容量は自動です。

    - A: 誤り。容量の確保が必要で、配信に向かない。
    - B: 誤り。SMB の共有で、配信の用途に合わない。
    - C: 誤り。データが消え、管理も多い。
    - D: 正しい。

    **スキル:** [ストレージの種類](../domain2.md#t2-1-storage-types) / **参照:** [比較](../../../services/storage.md#comparison)

### 問3 {#q3}

ストレージの種類の説明として正しいものはどれですか。

- A. ファイルストレージは複数のサーバーでマウントして共有できる
- B. ブロックストレージの EBS は複数のリージョンで自動的に複製される
- C. オブジェクトストレージは OS からマウントして起動ディスクにする
- D. ブロックストレージは HTTPS の API でオブジェクトを読み書きする

??? success "答えと解説"
    **正解: A**

    選ぶ手がかりは、アクセスの方法と共有の有無です。

    - A: 正しい。
    - B: 誤り。EBS は 1 つの AZ の中で複製する。
    - C: 誤り。それはブロック。
    - D: 誤り。それはオブジェクト。

    **スキル:** [ストレージの種類](../domain2.md#t2-1-storage-types) / **参照:** [EBS、EFS、S3、FSx の比較](../../../services/storage-advanced.md#storage-comparison)

### 問4 {#q4}

再作成できない顧客データを S3 に保管します。次のうち、AZ の喪失でデータを失う可能性があるストレージクラスはどれですか。

- A. S3 Standard-IA
- B. S3 Standard
- C. S3 One Zone-IA
- D. S3 Glacier Flexible Retrieval

??? success "答えと解説"
    **正解: C**

    One Zone-IA と Express One Zone は 1 つの AZ に保存するので、再作成できるデータに使います。

    - A: 誤り。3 つ以上の AZ に保存する。
    - B: 誤り。3 つ以上の AZ に保存する。
    - C: 正しい。
    - D: 誤り。3 つ以上の AZ に保存する。

    **スキル:** [ストレージの耐久性](../domain2.md#t2-2-data-durability) / **参照:** [ストレージクラス](../../../services/s3.md#storage-classes)

### 問5 {#q5}

インスタンスストアのデータの扱いとして正しいものはどれですか。

- A. インスタンスの停止や終了の後も、次の起動で同じデータが読める
- B. EBS と同じくスナップショットで別の AZ へコピーできる
- C. バッファなどの一時データに使い、残すデータは別に保存する
- D. 暗号化ができないので機密データには使えない

??? success "答えと解説"
    **正解: C**

    高速ですが揮発性です。

    - A: 誤り。停止や終了で消える。
    - B: 誤り。スナップショットの機能はない。
    - C: 正しい。
    - D: 誤り。対応するタイプでは暗号化される。

    **スキル:** [ストレージの耐久性](../domain2.md#t2-2-data-durability) / **参照:** [インスタンスストア](../../../services/storage-advanced.md#instance-store)

### 問6 {#q6}

EBS ボリュームのデータを、AZ の障害や破損に備えて保護します。適切なものを選んでください。（2つ選択）

- A. Multi-Attach を有効にして別の AZ のインスタンスにつなぐ
- B. スナップショットを別のリージョンにもコピーする
- C. 同じ AZ に別のボリュームを作ってミラーするだけにする
- D. `io2` に変更すれば複数の AZ に複製されるので、追加の作業は要らない
- E. スナップショットを定期的に取る

??? success "答えと解説"
    **正解: B, E**

    スナップショットは S3 に保存され、全 AZ から復元できます。復元のテストもします。

    - A: 誤り。Multi-Attach は同じ AZ の中でしか使えない。
    - B: 正しい。
    - C: 誤り。同じ AZ の障害に耐えられない。
    - D: 誤り。EBS は 1 つの AZ の中で複製する。
    - E: 正しい。

    **スキル:** [ストレージの耐久性](../domain2.md#t2-2-data-durability) / **参照:** [スナップショット](../../../services/storage.md#ebs-snapshots)、[復元テストと監査](../../../services/resilience.md#backup-testing)

??? success "答えと解説"

    - B: 誤り。NTFS の ACL が必要な共有の置き換えに向かない。
    - C: 誤り。Lustre は HPC 向けで、SMB ではない。
    - D: 正しい。

### 問23 {#q23}

HDD のボリュームが適さない用途を選んでください。（2つ選択）

- A. 順次に読むログの処理
- B. ビッグデータの順次の読み書き
- C. アクセスの少ない大きなコールドデータ
- D. ランダムアクセスの多いトランザクションの DB
- E. EC2 のブートボリューム

??? success "答えと解説"
    **正解: D, E**

    HDD はブートに使えず、ランダムアクセスも遅いです。

    - A: 誤り。`st1` に向く。
    - B: 誤り。`st1` に向く。
    - C: 誤り。`sc1` に向く。
    - D: 正しい。
    - E: 正しい。

    **スキル:** [ブロックストレージ](../domain4.md#t4-1-block) / **参照:** [EBS のボリュームタイプ](../../../services/storage.md#ebs-volume-types)

### 問24 {#q24}

RDS の容量の増加が読めません。最初から大きく確保する費用を避けます。何を有効にしますか。

- A. ストレージの自動スケーリング
- B. リードレプリカの追加とエンドポイントの変更
- C. Multi-AZ の DB クラスターへの変更
- D. バックアップの保持の変更

??? success "答えと解説"
    **正解: A**

    空きが少なくなると自動で増えます。減らすことはできません。

    - A: 正しい。
    - B: 誤り。読み取りの分散で、容量は増えない。
    - C: 誤り。可用性の機能で、容量の増加の機能ではない。
    - D: 誤り。保持の設定で、容量の問題を解決しない。

    **スキル:** [ストレージの自動拡張](../domain4.md#t4-1-autoscale) / **参照:** [RDS](../../../services/databases.md#rds)

### 問25 {#q25}

RDS のストレージの自動スケーリングの動作として正しいものはどれですか。

- A. 最大しきい値は設定できず、無制限に増える
- B. 変更は 1 時間に何回でも行われ、回数の制限はない
- C. 空きが増えると、割り当てが自動で縮小する
- D. 空きが割り当ての 10% 以下で 5 分以上続くなどの条件で増える

??? success "答えと解説"
    **正解: D**

    大量のロードでは間に合わないことがあります。

    - A: 誤り。最大しきい値を設定する。
    - B: 誤り。前回の最適化の完了や回数の条件がある。
    - C: 誤り。減らせない。
    - D: 正しい。

    **スキル:** [ストレージの自動拡張](../domain4.md#t4-1-autoscale) / **参照:** [RDS](../../../services/databases.md#rds)

### 問26 {#q26}

次のうち、容量の自動スケーリングの設定が不要なものはどれですか。

- A. Aurora のクラスターボリューム
- B. EC2 のインスタンスストア
- C. RDS for PostgreSQL の汎用 SSD
- D. EBS の `gp3` ボリューム

??? success "答えと解説"
    **正解: A**

    Aurora は自動で増減します。

    - A: 正しい。
    - B: 誤り。インスタンスタイプで容量が決まる。
    - C: 誤り。有効にする設定が必要。
    - D: 誤り。自動では増えない。

    **スキル:** [ストレージの自動拡張](../domain4.md#t4-1-autoscale) / **参照:** [Aurora](../../../services/databases.md#aurora)
