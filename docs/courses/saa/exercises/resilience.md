### 問1 {#q1}

欧州の利用者には規制のため欧州のサイトだけを見せます。Route 53 のどのルーティングポリシーを使いますか。

- A. 位置情報
- B. 複数値回答
- C. レイテンシー
- D. 加重

??? success "答えと解説"
    **正解: A**

    位置情報ルーティングは、利用者の場所で回答を決めます。

    - A: 正しい。
    - B: 誤り。複数の正常な IP を返すもの。
    - C: 誤り。距離の遅延で決まるので、国の要件を保証しない。
    - D: 誤り。割合での振り分けで、場所は見ない。

    **スキル:** [インフラとルーティング](../domain2.md#t2-2-global) / **参照:** [ルーティングポリシー](../../../services/networking.md#routing-policies)

### 問2 {#q2}

主系のリージョンが落ちたら副系へ切り替えます。Route 53 で必要な設定の組み合わせを選んでください。（2つ選択）

- A. フェイルオーバーのレコード
- B. 加重のレコードで割合を 100 と 0 に固定した設定
- C. プライベートホストゾーンと VPC の関連付け
- D. Route 53 のヘルスチェック
- E. シンプルなレコードに 2 つの IP を書いた設定

??? success "答えと解説"
    **正解: A, D**

    プライマリの異常をヘルスチェックで判定し、セカンダリを返します。

    - A: 正しい。
    - B: 誤り。自動の切り替えの意図に合う形ではなく、ヘルスチェックもない。
    - C: 誤り。VPC の中の名前解決の機能。
    - D: 正しい。
    - E: 誤り。ヘルスチェックを関連付けられない。

    **スキル:** [インフラとルーティング](../domain2.md#t2-2-global) / **参照:** [Route 53 ヘルスチェック](../../../services/networking.md#route53-health-checks)、[ルーティングポリシー](../../../services/networking.md#routing-policies)

### 問3 {#q3}

3 つの AZ のプライベートサブネットに EC2 があり、AZ ごとに NAT ゲートウェイを置きました。AZ の障害が他に波及しないようにするルートテーブルの設定はどれですか。

- A. 全 AZ のサブネットで 1 つのルートテーブルを共有し、最初の NAT を指す
- B. 各サブネットのルートでインターネットゲートウェイを直接指す
- C. ルートテーブルに 3 つの NAT への経路を同じ送信先で登録する
- D. AZ ごとにルートテーブルを分けて、同じ AZ の NAT を指す

??? success "答えと解説"
    **正解: D**

    同じ AZ の NAT を指すと、AZ の障害の影響を受けません。

    - A: 誤り。その AZ の障害で全体が止まる。
    - B: 誤り。プライベートでなくなる。
    - C: 誤り。同じ送信先に複数の経路は持てない。
    - D: 正しい。

    **スキル:** [インフラとルーティング](../domain2.md#t2-2-global) / **参照:** [サブネットとルートテーブル](../../../services/networking.md#subnets-route-tables)

### 問4 {#q4}

RDS MySQL の可用性を上げ、書き込みの切り替えは自動にします。同じリージョンの AZ の障害に備えます。どれを選びますか。

- A. クロスリージョンリードレプリカを作って手動で昇格する
- B. Multi-AZ の DB インスタンス配置
- C. ElastiCache を前に置く
- D. 毎日のスナップショットを別の AZ にコピーする

??? success "答えと解説"
    **正解: B**

    Multi-AZ は同期で複製し、自動でフェイルオーバーします。

    - A: 誤り。自動の切り替えではなく、手順も要る。
    - B: 正しい。
    - C: 誤り。書き込みの可用性にならない。
    - D: 誤り。復元に時間がかかり、データも失う。

    **スキル:** [AZ とリージョン](../domain2.md#t2-2-multi-az-region) / **参照:** [サービスごとの Multi-AZ と Multi-Region](../../../services/resilience.md#patterns-by-service)

    - A: 誤り。同じクラスターの読み取りの分け方。
    - B: 誤り。同じリージョンの中。
    - C: 正しい。
    - D: 誤り。データは複製されない。

    **スキル:** [AZ とリージョン](../domain2.md#t2-2-multi-az-region) / **参照:** [Aurora グローバルデータベース](../../../services/databases.md#aurora-global-database)

### 問10 {#q10}

DNS のキャッシュの影響を受けずに、すばやく別のリージョンへ切り替えます。クライアントは固定 IP を使います。どれが適切ですか。

- A. CloudFront のオリジンフェイルオーバーを設定する
- B. Route 53 のフェイルオーバーで TTL を 60 秒にする

    - B: 誤り。TTL やクライアントのキャッシュに左右される。
    - C: 正しい。
    - D: 誤り。同じリージョンの AZ 間の話。

    **スキル:** [フェイルオーバーの戦略](../domain2.md#t2-2-failover) / **参照:** [Global Accelerator との比較](../../../services/resilience.md#global-accelerator)
