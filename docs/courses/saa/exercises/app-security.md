# アプリケーションのアクセスと認証情報の問題集

対象の解説: [シークレットと設定](../../../services/secrets.md)、[Amazon Cognito](../../../services/cognito.md)

### 問1 {#q1}

アプリの RDS のパスワードを 30 日ごとに自動で入れ替えます。コードに値を書きません。最も少ない運用負荷の方法はどれですか。

- A. S3 に暗号化して置き、月に 1 度手で差し替える
- B. 環境変数に値を設定し、30 日ごとに手作業で全インスタンスを更新する
- C. Parameter Store の `SecureString` に保存し、EventBridge と自作の Lambda で更新する
- D. Secrets Manager に保存し、マネージドのローテーションを有効にする

??? success "答えと解説"
    **正解: D**

    Secrets Manager は RDS のローテーションを統合して提供します。

    - A: 誤り。ローテーションの機能がない。
    - B: 誤り。平文で手作業が残る。
    - C: 誤り。動作するが自作が必要で、運用負荷が大きい。
    - D: 正しい。

    **スキル:** [認証情報の保護](../domain1.md#t1-2-credentials) / **参照:** [ローテーション](../../../services/secrets.md#rotation)

### 問2 {#q2}

アプリの設定値と、ローテーションの要らない低リスクのトークンを安価に階層で管理します。どれが適切ですか。

- A. Parameter Store の標準パラメータで階層のパスを付けて保存する
- B. Secrets Manager にすべての設定値を 1 件ずつ保存して課金を受け入れる
- C. ソースコードの定数に書いて、Git で保護する
- D. DynamoDB のテーブルを自作して、暗号化のコードも書く

??? success "答えと解説"
    **正解: A**

    Parameter Store の標準パラメータは追加料金なしで、`SecureString` で暗号化もできます。

    - A: 正しい。
    - B: 誤り。シークレットごとの料金がかかる。
    - C: 誤り。コードに秘密情報を残す。
    - D: 誤り。不要な構築になる。

    **スキル:** [認証情報の保護](../domain1.md#t1-2-credentials) / **参照:** [Systems Manager Parameter Store](../../../services/secrets.md#parameter-store)、[3 つのサービスの比較](../../../services/secrets.md#comparison)

### 問3 {#q3}

EC2 のアプリの SSRF の脆弱性で、インスタンスメタデータからロールの認証情報を盗まれるリスクを下げます。どの設定が有効ですか。

- A. メタデータのホップ数の制限を大きくする
- B. インスタンスのメタデータの設定で IMDSv2 を必須にする
- C. SG で `169.254.169.254` への通信を拒否するルールを追加する
- D. インスタンスプロファイルを外し、アクセスキーを設定ファイルに置く

??? success "答えと解説"
    **正解: B**

    IMDSv2 はセッションのトークンを必須にするので、単純な GET での読み取りを防げます。

    - A: 誤り。到達の範囲が広がる。
    - B: 正しい。
    - C: 誤り。SG に拒否ルールはない。
    - D: 誤り。長期の認証情報になり、悪化する。

    **スキル:** [認証情報の保護](../domain1.md#t1-2-credentials) / **参照:** [インスタンスメタデータサービス (IMDS)](../../../services/ec2-beanstalk.md#imds)

### 問4 {#q4}

RDS for PostgreSQL に、アプリからパスワードなしで接続します。インスタンスのロールで認証トークンを発行します。どの機能ですか。

- A. Secrets Manager のマルチユーザーローテーション戦略
- B. KMS のグラントを DB のユーザーに発行する機能
- C. RDS の IAM データベース認証
- D. RDS の自動バックアップ

??? success "答えと解説"
    **正解: C**

    IAM データベース認証は MariaDB、MySQL、PostgreSQL で使えます。短命のトークンで接続します。

    - A: 誤り。パスワードの入れ替えで、パスワードなしの接続ではない。
    - B: 誤り。鍵の権限で、DB の認証ではない。
    - C: 正しい。
    - D: 誤り。認証と関係ない。

    **スキル:** [認証情報の保護](../domain1.md#t1-2-credentials) / **参照:** [IAM データベース認証](../../../services/databases.md#rds-iam-auth)

### 問5 {#q5}

認証情報の置き場所として不適切なものを選んでください。（2つ選択）

- A. EC2 のインスタンスプロファイル
- B. ソースコードのリポジトリ
- C. Secrets Manager
- D. AMI に焼き込んだ設定ファイル
- E. Parameter Store の `SecureString`

??? success "答えと解説"
    **正解: B, D**

    AMI やコードに入れると、コピーした先まで秘密情報が広がり、入れ替えもできません。

    - A: 誤り。AWS の権限を渡す適切な方法。
    - B: 正しい。
    - C: 誤り。適切な置き場所。
    - D: 正しい。
    - E: 誤り。適切な置き場所。

    **スキル:** [認証情報の保護](../domain1.md#t1-2-credentials) / **参照:** [3 つのサービスの比較](../../../services/secrets.md#comparison)

### 問6 {#q6}

モバイルアプリの利用者のサインアップとサインインを、ソーシャルログインも含めて実装します。どれを使いますか。

- A. Cognito ユーザープールとソーシャル IdP の連携
- B. IAM ユーザーを利用者ごとに作り、アクセスキーをアプリに配る
- C. AD Connector で利用者を社内の AD に登録して認証する
- D. Identity Center の権限セット

??? success "答えと解説"
    **正解: A**

    ユーザープールは利用者のディレクトリで、サインアップ、サインイン、ソーシャル連携を提供します。

    - A: 正しい。
    - B: 誤り。一般の利用者に IAM ユーザーは使わない。
    - C: 誤り。従業員のディレクトリの仕組み。
    - D: 誤り。従業員向けのサービス。

    **スキル:** [アプリへのアクセス](../domain1.md#t1-2-app-access) / **参照:** [ユーザープールと ID プール](../../../services/cognito.md#user-vs-identity-pools)

### 問7 {#q7}

サインイン済みのモバイル利用者が、自分のフォルダの S3 オブジェクトを直接アップロードします。AWS の一時的な認証情報を渡すのはどれですか。

- A. S3 ブロックパブリックアクセスの無効化と匿名の書き込み
- B. Cognito ID プールと認証済みロール
- C. Cognito ユーザープールのアプリクライアントの ID トークン
- D. ALB のセッション Cookie

??? success "答えと解説"
    **正解: B**

    ID プールはトークンを受け取り、IAM ロールの一時的な認証情報に交換します。

    - A: 誤り。公開になり不適切。
    - B: 正しい。
    - C: 誤り。トークンそのものは AWS の認証情報ではない。
    - D: 誤り。アプリへのアクセス用で、AWS の認証情報ではない。

    **スキル:** [アプリへのアクセス](../domain1.md#t1-2-app-access) / **参照:** [ユーザープールと ID プール](../../../services/cognito.md#user-vs-identity-pools)

### 問8 {#q8}

有料の動画を、CloudFront で購入者だけに配信します。購入者は多数のファイルにアクセスし、URL は変えたくありません。何を使いますか。

- A. S3 の署名付き URL をファイルごとに生成して、バケットを公開する
- B. CloudFront の署名付き URL を動画の 1 ファイルごとに発行する
- C. CloudFront の署名付き Cookie
- D. WAF の地理的一致ルール

??? success "答えと解説"
    **正解: C**

    署名付き Cookie は URL を変えずに、複数のファイルへのアクセスを許可します。

    - A: 誤り。URL が変わり、オリジンも公開になる。
    - B: 誤り。多数のファイルで URL を変えたくない要件に合わない。
    - C: 正しい。
    - D: 誤り。購入者の識別にならない。

    **スキル:** [アプリへのアクセス](../domain1.md#t1-2-app-access) / **参照:** [署名付き URL と署名付き Cookie](../../../services/networking.md#signed-urls-cookies)

### 問9 {#q9}

S3 の静的コンテンツを CloudFront 経由でだけ公開し、S3 の URL からの直接のアクセスは拒否します。設定を選んでください。（2つ選択）

- A. S3 の静的ウェブサイトエンドポイントをオリジンにする
- B. S3 の署名付き URL を CloudFront のオリジンパスに固定して設定する
- C. バケットを公開にし、Referer ヘッダーを条件にしてブラウザを制限する
- D. バケットポリシーで CloudFront のサービスプリンシパルを許可する
- E. OAC を設定し、ブロックパブリックアクセスは有効のままにする

??? success "答えと解説"
    **正解: D, E**

    OAC は CloudFront の署名でオリジンの S3 へアクセスします。

    - A: 誤り。ウェブサイトエンドポイントには公開が必要で、OAC を使えない。
    - B: 誤り。期限があり、この用途の方式ではない。
    - C: 誤り。ヘッダーは偽装でき、バケットも公開になる。
    - D: 正しい。
    - E: 正しい。

    **スキル:** [アプリへのアクセス](../domain1.md#t1-2-app-access) / **参照:** [S3 オリジンの保護: OAC](../../../services/networking.md#oac)

### 問10 {#q10}

社内向け Web アプリを、VPN なしで従業員に公開します。リクエストごとに ID と端末の状態を評価します。どれが適切ですか。

- A. インターネット向け ALB の SG を `0.0.0.0/0` で開ける
- B. Client VPN を従業員の全端末に配布する
- C. S3 の署名付き URL を毎日配信する
- D. AWS Verified Access のアクセスポリシー

??? success "答えと解説"
    **正解: D**

    Verified Access は ID とデバイスの条件をリクエストごとに評価する、VPN を使わない方式です。

    - A: 誤り。誰でも到達でき、ID の評価もない。
    - B: 誤り。VPN なしという要件に反する。
    - C: 誤り。アプリのアクセスの制御に合わない。
    - D: 正しい。

    **スキル:** [アプリへのアクセス](../domain1.md#t1-2-app-access) / **参照:** [Verified Access](../../../services/identity-directory.md#verified-access)
