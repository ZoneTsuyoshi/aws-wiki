# データの保護の問題集

対象の解説: [Amazon S3](../../../services/s3.md)、[回復性](../../../services/resilience.md)

### 問1 {#q1}

組織の全アカウントで、S3 バケットが誤って公開されることを防ぎます。最も適切なものはどれですか。

- A. 全バケットを SSE-KMS で暗号化して公開の影響を抑える
- B. バケットごとの ACL を毎週確認して手で修正する
- C. 組織やアカウントのレベルで S3 ブロックパブリックアクセスを有効にする
- D. CloudTrail のデータイベントで公開の操作を記録する

??? success "答えと解説"
    **正解: C**

    ブロックパブリックアクセスは、個々の設定よりも優先して公開を防ぎます。

    - A: 誤り。暗号化は公開の防止にならない。
    - B: 誤り。手作業で、防止にならない。
    - C: 正しい。
    - D: 誤り。記録で、防止ではない。

    **スキル:** [データガバナンス](../domain1.md#t1-3-governance) / **参照:** [ブロックパブリックアクセス](../../../services/s3.md#block-public-access)

### 問2 {#q2}

監査で「S3 のオブジェクトを誰が読んだか」を示せませんでした。CloudTrail の証跡はあります。何を変更しますか。

- A. S3 のデータイベントの記録を有効にする
- B. バケットのバージョニングを有効にして履歴を確認する
- C. 管理イベントの記録を、読み取りと書き込みの両方に変更する
- D. S3 のストレージメトリクスを見る

??? success "答えと解説"
    **正解: A**

    データイベントは既定で記録されません。

    - A: 正しい。
    - B: 誤り。読み取りの記録にならない。
    - C: 誤り。オブジェクトの読み取りは管理イベントではない。
    - D: 誤り。容量の数値で、誰が読んだかは分からない。

    **スキル:** [データガバナンス](../domain1.md#t1-3-governance) / **参照:** [イベントの種類](../../../services/observability.md#cloudtrail-events)

### 問3 {#q3}

データレイクの S3 のテーブルで、人事の列は一部の分析者だけに見せます。列と行の単位の権限を 1 か所で管理します。何を使いますか。

- A. バケットポリシーのプレフィックスで列ごとに制限する
- B. Lake Formation の列と行の権限
- C. Macie の機密データの検出ジョブで該当する列を隠す
- D. Glue クローラーの設定

??? success "答えと解説"
    **正解: B**

    Lake Formation はテーブル、列、行の権限を一元管理します。

    - A: 誤り。オブジェクトの単位で、列は分けられない。
    - B: 正しい。
    - C: 誤り。発見のサービスで、権限の管理ではない。
    - D: 誤り。スキーマの検出で、権限の管理ではない。

    **スキル:** [データガバナンス](../domain1.md#t1-3-governance) / **参照:** [AWS Lake Formation](../../../services/data-engineering.md#lake-formation)

### 問4 {#q4}

S3 バケットの次の要件を満たす組み合わせを選んでください。誤った削除から戻せること、古いバージョンを 90 日で消して費用を抑えること。（2つ選択）

- A. ブロックパブリックアクセスの全項目を有効にする
- B. ライフサイクルの `NoncurrentVersionExpiration` を 90 日にする
- C. Object Lock のコンプライアンスモードを 90 日で全オブジェクトに設定する
- D. バージョニングを有効にする
- E. S3 Transfer Acceleration を有効にする

??? success "答えと解説"
    **正解: B, D**

    バージョニングで戻せるようにし、古いバージョンをライフサイクルで片付けます。

    - A: 誤り。公開の防止で、削除の復旧にならない。
    - B: 正しい。
    - C: 誤り。削除そのものを禁止する機能で、要件と違う。
    - D: 正しい。
    - E: 誤り。転送の高速化で、関係ない。

    **スキル:** [データガバナンス](../domain1.md#t1-3-governance) / **参照:** [バージョニング](../../../services/s3.md#versioning)、[ライフサイクル](../../../services/s3.md#lifecycle)

### 問5 {#q5}

監査ログを 7 年間、ルートユーザーを含めて誰にも削除させません。正しい設定はどれですか。

- A. Object Lock のガバナンスモードで 7 年の保持期間を設定する
- B. MFA Delete を有効にして、管理者の MFA デバイスを金庫に保管する
- C. ライフサイクルで 7 年後に失効させるルールだけを設定する
- D. Object Lock のコンプライアンスモードで 7 年の保持期間を設定する

??? success "答えと解説"
    **正解: D**

    コンプライアンスモードは、誰も削除できず、期間の短縮もできません。

    - A: 誤り。権限があれば迂回できる。
    - B: 誤り。削除に MFA を求めるだけで、保持を保証しない。
    - C: 誤り。7 年より前の削除を防げない。
    - D: 正しい。

    **スキル:** [保持と分類](../domain1.md#t1-3-classification) / **参照:** [Object Lock](../../../services/s3.md#object-lock)

### 問6 {#q6}

機密度に応じて S3 のオブジェクトへのアクセスを制御します。ロールとオブジェクトの属性の一致で許可する方式で、分類の変更にも追従させたいと考えています。何を使いますか。

- A. ロールとオブジェクトのタグを使う ABAC
- B. CloudWatch Logs の保持期間を分類ごとに変更する
- C. ブロックパブリックアクセス
- D. プレフィックスごとに IAM ユーザーを作って権限を固定する

??? success "答えと解説"
    **正解: A**

    タグで分類を示し、タグの一致を条件に許可します。

    - A: 正しい。
    - B: 誤り。ログの保持で、アクセス制御ではない。
    - C: 誤り。公開の防止で、分類に基づかない。
    - D: 誤り。分類が変わるたびに変更が必要。

    **スキル:** [保持と分類](../domain1.md#t1-3-classification) / **参照:** [タグ戦略](../../../services/governance.md#tagging-strategy)

### 問7 {#q7}

AWS Backup のバックアップを、ランサムウェアや管理者の誤操作でも保持期間の間は削除させません。どの機能を使いますか。

- A. S3 Object Lock のガバナンスモードをボールトのバケットに設定する
- B. AWS Backup の Vault Lock
- C. バックアッププランの開始時間のウィンドウを短くする
- D. Config ルールでの検出

??? success "答えと解説"
    **正解: B**

    Vault Lock はボールトのバックアップを、設定した期間だけ削除できないようにします。

    - A: 誤り。ボールトはバケットではなく、ガバナンスは迂回できる。
    - B: 正しい。
    - C: 誤り。実行の時間の設定。
    - D: 誤り。検出で、削除を防げない。

    **スキル:** [保持と分類](../domain1.md#t1-3-classification) / **参照:** [Vault Lock](../../../services/resilience.md#vault-lock)

### 問8 {#q8}

S3 のレプリケーションで別のリージョンに複製しています。破損したファイルの上書きからも復旧できるようにします。正しい考え方はどれですか。

- A. ライフサイクルで複製元を Deep Archive に移して保護する
- B. レプリケーションがあれば破損は複製されないので、追加の対策は要らない
- C. 宛先のバケットの暗号化を変更すると、破損の複製を防げる
- D. 両方のバケットでバージョニングを使っているので、以前のバージョンに戻す

??? success "答えと解説"
    **正解: D**

    レプリケーションは両方のバケットでバージョニングが必須です。破損に備えるのは過去のバージョンです。

    - A: 誤り。階層の変更で、復旧の仕組みではない。
    - B: 誤り。破損や上書きも複製される。
    - C: 誤り。暗号化は関係しない。
    - D: 正しい。

    **スキル:** [データの復旧](../domain1.md#t1-3-backup) / **参照:** [レプリケーション](../../../services/s3.md#replication)、[バージョニング](../../../services/s3.md#versioning)

### 問9 {#q9}

複数のサービス（EBS、RDS、DynamoDB、EFS）のバックアップを一元管理し、別のアカウントにもコピーします。どれを選びますか。

- A. Data Lifecycle Manager をすべてのサービスに適用する
- B. S3 のレプリケーション
- C. AWS Backup のプランとアカウント間コピー
- D. サービスごとに自作の Lambda を書いてスナップショットを取り、コピーする

??? success "答えと解説"
    **正解: C**

    AWS Backup はプランで複数のサービスをまとめ、組織の別アカウントへのコピーも扱えます。

    - A: 誤り。EBS のスナップショットと AMI が対象。
    - B: 誤り。S3 の機能で、他のサービスに使えない。
    - C: 正しい。
    - D: 誤り。動作するが運用負荷が大きい。

    **スキル:** [データの復旧](../domain1.md#t1-3-backup) / **参照:** [AWS Backup](../../../services/resilience.md#backup)、[アカウント間コピーと組織での管理](../../../services/resilience.md#backup-cross-account)

### 問10 {#q10}

DynamoDB のテーブルを、35 日以内の任意の秒の時点に戻せるようにします。何を有効にしますか。

- A. DAX クラスターを追加する
- B. ポイントインタイムリカバリ（PITR）
- C. グローバルテーブルの別リージョンのレプリカを読む
- D. オンデマンドバックアップを 1 日 1 回スケジュールで作成する

??? success "答えと解説"
    **正解: B**

    PITR は 1〜35 日の範囲で設定でき、その期間内の任意の時点に復元できます。

    - A: 誤り。キャッシュで、復旧の機能ではない。
    - B: 正しい。
    - C: 誤り。誤った書き込みも複製される。
    - D: 誤り。取得した時点にしか戻せない。

    **スキル:** [データの復旧](../domain1.md#t1-3-backup) / **参照:** [バックアップと復元](../../../services/dynamodb.md#backup)

### 問11 {#q11}

RDS の自動バックアップの説明として正しいものはどれですか。

- A. 自動バックアップを有効にするとリードレプリカが自動で作られる
- B. 手動スナップショットも保持期間が過ぎると自動で消える
- C. 保持期間は最大 90 日で、0 にはできない
- D. 保持期間は 0〜35 日で、時点復旧に使える

??? success "答えと解説"
    **正解: D**

    長期の保管には、手動スナップショットや AWS Backup を使います。

    - A: 誤り。レプリカは別途作成する。
    - B: 誤り。手動スナップショットは削除するまで残る。
    - C: 誤り。0〜35 日で、0 で無効。
    - D: 正しい。

    **スキル:** [データの復旧](../domain1.md#t1-3-backup) / **参照:** [RDS](../../../services/databases.md#rds)
