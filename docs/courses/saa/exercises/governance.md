# ガバナンスと責任共有の問題集

対象の解説: [ガバナンス](../../../services/governance.md)、[クラウドの基礎](../../../services/cloud-foundations.md)

### 問1 {#q1}

全メンバーアカウントで、各アカウントの管理者を含めて CloudTrail の停止を禁止します。最も適切なものはどれですか。

- A. Config ルールで停止を検出してメールで通知する
- B. CloudTrail の証跡をメンバーアカウントごとに複製する
- C. `cloudtrail:StopLogging` を拒否する SCP をルートか OU に付ける
- D. 各アカウントに `cloudtrail:StopLogging` を拒否する IAM ポリシーを配布する

??? success "答えと解説"
    **正解: C**

    SCP はメンバーアカウントの IAM プリンシパルの権限の上限で、管理者でも超えられません。

    - A: 誤り。検出だけで、操作を止められない。
    - B: 誤り。停止の防止にならない。
    - C: 正しい。
    - D: 誤り。管理者がポリシーを外せる。

    **スキル:** [複数アカウントの戦略](../domain1.md#t1-1-multi-account) / **参照:** [SCP](../../../services/governance.md#scp)

### 問2 {#q2}

SCP の説明として正しいものを選んでください。（2つ選択）

- A. 管理アカウントのプリンシパルには効かない
- B. SCP を付けられるのはアカウント単位だけで、OU には付けられない
- C. 外部のアカウントのプリンシパルがリソースへアクセスするのを直接制限する
- D. サービスリンクロールには効かない
- E. SCP で Allow すると、IAM ポリシーがなくてもその操作が可能になる

??? success "答えと解説"
    **正解: A, D**

    SCP は上限を決めるだけなので、IAM での許可も必要です。例外も合わせて覚えます。

    - A: 正しい。
    - B: 誤り。ルート、OU、アカウントに付けられる。
    - C: 誤り。それは RCP の役割。
    - D: 正しい。
    - E: 誤り。SCP は権限を与えない。

    **スキル:** [複数アカウントの戦略](../domain1.md#t1-1-multi-account) / **参照:** [SCP](../../../services/governance.md#scp)、[SCP と RCP の例外](../../../services/identity-directory.md#guardrail-exceptions)

### 問3 {#q3}

組織の S3 バケットに、組織の外のプリンシパルがアクセスできないよう、リソース側の上限を組織全体で設定します。何を使いますか。

- A. 権限境界
- B. Firewall Manager のセキュリティポリシー
- C. SCP
- D. RCP（リソースコントロールポリシー）

??? success "答えと解説"
    **正解: D**

    RCP はリソース制御ポリシーで、組織のリソースへのアクセスの上限を一元的に決めます。

    - A: 誤り。個々のプリンシパルの上限。
    - B: 誤り。WAF や SG などのルールを展開するサービス。
    - C: 誤り。SCP は組織のプリンシパルの権限の上限で、外部のプリンシパルには効かない。
    - D: 正しい。

    **スキル:** [複数アカウントの戦略](../domain1.md#t1-1-multi-account) / **参照:** [RCP](../../../services/governance.md#rcp)

### 問4 {#q4}

新しい会社のマルチアカウント環境を、ベストプラクティスに沿ってすばやく構築します。ログ用と監査用のアカウント、予防と検出のコントロールも揃えたいと考えています。何を選びますか。

- A. CloudFormation で各アカウントの VPC だけを揃える
- B. Control Tower でランディングゾーンを作る
- C. Service Catalog の製品を手で組み合わせる
- D. Trusted Advisor の推奨を順に適用する

??? success "答えと解説"
    **正解: B**

    Control Tower はランディングゾーンとコントロールを組み立て、新しいアカウントも承認済みの設定で作れます。

    - A: 誤り。統制の仕組みが含まれない。
    - B: 正しい。
    - C: 誤り。承認済みの製品を配るサービスで、環境全体は作らない。
    - D: 誤り。点検で、環境を構築しない。

    **スキル:** [複数アカウントの戦略](../domain1.md#t1-1-multi-account) / **参照:** [AWS Control Tower](../../../services/governance.md#control-tower)

### 問5 {#q5}

ネットワークチームのアカウントの VPC のサブネットを、複数のアプリのアカウントで使わせます。VPC ピアリングは増やしたくありません。何を使いますか。

- A. RAM で VPC のサブネットを共有する
- B. 別アカウントのロールを引き受けてインスタンスを起動させる
- C. Service Catalog でサブネットを配布する
- D. 各アカウントに同じ CIDR の VPC を作り、ルートテーブルをコピーする

??? success "答えと解説"
    **正解: A**

    RAM の VPC サブネット共有なら、VPC 間の接続を増やさずにアカウントを分けられます。

    - A: 正しい。
    - B: 誤り。費用や権限の分離が崩れ、要件に合わない。
    - C: 誤り。リソースの共有ではなく、製品の配布。
    - D: 誤り。別のネットワークになり、CIDR の重複で接続もできない。

    **スキル:** [複数アカウントの戦略](../domain1.md#t1-1-multi-account) / **参照:** [AWS Resource Access Manager](../../../services/governance.md#ram)、[VPC サブネットの共有](../../../services/governance.md#ram-vpc-sharing)

### 問6 {#q6}

規制で、顧客データを東京と大阪のリージョンの外に置けません。誤って他のリージョンにリソースを作る操作を組織全体で止めるにはどうしますか。

- A. S3 の複製先を東京と大阪に限定する
- B. 全員に他のリージョンを使わないよう周知し、Config で報告する
- C. VPC を東京と大阪にだけ作り、他のリージョンの VPC を削除する
- D. 他のリージョンを拒否する SCP を組織に付ける

??? success "答えと解説"
    **正解: D**

    リージョンの制限には、`aws:RequestedRegion` を条件にした SCP を使います。IAM や Route 53 などグローバルなサービスは除外を考えます。

    - A: 誤り。S3 のレプリケーションだけの話で、全リソースに及ばない。
    - B: 誤り。操作を止められない。
    - C: 誤り。VPC を使わないサービスは止められない。
    - D: 正しい。

    **スキル:** [グローバルインフラ](../domain1.md#t1-1-global-infra) / **参照:** [リージョン](../../../services/cloud-foundations.md#regions)、[SCP](../../../services/governance.md#scp)

### 問7 {#q7}

アベイラビリティーゾーン（AZ）の説明として正しいものはどれですか。

- A. CloudFront の配信のために世界中の都市に置かれる拠点である
- B. 1 つのデータセンターの中の別のラックを指し、電源は共有する
- C. 互いに離れた独立した区画で、複数に分けると障害の影響を抑えられる
- D. リージョンをまたいで作成でき、グローバルに同じ名前を共有する

??? success "答えと解説"
    **正解: C**

    AZ は単一障害点を共有しないように分かれています。

    - A: 誤り。それはエッジロケーション。
    - B: 誤り。AZ は独立した電源、冷却、ネットワークを持つ区画。
    - C: 正しい。
    - D: 誤り。AZ はリージョンの中にある。

    **スキル:** [グローバルインフラ](../domain1.md#t1-1-global-infra) / **参照:** [アベイラビリティーゾーン](../../../services/cloud-foundations.md#availability-zones)

### 問8 {#q8}

ある会社がリージョンを選びます。判断の材料として最も優先して確認すべきものはどれですか。

- A. エッジロケーションの総数が世界で最も多いかどうか
- B. データの所在の規制を満たすかどうか
- C. IAM ユーザーをそのリージョンに置けるかどうか
- D. コンソールの表示言語

??? success "答えと解説"
    **正解: B**

    所在の規制があれば、まずリージョンを絞ります。そのあとに距離、サービスの有無、料金を比べます。

    - A: 誤り。リージョン選択の第一の基準ではない。
    - B: 正しい。
    - C: 誤り。IAM はグローバルなサービス。
    - D: 誤り。コンソールの言語はリージョンの選択に関わらない。

    **スキル:** [グローバルインフラ](../domain1.md#t1-1-global-infra) / **参照:** [リージョン](../../../services/cloud-foundations.md#regions)

### 問9 {#q9}

RDS for MySQL を使っています。責任共有モデルで利用者の責任になるものを選んでください。（2つ選択）

- A. DB エンジンのパッチのプログラムの作成と検証
- B. DB のユーザーの権限
- C. セキュリティグループの設定
- D. ストレージのディスクの廃棄
- E. データベースが動く物理サーバーの交換

??? success "答えと解説"
    **正解: B, C**

    RDS でも、ネットワークの許可、DB のユーザー、暗号化の設定、データは利用者が担当します。

    - A: 誤り。AWS が提供する。利用者は適用の時間帯を決める。
    - B: 正しい。
    - C: 正しい。
    - D: 誤り。AWS の責任。
    - E: 誤り。クラウド自体のセキュリティで AWS の責任。

    **スキル:** [責任共有モデル](../domain1.md#t1-1-shared-responsibility) / **参照:** [サービスごとの違い](../../../services/cloud-foundations.md#responsibility-by-service)

### 問10 {#q10}

EC2 で動かす Linux のセキュリティパッチの責任について、正しいものはどれですか。

- A. ゲスト OS は利用者の責任で、Patch Manager などで適用する
- B. サポートプランが Enterprise のときだけ AWS の責任になる
- C. AWS が自動で適用するので、利用者の作業は要らない
- D. ハイパーバイザーと同じく、AWS と利用者で等分に負担する

??? success "答えと解説"
    **正解: A**

    EC2 は抽象度が低いので、OS から上は利用者の範囲です。

    - A: 正しい。
    - B: 誤り。サポートプランで責任の分担は変わらない。
    - C: 誤り。EC2 のゲスト OS は利用者の責任。
    - D: 誤り。ハイパーバイザーは AWS、ゲスト OS は利用者。

    **スキル:** [責任共有モデル](../domain1.md#t1-1-shared-responsibility) / **参照:** [責任共有モデル](../../../services/cloud-foundations.md#shared-responsibility)

### 問11 {#q11}

同じ処理を EC2、Lambda で動かす場合を比べます。Lambda に移すことで、利用者の責任から外れるものはどれですか。

- A. 実行ロールの権限の設計
- B. 実行環境の OS のパッチの適用
- C. 処理するデータの分類と保護
- D. 関数のコードの脆弱性への対応

??? success "答えと解説"
    **正解: B**

    Lambda では OS とランタイムの基盤を AWS が管理します。コード、ロール、データは残ります。

    - A: 誤り。権限の設計は利用者の責任。
    - B: 正しい。
    - C: 誤り。データは利用者の責任。
    - D: 誤り。コードは利用者の責任。

    **スキル:** [責任共有モデル](../domain1.md#t1-1-shared-responsibility) / **参照:** [サービスごとの違い](../../../services/cloud-foundations.md#responsibility-by-service)

### 問12 {#q12}

監査人から、AWS の SOC 2 レポートと ISO の認証の提出を求められました。どこで入手しますか。

- A. Trusted Advisor のチェック
- B. Config の適合パック
- C. Security Hub CSPM の検出結果
- D. AWS Artifact のレポート

??? success "答えと解説"
    **正解: D**

    Artifact は AWS 自身の第三者監査レポートと契約を入手する場所です。

    - A: 誤り。自社の環境の点検。
    - B: 誤り。自社の設定の評価。
    - C: 誤り。自社の環境の評価で、AWS の報告書ではない。
    - D: 正しい。

    **スキル:** [コンプライアンス](../domain1.md#t1-3-compliance) / **参照:** [AWS Artifact](../../../services/threat-detection.md#artifact)

### 問13 {#q13}

自社の全アカウントの設定が、規制の基準に合っているかを継続して評価し、結果を監査に示します。ルールのセットをまとめて配布したいと考えています。どれを選びますか。

- A. CloudTrail の Insights
- B. AWS Artifact の報告書
- C. Config の適合パックの組織への展開
- D. GuardDuty の脅威リスト

??? success "答えと解説"
    **正解: C**

    適合パックは Config ルールと修復アクションの集まりで、組織に展開できます。

    - A: 誤り。API の異常な活動を検出する機能。
    - B: 誤り。AWS 自身の報告書で、自社の設定を評価しない。
    - C: 正しい。
    - D: 誤り。脅威の検出で、設定の準拠の評価ではない。

    **スキル:** [コンプライアンス](../domain1.md#t1-3-compliance) / **参照:** [適合パック](../../../services/governance.md#config-conformance-packs)

### 問14 {#q14}

規制で、単一テナントの HSM で鍵を管理し、FIPS 140 の検証済みの機器を自社だけで制御する必要があります。何を選びますか。

- A. CloudHSM
- B. Secrets Manager のカスタマー管理シークレット
- C. ACM の公開証明書
- D. KMS の AWS 管理キー

??? success "答えと解説"
    **正解: A**

    CloudHSM は単一テナントの HSM を提供します。AWS サービスで使うなら KMS のキーストアに接続できます。

    - A: 正しい。
    - B: 誤り。シークレットの保管で、HSM ではない。
    - C: 誤り。証明書の発行のサービス。
    - D: 誤り。AWS が管理する鍵で、単一テナントの要件に合わない。

    **スキル:** [コンプライアンス](../domain1.md#t1-3-compliance) / **参照:** [KMS との比較](../../../services/identity-directory.md#cloudhsm-vs-kms)

### 問15 {#q15}

API の操作の記録を 7 年間、改ざんされない形で保管します。最も適切なものを選んでください。（2つ選択）

- A. EC2 のローカルディスクにログを定期的にコピーする
- B. CloudTrail のイベント履歴をそのまま参照する
- C. CloudTrail の証跡を S3 に送る
- D. S3 Object Lock のコンプライアンスモードを使う
- E. CloudWatch のメトリクスに記録して保持期間を 7 年にする

??? success "答えと解説"
    **正解: C, D**

    長期の保管には証跡が必要です。Object Lock のコンプライアンスモードなら、誰も期間内に削除できません。

    - A: 誤り。耐久性がなく、改ざんも防げない。
    - B: 誤り。イベント履歴は 90 日で、管理イベントだけ。
    - C: 正しい。
    - D: 正しい。
    - E: 誤り。メトリクスは API の操作の記録ではない。

    **スキル:** [コンプライアンス](../domain1.md#t1-3-compliance) / **参照:** [証跡とイベント履歴](../../../services/observability.md#cloudtrail-trails)、[Object Lock](../../../services/s3.md#object-lock)
