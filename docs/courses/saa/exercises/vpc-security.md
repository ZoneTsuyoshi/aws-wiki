# VPC のセキュリティの問題集

対象の解説: [ネットワークと配信](../../../services/networking.md)、[ネットワーク接続](../../../services/network-connectivity.md)

### 問1 {#q1}

ALB の後ろのアプリのインスタンスは、ALB からの 443 だけを受けます。ALB の IP は変わることがあります。アプリの SG はどう書きますか。

- A. 送信元に ALB の SG を指定する
- B. 送信元を `0.0.0.0/0` にしてアプリ側で IP を検査する
- C. 送信元に ALB の現在の IP を書き、変わったら更新する
- D. NACL で ALB の IP を許可し、SG はすべて許可にする

??? success "答えと解説"
    **正解: A**

    SG の送信元には別の SG を指定でき、IP の変化に影響されません。

    - A: 正しい。
    - B: 誤り。インターネット全体に開くことになる。
    - C: 誤り。IP は変わるので追従できない。
    - D: 誤り。IP の問題が残り、SG の保護もなくなる。

    **スキル:** [VPC のセキュリティ部品](../domain1.md#t1-2-vpc-security) / **参照:** [セキュリティグループのルール](../../../services/networking.md#security-group-rules)

### 問2 {#q2}

特定の IP アドレスからの攻撃を、サブネットの単位で止めます。どれを使いますか。

- A. ルートテーブルからインターネットゲートウェイを外す
- B. SG に拒否ルールを追加する
- C. NAT ゲートウェイに拒否リストを設定する
- D. NACL に番号の小さい拒否ルールを追加する

??? success "答えと解説"
    **正解: D**

    NACL は許可と拒否を番号の小さい順に評価します。拒否は許可より小さい番号にします。

    - A: 誤り。すべての通信が止まる。
    - B: 誤り。SG には拒否ルールがない。
    - C: 誤り。NAT ゲートウェイにそのような機能はない。
    - D: 正しい。

    **スキル:** [VPC のセキュリティ部品](../domain1.md#t1-2-vpc-security) / **参照:** [ネットワーク ACL のルール](../../../services/networking.md#nacl-rules)

### 問3 {#q3}

自作の NACL をプライベートサブネットに付けたところ、NAT ゲートウェイ経由でインターネットの更新サーバーへ行く通信が失敗します。SG は問題ありません。原因として最も可能性が高いのはどれですか。

- A. NACL はステートフルなので、戻りの許可は不要だが送信の評価で失敗している
- B. 戻りのエフェメラルポートの許可がない
- C. NAT の SG の不足
- D. SG がステートレスなので、インバウンドの許可が足りない

??? success "答えと解説"
    **正解: B**

    NACL はステートレスなので、戻り通信のポート 1024〜65535 を明示的に許可します。

    - A: 誤り。NACL はステートレス。
    - B: 正しい。
    - C: 誤り。NAT ゲートウェイに SG は付けられない。
    - D: 誤り。SG はステートフル。

    **スキル:** [VPC のセキュリティ部品](../domain1.md#t1-2-vpc-security) / **参照:** [ネットワーク ACL のルール](../../../services/networking.md#nacl-rules)、[NAT ゲートウェイ](../../../services/network-connectivity.md#nat-gateway)

### 問4 {#q4}

NAT ゲートウェイの説明として正しいものを選んでください。（2つ選択）

- A. インターネットから開始された接続は受けない
- B. プライベートサブネットに置くと、パブリック IP がなくても公開型として動く
- C. インターネットからインスタンスの管理ポートへ転送できる
- D. SG を付けて通信を制限できる
- E. プライベートサブネットのインスタンスから外への通信を通す

??? success "答えと解説"
    **正解: A, E**

    NAT ゲートウェイは外向きの通信だけを通し、外からの接続は受けません。

    - A: 正しい。
    - B: 誤り。パブリックの NAT ゲートウェイはパブリックサブネットに置く。
    - C: 誤り。ポートフォワードはできない。
    - D: 誤り。NAT ゲートウェイに SG は付けられない。
    - E: 正しい。

    **スキル:** [VPC のセキュリティ部品](../domain1.md#t1-2-vpc-security) / **参照:** [NAT ゲートウェイ](../../../services/network-connectivity.md#nat-gateway)

### 問5 {#q5}

SG と NACL の違いとして正しいものを選んでください。（2つ選択）

- A. SG は戻り通信を自動で許可する
- B. SG はサブネット単位、NACL は ENI 単位で適用される
- C. NACL は戻り通信の明示的な許可が必要である
- D. NACL は許可だけ、SG は許可と拒否を書ける
- E. SG はルールを番号の順に評価し、最初の一致で決まる

??? success "答えと解説"
    **正解: A, C**

    SG はステートフルで ENI 単位、NACL はステートレスでサブネット単位です。

    - A: 正しい。
    - B: 誤り。逆。
    - C: 正しい。
    - D: 誤り。逆。
    - E: 誤り。それは NACL の評価。

    **スキル:** [VPC のセキュリティ部品](../domain1.md#t1-2-vpc-security) / **参照:** [セキュリティグループとネットワーク ACL](../../../services/networking.md#security-groups-nacls)

### 問6 {#q6}

あるサブネットがパブリックであるかを決めるものはどれですか。

- A. サブネットの名前に public が含まれているか
- B. サブネットの CIDR が `10.0.0.0/24` であるか
- C. ルートテーブルにインターネットゲートウェイへの経路があるか
- D. NACL ですべての通信を許可しているか

??? success "答えと解説"
    **正解: C**

    `0.0.0.0/0` の経路がインターネットゲートウェイを指すサブネットがパブリックです。

    - A: 誤り。名前は関係しない。
    - B: 誤り。CIDR は関係しない。
    - C: 正しい。
    - D: 誤り。NACL だけでは決まらない。

    **スキル:** [ネットワークの分割](../domain1.md#t1-2-segmentation) / **参照:** [サブネットとルートテーブル](../../../services/networking.md#subnets-route-tables)

### 問7 {#q7}

3 層の Web アプリをネットワークで分けます。DB にインターネットへの経路を持たせない配置はどれですか。

- A. ALB、アプリ、DB をすべてパブリックサブネットに置き、SG で制限する
- B. DB をパブリックに置く
- C. ALB をパブリック、アプリをプライベート、DB を閉域に置く
- D. ALB とアプリをプライベート、DB を NAT ゲートウェイと同じサブネットに置く

??? success "答えと解説"
    **正解: C**

    各層を別のサブネットに分け、SG で「ALB からアプリ」「アプリから DB」の順にだけ許可します。

    - A: 誤り。DB がインターネットに経路を持つ。
    - B: 誤り。逆で、DB が公開側になる。
    - C: 正しい。
    - D: 誤り。インターネットからの入口がなく、DB も外への経路を持つ。

    **スキル:** [ネットワークの分割](../domain1.md#t1-2-segmentation) / **参照:** [サブネットとルートテーブル](../../../services/networking.md#subnets-route-tables)

### 問8 {#q8}

プライベートサブネットのインスタンスに管理の接続をします。インバウンドのポートを開けず、踏み台も置きたくありません。何を使いますか。

- A. Systems Manager の Session Manager
- B. パブリックサブネットの踏み台に 22 番を開け、SSH の鍵を配る
- C. インスタンスに Elastic IP を付けて管理者の IP だけ許可する
- D. NAT ゲートウェイでポートを転送する

??? success "答えと解説"
    **正解: A**

    Session Manager はインバウンドのポートも踏み台も要りません。操作の記録も残せます。

    - A: 正しい。
    - B: 誤り。踏み台を公開し、ポートも開ける。
    - C: 誤り。公開 IP を持ち、ポートも開ける。
    - D: 誤り。ポートフォワードはできない。

    **スキル:** [ネットワークの分割](../domain1.md#t1-2-segmentation) / **参照:** [Session Manager](../../../services/operations.md#session-manager)

### 問9 {#q9}

プライベートサブネットの EC2 が S3 に大量のデータを送っています。通信をインターネットに出さず、エンドポイントの追加料金もかけたくありません。何を作りますか。

- A. NAT ゲートウェイの増設
- B. S3 のゲートウェイエンドポイント
- C. S3 のインターフェイスエンドポイント
- D. S3 Transfer Acceleration

??? success "答えと解説"
    **正解: B**

    ゲートウェイエンドポイントはルートテーブルに経路を足すだけで、追加料金はありません。

    - A: 誤り。データ処理料金がかかり、インターネット側へ出る経路のまま。
    - B: 正しい。
    - C: 誤り。時間とデータ量の料金がかかる。
    - D: 誤り。エッジ経由の遠距離転送の高速化で、要件と違う。

    **スキル:** [サービスエンドポイント](../domain1.md#t1-2-endpoints) / **参照:** [VPC エンドポイントと PrivateLink](../../../services/networking.md#vpc-endpoints)

### 問10 {#q10}

オンプレミスから Direct Connect 経由で、S3 にプライベートに接続します。適切なものはどれですか。

- A. S3 の静的ウェブサイトのエンドポイントを VPC に関連付ける
- B. S3 のゲートウェイエンドポイントをルートテーブルに追加する
- C. NAT ゲートウェイで中継する
- D. S3 のインターフェイスエンドポイントを使う

??? success "答えと解説"
    **正解: D**

    インターフェイスエンドポイントはサブネットに ENI を作るので、オンプレミスから届きます。

    - A: 誤り。VPC に関連付ける仕組みはなく、HTTP の公開の機能。
    - B: 誤り。ゲートウェイエンドポイントはオンプレミスから使えない。
    - C: 誤り。プライベート接続の要件を満たさない。
    - D: 正しい。

    **スキル:** [サービスエンドポイント](../domain1.md#t1-2-endpoints) / **参照:** [エンドポイントの選び方と制約](../../../services/networking.md#endpoint-settings)

### 問11 {#q11}

バケットへのアクセスを、特定の VPC エンドポイントからだけに限定します。どう設定しますか。

- A. `aws:SourceVpce` が一致しないものを拒否するバケットポリシー
- B. S3 ブロックパブリックアクセスをオフにしてから NACL で許可する
- C. エンドポイントの SG に S3 のプレフィックスリストを追加するだけにする
- D. `aws:SecureTransport` が `false` のリクエストを Deny する

??? success "答えと解説"
    **正解: A**

    リソース側で `aws:SourceVpce` を条件にします。エンドポイントポリシーは、そのエンドポイントから何ができるかを絞るものです。

    - A: 正しい。
    - B: 誤り。公開設定を緩めるだけで、限定にならない。
    - C: 誤り。バケット側の制限がなく、他の経路を拒否できない。
    - D: 誤り。TLS の強制で、経路は限定しない。

    **スキル:** [サービスエンドポイント](../domain1.md#t1-2-endpoints) / **参照:** [エンドポイントポリシー](../../../services/networking.md#endpoint-policies)

### 問12 {#q12}

VPC エンドポイントの比較で正しいものを選んでください。（2つ選択）

- A. ゲートウェイはルートテーブルの経路で動く
- B. ゲートウェイは SG で制御し、インターフェイスは SG を付けられない
- C. インターフェイスはサブネットの ENI で動く
- D. インターフェイスは S3 と DynamoDB だけに対応する
- E. ゲートウェイは時間の料金、インターフェイスは追加料金なしである

??? success "答えと解説"
    **正解: A, C**

    仕組みの違いが、オンプレミスから使えるかと料金の違いにつながります。

    - A: 正しい。
    - B: 誤り。逆で、SG を使うのはインターフェイス側。
    - C: 正しい。
    - D: 誤り。対象は多くのサービス。S3 と DynamoDB に限るのはゲートウェイ。
    - E: 誤り。逆。

    **スキル:** [サービスエンドポイント](../domain1.md#t1-2-endpoints) / **参照:** [VPC エンドポイントと PrivateLink](../../../services/networking.md#vpc-endpoints)、[エンドポイントの選び方と制約](../../../services/networking.md#endpoint-settings)

### 問13 {#q13}

本社と VPC を暗号化された回線で今週中につなぎます。専用線の開通を待てません。何を選びますか。

- A. Direct Connect の専用接続
- B. VPC ピアリング
- C. Site-to-Site VPN
- D. Client VPN

??? success "答えと解説"
    **正解: C**

    IPsec の VPN はすぐに使えます。トンネルは 2 本あるので両方を設定します。

    - A: 誤り。開通に時間がかかり、既定では暗号化されない。
    - B: 誤り。VPC 同士の接続で、本社とは結べない。
    - C: 正しい。
    - D: 誤り。従業員の端末の接続に使う。

    **スキル:** [外部との接続](../domain1.md#t1-2-external) / **参照:** [Site-to-Site VPN](../../../services/network-connectivity.md#site-to-site-vpn)

### 問14 {#q14}

Direct Connect の通信を、ルーターから AWS のデバイスまでの区間で暗号化します。10 Gbps の専用接続を使っています。何を使いますか。

- A. NACL で暗号化された通信だけを許可する
- B. ACM の証明書を仮想インターフェイスに付ける
- C. Direct Connect を使うだけで既定で暗号化されるので、何も要らない
- D. MACsec を有効にする

??? success "答えと解説"
    **正解: D**

    MACsec は専用接続の 10、100、400 Gbps で使えるレイヤー 2 の暗号化です。

    - A: 誤り。NACL にその機能はない。
    - B: 誤り。接続の暗号化の仕組みではない。
    - C: 誤り。既定では暗号化されない。
    - D: 正しい。

    **スキル:** [外部との接続](../domain1.md#t1-2-external) / **参照:** [MACsec](../../../services/network-connectivity.md#dx-macsec)

### 問15 {#q15}

Direct Connect の専用線を使い、オンプレミスから VPC まで IPsec で暗号化しつつ、パブリック IP は使いたくありません。適切な構成はどれですか。

- A. VPC ピアリングを Direct Connect の VIF に関連付ける
- B. Transit Gateway とプライベート IP VPN
- C. パブリック VIF の上にインターネットの VPN を張る
- D. Client VPN を各サーバーに入れて、VIF を経由させる

??? success "答えと解説"
    **正解: B**

    プライベート IP VPN は Direct Connect の上で動き、Transit Gateway と組み合わせます。

    - A: 誤り。そのような関連付けはできない。
    - B: 正しい。
    - C: 誤り。パブリック IP を使う。
    - D: 誤り。端末向けで、拠点間の要件に合わない。

    **スキル:** [外部との接続](../domain1.md#t1-2-external) / **参照:** [プライベート IP VPN](../../../services/network-connectivity.md#vpn-private-ip)

### 問16 {#q16}

在宅の従業員 300 人が、各自の端末から VPC の内部アプリへ接続します。OpenVPN ベースのマネージドなサービスを使います。どれを選びますか。

- A. Direct Connect のホスト接続を自宅ごとに契約する
- B. AWS Client VPN のエンドポイント
- C. Global Accelerator
- D. Site-to-Site VPN を人数分作る

??? success "答えと解説"
    **正解: B**

    Client VPN は端末から VPC へ接続するマネージド VPN です。

    - A: 誤り。現実的でなく、端末向けではない。
    - B: 正しい。
    - C: 誤り。公開の高速化で、VPN の代わりにならない。
    - D: 誤り。拠点間の接続で、端末向けではない。

    **スキル:** [外部との接続](../domain1.md#t1-2-external) / **参照:** [Client VPN](../../../services/network-connectivity.md#client-vpn)
