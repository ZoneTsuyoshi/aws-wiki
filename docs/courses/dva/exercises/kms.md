# KMS の問題集

対象の解説: [AWS KMS](../../../services/kms.md)

### 問1 {#q1}

ある開発者は引数なしで `CreateKey` を呼びました。作成されるキーの説明として正しいものはどれですか。

- A. `RSA_2048` の非対称キーで、用途は署名と検証の両方を兼ねる
- B. HMAC キーで、用途はメッセージ認証
- C. `SYMMETRIC_DEFAULT` の対称キーで、用途は暗号化と復号
- D. マルチリージョンのプライマリキー

??? success "答えと解説"
    **正解: C**

    既定は `KeySpec=SYMMETRIC_DEFAULT`、`KeyUsage=ENCRYPT_DECRYPT`、`Origin=AWS_KMS` です。

    - A: 誤り。`KeySpec` の指定が必要で、RSA キーの用途は暗号化か署名のどちらか一方。
    - B: 誤り。HMAC は `KeySpec` と `KeyUsage` の指定が必要。
    - C: 正しい。
    - D: 誤り。`MultiRegion` の既定は `false`。

    **スキル:** C03 2.2.4 / **参照:** [キーの作成時の設定](../../../services/kms.md#key-creation-settings)

### 問2 {#q2}

AWS の認証情報を持たない取引先のシステムが、データを暗号化して送ってきます。復号は社内で行います。KMS キーの種類として最も適切なものはどれですか。

- A. `SYMMETRIC_DEFAULT` のカスタマー管理キー
- B. `RSA_4096` で `ENCRYPT_DECRYPT` のカスタマー管理キー
- C. `HMAC_256` のカスタマー管理キー
- D. `alias/aws/s3` の AWS 管理キーのポリシーを変更して相手に共有する

??? success "答えと解説"
    **正解: B**

    公開鍵を `GetPublicKey` で取得して渡せば、相手は KMS の外で暗号化できます。復号は KMS で行います。

    - A: 誤り。対称キーの鍵素材は KMS の外に出ない。相手が AWS を呼べないと使えない。
    - B: 正しい。
    - C: 誤り。HMAC は暗号化に使えない。
    - D: 誤り。AWS 管理キーのポリシーは変更できず、サービス経由でしか使えない。

    **スキル:** C03 2.2.4 / **参照:** [対称と非対称の違い](../../../services/kms.md#symmetric-vs-asymmetric)

### 問3 {#q3}

`RSA_2048` のキーで `RSAES_OAEP_SHA_256` を使い、`Encrypt` を呼びます。平文の上限はどれですか。

- A. 190 バイト
- B. 214 バイト
- C. 446 バイト
- D. 4,096 バイト

??? success "答えと解説"
    **正解: A**

    `RSA_2048` で `SHA_256` なら 190 バイト、`SHA_1` なら 214 バイトです。

    - A: 正しい。
    - B: 誤り。`RSAES_OAEP_SHA_1` の場合の値。
    - C: 誤り。`RSA_4096` と `SHA_256` の場合の値。
    - D: 誤り。対称キーの場合の値。

    **スキル:** C03 2.2.4 / **参照:** [API の詳細](../../../services/kms.md#api-details)

### 問4 {#q4}

アプリが 10 MB のファイルを暗号化する予定ですが、処理は数日後に別のワーカーが行います。今は暗号化済みのデータキーだけを保存したいと考えています。最も適切な API はどれですか。

- A. `Encrypt`
- B. `GenerateDataKey`
- C. `GenerateRandom`
- D. `GenerateDataKeyWithoutPlaintext`

??? success "答えと解説"
    **正解: D**

    平文のキーを返さないので、ワーカーが使う直前に `Decrypt` します。

    - A: 誤り。対称キーでも平文は 4,096 バイトまで。
    - B: 誤り。平文のキーも返るので、今は不要なものをメモリに持つことになる。
    - C: 誤り。ランダムなバイト列で、KMS キーで暗号化されない。
    - D: 正しい。

    **スキル:** C03 2.2.4 / **参照:** [API の詳細](../../../services/kms.md#api-details)

### 問5 {#q5}

`GenerateRandom` について正しいものはどれですか。

- A. 対称の KMS キーの指定が必須である
- B. `NumberOfBytes` は 1〜1,024 である
- C. 既定で 32 バイトを返す
- D. クロスアカウントで呼ぶにはキー ARN が必要である

??? success "答えと解説"
    **正解: B**

    `NumberOfBytes` は必須で既定値はありません。特定のキーを使わないので、クロスアカウントの考慮は不要です。

    - A: 誤り。KMS キーは指定しない。
    - B: 正しい。
    - C: 誤り。既定値はない。
    - D: 誤り。キーを使わない。

    **スキル:** C03 2.2.4 / **参照:** [API の詳細](../../../services/kms.md#api-details)

### 問6 {#q6}

カスタマー管理キーのキーポリシーから `arn:aws:iam::111122223333:root` の文を削除しました。同じアカウントのロールには IAM ポリシーで `kms:Decrypt` を許可しています。ロールが `Decrypt` を呼ぶとどうなりますか。

- A. IAM の許可があるので成功する
- B. `InvalidCiphertextException` になる
- C. キーが自動で無効化される
- D. `AccessDeniedException` になる

??? success "答えと解説"
    **正解: D**

    KMS では、キーポリシーの許可がなければ IAM ポリシーは効きません。ルートの文が IAM ポリシーでの委譲を有効にしています。

    - A: 誤り。S3 などと異なり、キーポリシーの許可が必須。
    - B: 誤り。これは暗号文やコンテキストの問題のときのエラー。
    - C: 誤り。ポリシーの変更でキーの状態は変わらない。
    - D: 正しい。

    **スキル:** C03 2.2.4 / **参照:** [既定のキーポリシー](../../../services/kms.md#default-key-policy-details)

### 問7 {#q7}

API で作成したキーと、コンソールで作成したキーの既定のキーポリシーの違いとして正しいものを選んでください。（2つ選択）

- A. API で作成すると、IAM を有効にする文だけが入る
- B. コンソールで作成すると、キー管理者とキー利用者の文も入る
- C. API で作成すると、作成者だけが使える文が入る
- D. コンソールで作成すると、ルートの文が削除される
- E. キー管理者は既定で `kms:Decrypt` を持つ

??? success "答えと解説"
    **正解: A, B**

    キー管理者はキーを管理できますが、暗号操作の権限は持ちません。

    - A: 正しい。
    - B: 正しい。
    - C: 誤り。作成者だけの文は作られない。
    - D: 誤り。コンソールでもこの文から始まる。
    - E: 誤り。暗号操作はキー利用者の権限。

    **スキル:** C03 2.2.4 / **参照:** [既定のキーポリシー](../../../services/kms.md#default-key-policy-details)

### 問8 {#q8}

カスタマー管理キーを、S3 経由でだけ使わせ、アプリからの直接の `Decrypt` は拒否したいと考えています。キーポリシーの条件として最も適切なものはどれですか。

- A. `kms:CallerAccount`
- B. `kms:ViaService`
- C. `kms:GrantIsForAWSResource`
- D. `aws:SourceIp`

??? success "答えと解説"
    **正解: B**

    `s3.ap-northeast-1.amazonaws.com` のようにサービスとリージョンを指定します。

    - A: 誤り。アカウントを絞るだけで、経路は絞れない。
    - B: 正しい。
    - C: 誤り。グラントの作成に関する条件。
    - D: 誤り。経路がサービスかどうかは判定できない。

    **スキル:** C03 2.2.4 / **参照:** [kms:ViaService](../../../services/kms.md#via-service)

### 問9 {#q9}

ワーカーのロールに一時的に復号の権限を渡します。作成直後から確実に使いたいので、キーポリシーの変更は避けたいと考えています。最も適切な方法はどれですか。

- A. グラントを作成し、`GrantToken` をリクエストに渡す
- B. グラントを作成し、5 分待ってから使う
- C. IAM ポリシーを付けて、そのあと `sts:AssumeRole` で別のセッションを作る
- D. キーの別名を変更する

??? success "答えと解説"
    **正解: A**

    グラントは結果整合性なので、すぐに使うならグラントトークンを渡します。

    - A: 正しい。
    - B: 誤り。反映は通常数秒以内だが、確実に使う方法ではない。
    - C: 誤り。キーポリシーの条件次第で効かず、要件に合わない。
    - D: 誤り。別名は権限と関係がない。

    **スキル:** C03 2.2.4 / **参照:** [グラントの設定](../../../services/kms.md#grant-settings)

### 問10 {#q10}

`CreateGrant` の `Operations` に指定できないものはどれですか。

- A. `Decrypt`
- B. `GenerateDataKey`
- C. `ScheduleKeyDeletion`
- D. `DescribeKey`

??? success "答えと解説"
    **正解: C**

    グラントで許可できるのはグラント操作だけです。それ以外は `ValidationError` になります。

    - A: 誤り。暗号操作は指定できる。
    - B: 誤り。指定できる。
    - C: 正しい。キーの削除は指定できない。
    - D: 誤り。指定できる。

    **スキル:** C03 2.2.4 / **参照:** [グラントの設定](../../../services/kms.md#grant-settings)

### 問11 {#q11}

クライアント側で暗号化したデータを、東京とオレゴンで再暗号化なしで復号できるようにしたいと考えています。最も適切なものはどれですか。

- A. 既存の単一リージョンのキーをマルチリージョンに変換する
- B. 両方のリージョンに同じ別名を持つ別のキーを作る
- C. AWS 管理キーを両方のリージョンで使う
- D. `MultiRegion=true` で作り、`ReplicateKey` で複製する

??? success "答えと解説"
    **正解: D**

    マルチリージョンキーは鍵素材とキー ID が同じなので、別のリージョンの暗号文を復号できます。

    - A: 誤り。既存のキーは変換できない。
    - B: 誤り。別名が同じでも鍵素材は別のもの。
    - C: 誤り。AWS 管理キーは直接使えず、鍵素材もリージョンごとに異なる。
    - D: 正しい。

    **スキル:** C03 2.2.1 / **参照:** [マルチリージョンキー](../../../services/kms.md#multi-region-keys)

### 問12 {#q12}

マルチリージョンキーの説明として正しいものを選んでください。（2つ選択）

- A. キーポリシーはキーごとに独立している
- B. レプリカのキー ID はプライマリと同じである
- C. レプリカごとに別の鍵素材を持つ
- D. カスタムキーストアに作るのが一般的である
- E. レプリカが残っていてもプライマリはすぐ削除される

??? success "答えと解説"
    **正解: A, B**

    鍵素材とキー ID は共通で、キーポリシー、グラント、別名は独立です。

    - A: 正しい。
    - B: 正しい。
    - C: 誤り。鍵素材は共通。
    - D: 誤り。カスタムキーストアには作れない。
    - E: 誤り。レプリカの削除後に待機期間が始まる。

    **スキル:** C03 2.2.1 / **参照:** [マルチリージョンキー](../../../services/kms.md#multi-region-keys)

### 問13 {#q13}

カスタマー管理キーの自動ローテーションを 30 日ごとにしたいと考えています。結果として正しいものはどれですか。

- A. 指定できない。範囲は 90〜2,560 日である
- B. 30 日で設定でき、既存の暗号文も再暗号化される
- C. 30 日で設定でき、キーの ARN が毎回変わる
- D. 指定できない。期間は 365 日で固定である

??? success "答えと解説"
    **正解: A**

    `RotationPeriodInDays` は 90〜2,560 日です。より短い周期が必要な場合に限り、オンデマンド（キーあたり 25 回）を併用できます。

    - A: 正しい。
    - B: 誤り。範囲外で、既存の暗号文も再暗号化しない。
    - C: 誤り。範囲外で、ARN も変わらない。
    - D: 誤り。365 日は既定値で固定ではない。

    **スキル:** C03 2.2.4 / **参照:** [ローテーションの設定](../../../services/kms.md#rotation-settings)

### 問14 {#q14}

本番のキーを誤って `ScheduleKeyDeletion` しました。今は待機期間中です。データを失わずに元に戻す手順として最も適切なものはどれですか。

- A. `EnableKey` だけを呼ぶ
- B. `CancelKeyDeletion` を呼び、その後 `EnableKey` を呼ぶ
- C. 待機期間中に `ReEncrypt` で別のキーへ全データを移してから諦める
- D. `RotateKeyOnDemand` を呼ぶ

??? success "答えと解説"
    **正解: B**

    取り消すとキーは `Disabled` の状態になるので、続けて有効にします。

    - A: 誤り。削除の予定は残る。
    - B: 正しい。
    - C: 誤り。削除待ちのキーは暗号操作に使えない。
    - D: 誤り。削除待ちのキーには使えない。

    **スキル:** C03 2.2.4 / **参照:** [キーの無効化と削除](../../../services/kms.md#disable-delete)

### 問15 {#q15}

データを暗号学的に使えなくする処理を、待機期間なしで実行したいと考えています。また、必要になったら元に戻せるようにしたいです。最も適切な方法はどれですか。

- A. `ScheduleKeyDeletion` の待機期間を 0 日に指定して、すぐに削除する
- B. `DisableKeyRotation` を呼ぶ
- C. インポートした鍵素材を `DeleteImportedKeyMaterial` で消す
- D. キーの別名を削除する

??? success "答えと解説"
    **正解: C**

    インポートした鍵素材はすぐに削除でき、再インポートすれば戻ります。

    - A: 誤り。待機期間は 7〜30 日。
    - B: 誤り。ローテーションを止めるだけ。
    - C: 正しい。その間のキーの状態は `PendingImport`。
    - D: 誤り。別名を消してもキー自体は使える。

    **スキル:** C03 2.2.4 / **参照:** [鍵素材のインポート](../../../services/kms.md#imported-key-material)

### 問16 {#q16}

インポートした鍵素材を持つ対称キーのローテーションとして正しいものはどれですか。

- C. 別名の切り替えだけが使える

### 問17 {#q17}

別のアカウントのキーを使うアプリが、`KeyId="alias/shared-key"` で呼ぶと `NotFoundException` になります。キーポリシーと IAM ポリシーは正しく設定されています。最も適切な修正はどれですか。

- C. キーの所有者のアカウントで Decrypt を呼ぶ

東京リージョンの SSE-KMS のバケットに大量のアップロードがあり、`ThrottlingException` が発生しています。バケットキーの効果として正しいものを選んでください。（2つ選択）

### 問19 {#q19}

AWS Encryption SDK のデータキーキャッシュを使います。しきい値の説明として正しいものはどれですか。

- A. 最大有効期間は必須で、0 より大きい値を指定する

KMS の操作を CloudTrail で監査するときの説明として正しいものはどれですか。
