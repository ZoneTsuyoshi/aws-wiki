# 証明書と WAF の問題集

対象の解説: [証明書と AWS WAF](../../../services/certificates.md)

### 問1 {#q1}

東京リージョンの ALB と、CloudFront の両方に同じドメインで ACM の公開証明書を使います。最も適切な構成はどれですか。

- A. 東京に 1 枚作り、両方で使う
- B. `us-east-1` に 1 枚作り、東京の ALB にコピーする
- C. 東京と `us-east-1` にそれぞれ 1 枚作る
- D. ALB にだけ付けて、CloudFront はオリジンの証明書を使う

??? success "答えと解説"
    **正解: C**

    ACM の証明書はリージョンのリソースで、コピーできません。CloudFront は `us-east-1` の証明書だけを使えます。

    - A: 誤り。CloudFront で選べない。
    - B: 誤り。リージョン間でコピーできない。
    - C: 正しい。DNS の CNAME を共有できるので、再検証の手間も少ない。
    - D: 誤り。ビューワーとの間に CloudFront の証明書が必要。

    **スキル:** C03 2.2.2 / **参照:** [リージョンのルール](../../../services/certificates.md#region-rules)

### 問2 {#q2}

DNS 検証の ACM の公開証明書を ALB に付けています。証明書が自動更新されなくなる操作はどれですか。

- A. Route 53 から ACM の CNAME レコードを削除する
- B. ALB のリスナールールを変更する
- C. 証明書にタグを追加する
- D. ALB のターゲットを追加する

??? success "答えと解説"
    **正解: A**

    CNAME が残っていれば自動で更新されます。

    - A: 正しい。統合サービスから外した場合も更新が止まる。
    - B: 誤り。更新の条件と関係がない。
    - C: 誤り。同上。
    - D: 誤り。同上。

    **スキル:** C03 2.2.2 / **参照:** [DNS 検証の注意点](../../../services/certificates.md#dns-validation-details)

### 問3 {#q3}

ACM の公開証明書の有効期間と更新について、現在の仕様として正しいものを選んでください。（2つ選択）

- A. 新しく発行される証明書の有効期間は 198 日である
- B. 198 日の証明書は期限の 45 日前から更新される
- C. 新しい証明書の有効期間は 395 日である
- D. メール検証の案内は WHOIS の連絡先に送られる
- E. インポートした証明書も ACM が更新する

??? success "答えと解説"
    **正解: A, B**

    以前の 395 日の証明書は更新で 198 日になります。古い教材には 13 か月と書かれているので、注意します。

    - A: 正しい。
    - B: 正しい。以前の 395 日のものは 60 日前。
    - C: 誤り。以前の仕様。
    - D: 誤り。WHOIS は現在は使わず、`admin@` などの 5 つの宛先に送る。
    - E: 誤り。自動更新されない。

    **スキル:** C03 2.2.2 / **参照:** [自動更新](../../../services/certificates.md#auto-renewal)

### 問4 {#q4}

他社の CA の証明書を ACM にインポートします。秘密鍵はパスフレーズで保護され、DER 形式です。最も適切な手順はどれですか。

- A. そのままインポートする
- B. 秘密鍵を KMS で暗号化してインポートする
- C. パスフレーズを `--passphrase` に指定してインポートする
- D. パスフレーズを解除して PEM に変換し、インポートする

??? success "答えと解説"
    **正解: D**

    すべて PEM で、秘密鍵は暗号化なしで 5 KB までです。

    - A: 誤り。DER はエラーになる。
    - B: 誤り。暗号化された秘密鍵はインポートできない。
    - C: 誤り。そのような方法はない。
    - D: 正しい。

    **スキル:** C03 2.2.2 / **参照:** [インポートの条件](../../../services/certificates.md#import-requirements)

### 問5 {#q5}

インポートした証明書の期限切れを 45 日前から毎日通知したいと考えています。最も運用負荷が低い方法はどれですか。

- A. 毎日 `DescribeCertificate` を呼ぶ Lambda を自作する
- B. EventBridge の `ACM Certificate Approaching Expiration` を SNS に送る
- C. ALB のアクセスログを確認する
- D. CloudTrail で `ImportCertificate` を検索する

??? success "答えと解説"
    **正解: B**

    このイベントはプライベートとインポートの証明書では 45 日前から毎日送られます。公開証明書は 30 日前からです。

    - A: 誤り。動くが、運用負荷が高い。
    - B: 正しい。
    - C: 誤り。証明書の期限はわからない。
    - D: 誤り。期限の通知にはならない。

    **スキル:** C03 2.2.2 / **参照:** [更新の監視](../../../services/certificates.md#renewal-monitoring)

### 問6 {#q6}

コンテナ間の通信に、7 日で切れる証明書を大量に発行し、失効の仕組みは持ちたくありません。AWS Private CA の設定として最も適切なものはどれですか。

- A. 短期証明書モードの CA を階層の最後に置く
- B. 汎用モードの CA で OCSP を有効にする
- C. 短期証明書モードのルート CA から下位 CA を複数作る
- D. ACM の公開証明書を使う

??? success "答えと解説"
    **正解: A**

    短期証明書モードは最大 7 日で、失効の代わりになる場合があります。階層の最後に置き、料金も低くなります。

    - A: 正しい。
    - B: 誤り。失効の仕組みを持たないという要件に反する。
    - C: 誤り。短期証明書モードは階層の最後に置く。
    - D: 誤り。社内の相互通信で公開証明書を大量に発行する用途ではなく、期間も選べない。

    **スキル:** C03 2.2.2 / **参照:** [Private CA の設定の詳細](../../../services/certificates.md#private-ca-settings)

### 問7 {#q7}

ウェブ ACL の関連付けの説明として正しいものを選んでください。（2つ選択）

- A. 1 つの ALB に 2 つのウェブ ACL を付けられる
- B. 1 つのウェブ ACL を複数の ALB に付けられる
- C. CloudFront に付けたウェブ ACL は ALB にも付けられる
- D. CloudFront 用のウェブ ACL は `us-east-1` に作る
- E. NLB にウェブ ACL を付けられる

??? success "答えと解説"
    **正解: B, D**

    リソースとウェブ ACL は 1 つのウェブ ACL に対して複数のリソースの関係です。

    - A: 誤り。リソースごとに 1 つ。
    - B: 正しい。
    - C: 誤り。CloudFront に付けたものは他の種類に付けられない。
    - D: 正しい。
    - E: 誤り。NLB は対象外。

    **スキル:** C03 2.1.2 / **参照:** [スコープと関連付け](../../../services/certificates.md#waf-scope)

### 問8 {#q8}

ALB の WAF で本文の SQL インジェクションを検査しています。攻撃文字列を本文の 10 KB より後ろに置いたリクエストが検査をすり抜ける可能性があります。正しい説明はどれですか。

- A. ALB の検査の上限は 8 KB で固定なので、サイズの大きいリクエストを別に制御する
- B. ALB の検査の上限を 64 KB に引き上げる
- C. WCU を 5,000 以上に増やす
- D. レートベースルールの `Limit` を下げる

??? success "答えと解説"
    **正解: A**

    ALB と AppSync は 8 KB で固定です。CloudFront や API Gateway などは既定 16 KB で、最大 64 KB まで増やせます。

    - A: 正しい。サイズ制約のルールを併用する。
    - B: 誤り。ALB では変更できない。
    - C: 誤り。WCU の上限は 5,000 で、検査の範囲とは関係がない。
    - D: 誤り。回数を制限するだけで、中身は検査しない。

    **スキル:** C03 2.1.2 / **参照:** [容量と本文の検査](../../../services/certificates.md#waf-capacity-body)

### 問9 {#q9}

REST クライアント（ブラウザではない）からも呼ばれる API に、WAF の CAPTCHA アクションを付けたところ、クライアントが HTTP 405 を受け取るようになりました。最も適切な説明はどれですか。

- A. API Gateway のスロットリングが発生した
- B. WAF が内部エラーを返している
- C. トークンがないので WAF がパズルを返している
- D. `FORWARDED_IP` の設定が足りない

??? success "答えと解説"
    **正解: C**

    CAPTCHA はトークンが無効なら HTTP 405 でパズルを返します。Challenge は HTTP 202 です。いずれもブラウザが前提です。

    - A: 誤り。スロットリングは HTTP 429。
    - B: 誤り。アクションどおりの応答である。
    - C: 正しい。
    - D: 誤り。送信元の取り方の設定で、この応答とは関係がない。

    **スキル:** C03 2.1.2 / **参照:** [ルールのアクションの詳細](../../../services/certificates.md#waf-actions-details)

### 問10 {#q10}

ログイン API に、IP ごとに 1 分間 100 回の制限を付けます。レートベースルールの設定として最も適切なものはどれですか。

- A. `Limit=100`, `EvaluationWindowSec=60`, `AggregateKeyType=IP`, スコープダウンで `/login` に限定
- B. `Limit=100`, `EvaluationWindowSec=300`, `AggregateKeyType=CONSTANT`, スコープダウンなし
- C. `Limit=5`, `EvaluationWindowSec=60`, `AggregateKeyType=IP`, スコープダウンで `/login` に限定
- D. `Limit=100`, `EvaluationWindowSec=30`, `AggregateKeyType=IP`, スコープダウンで `/login` に限定

??? success "答えと解説"
    **正解: A**

    ウィンドウは 60、120、300、600 秒で、`Limit` の最小は 10 です。

    - A: 正しい。
    - B: 誤り。5 分のウィンドウで、`CONSTANT` はスコープダウンが必須。
    - C: 誤り。`Limit` の最小は 10。
    - D: 誤り。30 秒は選べない。

    **スキル:** C03 2.1.2 / **参照:** [レートベースルールの詳細](../../../services/certificates.md#rate-based-details)

### 問11 {#q11}

CloudFront の背後の ALB に WAF を付けました。レートベースルールが、全利用者をまとめて制限してしまいます。最も適切な修正はどれですか。

- A. レートの `Limit` を 2,000 倍にする
- B. 集約キーを `FORWARDED_IP` にし、`X-Forwarded-For` を指定する
- C. ALB の代わりに NLB にウェブ ACL を付ける
- D. ウィンドウを 600 秒にする

??? success "答えと解説"
    **正解: B**

    ALB からは送信元が CloudFront に見えます。転送された IP を使うか、CloudFront に WAF を付けます。

    - A: 誤り。IP ごとの制限にならない。
    - B: 正しい。
    - C: 誤り。NLB には付けられない。
    - D: 誤り。ウィンドウを変えても送信元の問題は解決しない。

    **スキル:** C03 2.1.2 / **参照:** [レートベースルール](../../../services/certificates.md#rate-based-rules)

### 問12 {#q12}

WAF のログを S3 に送ろうとしましたが、バケットが送信先の選択肢に出ません。バケットは `app-logs` という名前です。最も適切な修正はどれですか。

- A. `aws-waf-logs-` で始まる名前のバケットを使う
- B. S3 のバージョニングを有効にする
- C. ウェブ ACL を `us-east-1` に作り直す
- D. `SampledRequestsEnabled` を `false` にする

??? success "答えと解説"
    **正解: A**

    S3、CloudWatch Logs、Firehose のいずれも、名前は `aws-waf-logs-` で始める必要があります。

    - A: 正しい。
    - B: 誤り。名前の条件とは関係がない。
    - C: 誤り。リソースのスコープの話で、名前の問題ではない。
    - D: 誤り。サンプルの設定で、ログの送信先とは別。

    **スキル:** C03 2.1.2 / **参照:** [ログ](../../../services/certificates.md#waf-logging)
