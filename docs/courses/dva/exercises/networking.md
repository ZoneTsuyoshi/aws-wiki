# ネットワークの問題集

対象の解説: [ネットワーク（VPC / Route 53 / ELB / CloudFront）](../../../services/networking.md)

### 問1 {#q1}

ある開発者は、ALB の後ろの EC2 のサブネットに自作のネットワーク ACL を関連付けました。受信で TCP 8080 を ALB のサブネットから許可し、送信も TCP 8080 を許可しました。セキュリティグループは正しく設定されていますが、ALB は 504 を返します。最も適切な修正はどれですか。

- A. EC2 のセキュリティグループの送信ルールに 8080 を追加する
- B. ALB のアイドルタイムアウトを 300 秒に伸ばす
- C. NACL の送信でエフェメラルポート 1024-65535 を許可する
- D. ターゲットグループの `Matcher` を `200-499` に変更する

??? success "答えと解説"
    **正解: C**

    ネットワーク ACL はステートレスなので、戻り通信も許可が要ります。自作の NACL は最後の `*` で全拒否です。ELB からの要求は 1024-65535 のポートを使うので、ターゲットからの応答をそのポート宛てに許可します。

    - A: セキュリティグループはステートフルで、戻り通信は自動で許可されます。
    - B: 応答がネットワークで止まっているので、待ち時間を伸ばしても解決しません。
    - C: 正しい修正です。
    - D: ヘルスチェックの成功コードの設定で、通信の遮断には関係ありません。

    **スキル:** C03 4.1.1 / **参照:** [ネットワーク ACL のルール](../../../services/networking.md#nacl-rules)

### 問2 {#q2}

NACL に `100 ALLOW 0.0.0.0/0 TCP 443` があります。攻撃元の `203.0.113.5` を遮断するため、`200 DENY 203.0.113.5/32 TCP 443` を追加しましたが、通信は止まりません。原因として最も適切なものはどれですか。

- A. NACL では `/32` の範囲を指定できない
- B. 小さい番号のルールが先に一致して適用されている
- C. NACL の変更の反映に 24 時間かかる
- D. 拒否はセキュリティグループで行う必要がある

??? success "答えと解説"
    **正解: B**

    NACL は番号の小さい順に評価し、最初の一致で決まります。100 の許可が先に一致するので、200 は評価されません。拒否を 100 より小さい番号にします。

    - A: `/32` は指定できます。
    - B: 正しい説明です。
    - C: 変更はサブネットへ自動で反映されます。
    - D: セキュリティグループには拒否のルールがありません。

    **スキル:** C03 4.1.1 / **参照:** [ネットワーク ACL のルール](../../../services/networking.md#nacl-rules)

### 問3 {#q3}

プライベートサブネットのアプリから Secrets Manager へ、インターフェイスエンドポイント経由で接続したいと考えています。エンドポイントを作成し、プライベート DNS を有効にしようとしましたが、失敗します。確認すべき VPC の属性の組み合わせはどれですか。

- A. `enableDnsSupport` と `enableDnsHostnames` の両方が `true`
- B. `enableDnsSupport` が `true` で `enableDnsHostnames` が `false`
- C. `enableDnsSupport` が `false` で `enableDnsHostnames` が `true`
- D. どちらも `false` で、DHCP オプションセットに独自の DNS を設定

??? success "答えと解説"
    **正解: A**

    インターフェイスエンドポイントのプライベート DNS には、両方の属性を `true` にする必要があります。デフォルト VPC 以外では `enableDnsHostnames` の既定は `false` です。

    - A: 正しい設定です。
    - B: `enableDnsHostnames` が足りません。
    - C: `enableDnsSupport` が足りません。
    - D: Amazon 提供の DNS を使わず、プライベート DNS の前提を満たしません。

    **スキル:** C03 2.3.2 / **参照:** [VPC の DNS 属性](../../../services/networking.md#vpc-dns-attributes)

### 問4 {#q4}

VPC エンドポイントについて正しい説明はどれですか。（2つ選択）

- A. ゲートウェイエンドポイントは VPN の先のオンプレミスからも使える
- B. エンドポイントポリシーは IAM の権限に追加の許可を与える
- C. 既定のエンドポイントポリシーはフルアクセスである
- D. S3 と DynamoDB はゲートウェイとインターフェイスの両方に対応する
- E. インターフェイスエンドポイントにはセキュリティグループを付けられない

??? success "答えと解説"
    **正解: C, D**

    エンドポイントポリシーの既定はフルアクセスです。S3 と DynamoDB は両方の種類に対応します。

    - A: ゲートウェイエンドポイントの接続は VPC の外へ延長できません。
    - B: ポリシーは範囲を絞るもので、許可を与えるものではありません。
    - C: 正しい説明です。
    - D: 正しい説明です。
    - E: セキュリティグループを関連付けます。既定では VPC のデフォルト SG が付きます。

    **スキル:** C03 2.3.2 / **参照:** [エンドポイントの選び方と制約](../../../services/networking.md#endpoint-settings)

### 問5 {#q5}

Lambda 関数を VPC のパブリックサブネットに接続しましたが、外部 API の呼び出しがタイムアウトします。セキュリティグループの送信は全許可です。最も適切な対応はどれですか。

- A. 関数をパブリックサブネットのまま Elastic IP を割り当てる
- B. 関数のメモリを増やしてタイムアウトを伸ばす
- C. 関数のセキュリティグループの受信に 443 を追加する
- D. プライベートサブネットに接続し、NAT ゲートウェイ経由にする

??? success "答えと解説"
    **正解: D**

    VPC に接続した関数の ENI にはパブリック IP が付かないので、パブリックサブネットでもインターネットへ出られません。プライベートサブネットに接続し、NAT ゲートウェイへのルートを持たせます。

    - A: 関数の VPC 設定はサブネット、セキュリティグループ、IPv6 の許可だけで、Elastic IP を割り当てる項目はありません。
    - B: 経路がない問題は、リソースを増やしても解決しません。
    - C: 戻り通信はステートフルに許可されるので、受信ルールは関係ありません。
    - D: 正しい対応です。

    **スキル:** C03 1.2.1 / **参照:** [Lambda の VPC 接続](../../../services/networking.md#lambda-vpc)

### 問6 {#q6}

`example.com` と `www.example.com` を、ALB へ向けます。ALB の IP は変わることがあります。最も適切な設定はどれですか。

- A. 両方とも CNAME にして TTL を 60 秒にする
- B. 両方とも ALB の IP を書いた A レコードにする
- C. 両方ともエイリアス A レコードにする
- D. `example.com` を CNAME、`www` を A レコードにする

??? success "答えと解説"
    **正解: C**

    エイリアスはゾーンの頂点に作成でき、ALB の IP の変化にも自動で追従します。AWS リソースへのクエリは無料です。

    - A: 頂点の `example.com` に CNAME は作れません。
    - B: IP が変わると繋がらなくなります。
    - C: 正しい設定です。
    - D: 頂点の CNAME は作れず、`www` の A も IP の変化に追従しません。

    **スキル:** C03 3.1.5 / **参照:** [TTL とエイリアスの違い](../../../services/networking.md#route53-ttl)

### 問7 {#q7}

Route 53 のヘルスチェックについて正しい説明はどれですか。（2つ選択）

- A. プライベートサブネットの IP を直接チェックできる
- B. 既定の間隔は 30 秒で、10 秒の Fast は追加料金がかかる
- C. 文字列の一致は応答の先頭 5,120 バイトが対象である
- D. HTTP のチェックは `4xx` を正常として扱う
- E. 全チェッカーの 100% が正常と報告しないと異常になる

??? success "答えと解説"
    **正解: B, C**

    間隔の既定は 30 秒で、Fast は 10 秒です。文字列の一致は応答本文の先頭 5,120 バイトで探します。

    - A: チェッカーはインターネット上にあるので届きません。CloudWatch アラームのヘルスチェックを使います。
    - B: 正しい説明です。
    - C: 正しい説明です。
    - D: 正常は `2xx` と `3xx` です。
    - E: 18% を超えるチェッカーが正常と報告すれば正常です。

    **スキル:** C03 4.2.5 / **参照:** [Route 53 ヘルスチェック](../../../services/networking.md#route53-health-checks)

### 問8 {#q8}

国別に別の ALB へ振り分けるため、Route 53 で日本とドイツの位置情報レコードだけを作りました。ほかの国の利用者から名前解決できないとの報告があります。最も適切な対応はどれですか。

- A. 既定のロケーションのレコードを追加する
- B. レイテンシールーティングへのフェイルオーバーを設定する
- C. 両方のレコードの TTL を短くする
- D. 地理的近接性の `Bias` を 99 にする

??? success "答えと解説"
    **正解: A**

    位置情報ルーティングでは、一致するレコードがなく既定のレコードもないと、Route 53 は「no answer」を返します。既定のレコードを追加します。IP を特定できない問い合わせにも対応できます。

    - A: 正しい対応です。
    - B: 位置情報に一致しない問い合わせを救う仕組みではありません。
    - C: TTL はキャッシュの長さで、応答の有無を変えません。
    - D: `Bias` は地理的近接性の設定で、位置情報のレコードにはありません。

    **スキル:** C03 4.1.1 / **参照:** [ルーティングポリシーの設定](../../../services/networking.md#routing-settings)

### 問9 {#q9}

ALB のターゲットグループは既定の設定です。ターゲットが完全に停止してから、そのターゲットへのリクエストが止まるまでのおおよその時間と、修復後に通信が戻るまでのおおよその時間はどれですか。

- A. 10 秒と 30 秒
- B. 30 秒と 60 秒
- C. 60 秒と 150 秒
- D. 150 秒と 60 秒

??? success "答えと解説"
    **正解: C**

    既定は間隔 30 秒、`UnhealthyThresholdCount` 2、`HealthyThresholdCount` 5 です。異常と判定されるまで約 `30 × 2 = 60` 秒、正常に戻るまで約 `30 × 5 = 150` 秒です。

    - A: 既定の間隔より短く、計算が合いません。
    - B: 正常に戻るまでの回数が少なすぎます。
    - C: 正しい計算です。
    - D: 異常と正常のしきい値が逆です。

    **スキル:** C03 4.2.5 / **参照:** [ヘルスチェックの計算](../../../services/networking.md#health-check-calc)

### 問10 {#q10}

処理に最長 90 秒かかる API を ALB の後ろで運用しています。登録解除の待ちは 30 秒、アイドルタイムアウトは既定の 60 秒です。デプロイのたびに処理中の接続が切れ、さらに通常時も一部のリクエストが 504 になります。調整すべき設定の組み合わせはどれですか。（2つ選択）

- A. `deregistration_delay.timeout_seconds` を 120 秒にする
- B. `idle_timeout.timeout_seconds` を 120 秒にする
- C. `slow_start.duration_seconds` を 120 秒にする
- D. `HealthCheckTimeoutSeconds` を 120 秒にする
- E. `stickiness.lb_cookie.duration_seconds` を 120 秒にする

??? success "答えと解説"
    **正解: A, B**

    登録解除の待ちは、最長の処理時間以上にします。アイドルタイムアウトも、90 秒の無応答で 504 にならないように、それより長くします。

    - A: デプロイ時の切断を防ぎます。
    - B: 通常時の 504 を防ぎます。
    - C: 新しいターゲットへの配分を緩やかにする設定で、切断や 504 の原因ではありません。
    - D: ヘルスチェックの待ち時間で、API の応答待ちには関係ありません。
    - E: セッションの固定の期間で、タイムアウトには関係ありません。

    **スキル:** C03 4.1.1 / **参照:** [アイドルタイムアウトとキープアライブ](../../../services/networking.md#alb-idle-timeout)

### 問11 {#q11}

ALB のログに断続的な 502 があり、`HTTPCode_ELB_502_Count` が増えています。ターゲットは Nginx で、`keepalive_timeout` は 30 秒、ALB のアイドルタイムアウトは 60 秒です。最も適切な対応はどれですか。

- A. ALB のアイドルタイムアウトを 15 秒に下げる
- B. `keepalive_timeout` を ALB のアイドルタイムアウトより長くする
- C. ターゲットグループのプロトコルバージョンを HTTP/2 にする
- D. ヘルスチェックの間隔を 5 秒にする

??? success "答えと解説"
    **正解: B**

    ターゲットが先に接続を閉じると、ALB がその接続に要求を送って RST や FIN を受け、502 になります。ターゲットのキープアライブを ALB より長くするのが公式の確認項目です。

    - A: 長時間の応答が切れるようになり、アプリの要件を損ないます。
    - B: 正しい対応です。
    - C: プロトコルの不一致は別の症状（464 など）です。
    - D: ヘルスチェックの頻度は、この接続の閉じ方を変えません。

    **スキル:** C03 4.1.1 / **参照:** [ALB のエラーの原因一覧](../../../services/networking.md#alb-error-detail)

### 問12 {#q12}

ターゲットがすべて `unhealthy` のターゲットグループへ、ALB がリクエストを転送しています。動作の説明として最も適切なものはどれですか。

- A. ALB は 503 を返し、ターゲットへは転送しない
- B. ALB は 504 を返し、ターゲットへは転送しない
- C. ALB はフェイルオープンし、すべてのターゲットへ転送する
- D. ALB は別のターゲットグループへ自動で転送する

??? success "答えと解説"
    **正解: C**

    登録済みのターゲットがすべて異常なら、ALB は状態を無視して全ターゲットへ転送します。503 になるのは、登録済みのターゲットがない場合や、すべて `unused` の場合です。

    - A: この問題の状況では 503 になりません。
    - B: 504 は応答がないときのエラーで、この動作の説明ではありません。
    - C: 正しい説明です。
    - D: 自動で別のターゲットグループへは切り替わりません。

    **スキル:** C03 4.2.5 / **参照:** [ヘルスチェック](../../../services/networking.md#alb-health-checks)

### 問13 {#q13}

キャッシュポリシーの TTL は Minimum 60、Default 3600、Maximum 86400 です。オリジンが `Cache-Control: no-cache` を返すとき、CloudFront のキャッシュの動作はどれですか。

- A. キャッシュしない
- B. 60 秒キャッシュする
- C. 3,600 秒キャッシュする
- D. 86,400 秒キャッシュする

??? success "答えと解説"
    **正解: B**

    Minimum TTL が 0 より大きいと、`no-cache`、`no-store`、`private` があっても、CloudFront はその値の間キャッシュします。オリジンの指示を尊重するには Minimum TTL を 0 にします。

    - A: Minimum TTL が 0 なら、この動作になります。
    - B: 正しい動作です。
    - C: Default TTL は、オリジンが有効期限を示さないときの値です。
    - D: Maximum TTL は上限で、ここでは使われません。

    **スキル:** C03 4.3.4 / **参照:** [キャッシュポリシーの項目と TTL の計算](../../../services/networking.md#ttl-worked)

### 問14 {#q14}

CloudFront の Lambda@Edge の設定について、正しい説明はどれですか。

- A. `$LATEST` か、エイリアスの ARN を関連付ける
- B. 環境変数で接続先を切り替えられる
- C. 関数は任意のリージョンで作成できる
- D. 番号付きバージョンの ARN を関連付ける

??? success "答えと解説"
    **正解: D**

    Lambda@Edge には番号付きのバージョンを指定し、`$LATEST` とエイリアスは使えません。関数は `us-east-1` で作成します。環境変数や VPC 接続は使えません。

    - A: どちらも使えません。
    - B: 予約済みを除く環境変数は使えません。
    - C: `us-east-1` で作成します。
    - D: 正しい説明です。

    **スキル:** C03 4.3.4 / **参照:** [エッジ関数の制限](../../../services/networking.md#edge-function-limits)

### 問15 {#q15}

オリジングループでオリジンフェイルオーバーを設定し、条件に 500、502、503、504 を選びました。障害試験では `GET` は切り替わりますが、注文を送信する `POST` はエラーのままです。最も適切な説明はどれですか。

- A. 400 と 404 も条件に追加する必要がある
- B. 接続タイムアウトを 1 秒にする必要がある
- C. フェイルオーバーは `GET`、`HEAD`、`OPTIONS` のみが対象である
- D. セカンダリのオリジンで書き込みの権限が不足している

??? success "答えと解説"
    **正解: C**

    CloudFront がセカンダリへ切り替えるのは、ビューワーのメソッドが `GET`、`HEAD`、`OPTIONS` のときだけです。書き込みの可用性は別の仕組みで確保します。

    - A: 条件のコードを増やしても、`POST` は切り替わりません。
    - B: 待ち時間を短くしても対象のメソッドは変わりません。
    - C: 正しい説明です。
    - D: セカンダリへ要求自体が送られていません。

    **スキル:** C03 1.1.3 / **参照:** [オリジンフェイルオーバー](../../../services/networking.md#origin-failover)
