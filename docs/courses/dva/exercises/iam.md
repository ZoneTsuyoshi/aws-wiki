# IAM と STS の問題集

対象の解説: [IAM と STS](../../../services/iam.md)

### 問1 {#q1}

ある開発者は、S3 バケット `reports` の一覧を取得するアプリのロールに、次の文だけを付けました。`"Action": ["s3:GetObject", "s3:ListBucket"], "Resource": "arn:aws:s3:::reports/*"`。オブジェクトは取得できますが、一覧の取得は `AccessDenied` になります。最も適切な修正はどれですか。

- A. `Resource` に `arn:aws:s3:::reports` を追加する
- B. `Action` を `s3:*` に変更する
- C. バケットポリシーで匿名アクセスを許可する
- D. `Effect` を `NotAction` に書き換える

??? success "答えと解説"
    **正解: A**

    `s3:ListBucket` の対象はバケット自体で、`s3:GetObject` の対象はオブジェクトです。`reports/*` はオブジェクトにしか一致しないので、バケットの ARN を足します。

    - A: 正しい。`ListBucket` が要求するリソースの ARN を足している。
    - B: 誤り。操作を広げても `Resource` が一致しないので拒否されたまま。
    - C: 誤り。不要に公開するうえ、最小権限に反する。
    - D: 誤り。`Effect` の値は `Allow` か `Deny` で、`NotAction` は別の要素。

    **スキル:** C03 2.1.6 / **参照:** [Resource と NotResource](../../../services/iam.md#notresource)

### 問2 {#q2}

ポリシーに `{"Effect": "Allow", "NotAction": "iam:*", "Resource": "*"}` と書かれています。このポリシーの結果として最も適切なものはどれですか。

- A. IAM の操作だけが明示的に拒否され、他は何も許可されない
- B. IAM の操作だけが許可される
- C. IAM 以外のすべての操作が許可される
- D. 同じ文に `Action` がないので、作成時にエラーになる

??? success "答えと解説"
    **正解: C**

    `NotAction` は指定した操作以外に一致します。`Allow` と組み合わせると、IAM 以外の全サービスの全操作を許可します。

    - A: 誤り。`NotAction` は拒否を意味しない。IAM の操作は暗黙の拒否のまま。
    - B: 誤り。逆の意味。
    - C: 正しい。将来のサービスも含むので、広く許可しやすい書き方である。
    - D: 誤り。`Action` と `NotAction` はどちらか一方を書く。

    **スキル:** C03 2.1.6 / **参照:** [NotAction](../../../services/iam.md#notaction)

### 問3 {#q3}

条件 `{"StringLikeIfExists": {"ec2:InstanceType": ["t3.*"]}}` を持つ `Allow` の文があります。`ec2:InstanceType` キーがリクエストに存在しない場合の動作として正しいものはどれですか。

- A. 条件を満たさず、この文は適用されない
- B. 条件を満たしたとみなされ、他の要素が一致すれば文が適用される
- C. 明示的な拒否として扱われる
- D. `Null` 演算子に自動で置き換えて評価される

??? success "答えと解説"
    **正解: B**

    `...IfExists` は、キーがあれば通常どおり評価し、なければ条件を満たしたとみなします。

    - A: 誤り。これは `IfExists` のない `StringLike` の動作。
    - B: 正しい。キーを持たないリソースへの操作も通せる。
    - C: 誤り。条件の不一致は明示的な拒否ではない。
    - D: 誤り。`Null` は別の演算子で、自動で置き換えられない。`IfExists` は `Null` には付けられない。

    **スキル:** C03 2.1.2 / **参照:** [条件演算子](../../../services/iam.md#condition-operators)

### 問4 {#q4}

`Allow` の文に `{"ForAllValues:StringEquals": {"aws:TagKeys": ["env", "team"]}}` を付けました。ところが、タグを 1 つも付けないリクエストも許可されました。原因として最も適切なものはどれですか。

- A. `aws:TagKeys` は単一値のキーなので、修飾子が無視されている
- B. `StringEquals` が大文字と小文字を区別しないため
- C. キーが存在しないとき `ForAllValues` は真を返すため
- D. 条件の評価は `Deny` の文でしか行われないため

??? success "答えと解説"
    **正解: C**

    `ForAllValues` は、キーがない場合や値が空の場合にも真を返します。タグを必須にするなら、`Null` などでキーの存在も確認します。

    - A: 誤り。`aws:TagKeys` は複数の値を持つキーである。
    - B: 誤り。`StringEquals` は大文字と小文字を区別する。
    - C: 正しい。`Allow` と組み合わせるときの落とし穴である。
    - D: 誤り。`Allow` の条件も評価される。

    **スキル:** C03 2.1.2 / **参照:** [条件演算子](../../../services/iam.md#condition-operators)

### 問5 {#q5}

開発チームはポリシーの `Resource` を `arn:aws:s3:::data/${aws:PrincipalTag/team}/*` と書きました。しかし、どのロールでも `AccessDenied` になります。ポリシーの先頭には `"Version": "2008-10-17"` があります。最も適切な対応はどれですか。

- A. `Sid` をロールごとに付ける
- B. `Version` を `2012-10-17` に変更する
- C. `${}` を `$()` に書き換える
- D. `aws:PrincipalTag` を `aws:username` に変更する

??? success "答えと解説"
    **正解: B**

    ポリシー変数は `Version` が `2012-10-17` のときだけ使えます。古いバージョンでは、ただの文字列として扱われ、一致しません。

    - A: 誤り。`Sid` は評価に影響しない。
    - B: 正しい。変数を置き換えられるようになる。
    - C: 誤り。変数の書式は `${...}` である。
    - D: 誤り。`aws:username` はロールでは値が入らない。

    **スキル:** C03 2.1.6 / **参照:** [ポリシー変数](../../../services/iam.md#policy-variables)

### 問6 {#q6}

3 つの主体だけで共有する権限を、主体の削除と一緒に消えず、バージョン管理してロールバックできるようにしたいと考えています。最も適切なものはどれですか。

- A. 各主体のインラインポリシー
- B. カスタマー管理ポリシー
- C. セッションポリシー
- D. 権限境界

??? success "答えと解説"
    **正解: B**

    カスタマー管理ポリシーは複数の主体に付けられ、独立して残り、最大 5 つのバージョンを保存できます。

    - A: 誤り。主体と 1 対 1 で、主体の削除と一緒に消え、バージョン管理もない。
    - B: 正しい。要件をすべて満たす。
    - C: 誤り。セッションごとに渡すもので、永続的に付与するものではない。
    - D: 誤り。上限を決めるだけで、権限を与えない。

    **スキル:** C03 2.1.6 / **参照:** [管理ポリシーとインラインポリシー](../../../services/iam.md#managed-vs-inline)

### 問7 {#q7}

ロールの `MaxSessionDuration` を 8 時間にしました。アプリは `AssumeRole` で `DurationSeconds` を指定していません。このセッションの有効期間はどれですか。

- A. 15 分
- B. 1 時間
- C. 8 時間
- D. 12 時間

??? success "答えと解説"
    **正解: B**

    `DurationSeconds` を省略すると、最大セッション時間に関係なく 1 時間です。`MaxSessionDuration` は要求できる上限を決めるだけです。

    - A: 誤り。15 分は指定できる最短の時間。
    - B: 正しい。既定値は 1 時間。
    - C: 誤り。8 時間にするには `DurationSeconds=28800` を指定する。
    - D: 誤り。12 時間は `MaxSessionDuration` の上限。

    **スキル:** C03 2.1.7 / **参照:** [最大セッション時間](../../../services/iam.md#max-session-duration)

### 問8 {#q8}

Lambda の実行ロール A が、別のロール B を `AssumeRole` します。ロール B の `MaxSessionDuration` は 4 時間で、アプリは `DurationSeconds=7200` を指定しました。結果として正しいものはどれですか。

- A. 2 時間のセッションができる
- B. 4 時間のセッションができる
- C. 1 時間に切り詰めて成功する
- D. リクエストが失敗する

??? success "答えと解説"
    **正解: D**

    ロールから別のロールを引き受けるロールチェーンでは、セッションは最大 1 時間です。これより長い値を指定すると失敗します。

    - A: 誤り。`MaxSessionDuration` の範囲内でも、チェーンでは効かない。
    - B: 誤り。`DurationSeconds` の指定より長くなることはない。
    - C: 誤り。切り詰めずに失敗する。
    - D: 正しい。3600 以下を指定するか、チェーンを避ける。

    **スキル:** C03 2.1.7 / **参照:** [最大セッション時間](../../../services/iam.md#max-session-duration)

### 問9 {#q9}

STS の次の API のうち、セッションポリシーを渡せないものはどれですか。

- A. `AssumeRole`
- B. `AssumeRoleWithWebIdentity`
- C. `GetFederationToken`
- D. `GetSessionToken`

??? success "答えと解説"
    **正解: D**

    `GetSessionToken` はセッションポリシーに対応していません。元の IAM ユーザーと同じ権限のまま、MFA を証明する用途です。

    - A: 誤り。`Policy` と `PolicyArns` を渡せる。
    - B: 誤り。渡せる。
    - C: 誤り。渡せる。渡さないと権限のないセッションになる。
    - D: 正しい。

    **スキル:** C03 2.1.2 / **参照:** [API の比較](../../../services/iam.md#sts-api-compare)

### 問10 {#q10}

カスタム ID ブローカーが `GetFederationToken` で一時認証情報を発行しました。この認証情報の制限として正しいものを選んでください。（2つ選択）

- A. CLI や API で IAM の操作を呼べない
- B. `AssumeRole` を呼べる
- C. STS の操作では `GetCallerIdentity` だけ呼べる
- D. MFA の情報を渡せば `AssumeRole` を呼べる
- E. 期間は常に 1 時間である

??? success "答えと解説"
    **正解: A, C**

    `GetFederationToken` の認証情報は、CLI と API で IAM を呼べず、STS は `GetCallerIdentity` だけです。

    - A: 正しい。コンソールのセッションでは制限が適用されない点だけ異なる。
    - B: 誤り。`AssumeRole` を呼べるのは `GetSessionToken` の認証情報である。
    - C: 正しい。
    - D: 誤り。この API は MFA に対応していない。
    - E: 誤り。IAM ユーザーなら既定 12 時間、最大 36 時間。

    **スキル:** C03 2.1.3 / **参照:** [API の比較](../../../services/iam.md#sts-api-compare)

### 問11 {#q11}

マルチテナントのアプリで、広い権限のロールを引き受けるときに、テナント A のパスだけに絞ったポリシーを渡します。セッションポリシーの理解として正しいものはどれですか。

- A. ロールの権限に、渡したポリシーの権限が加わる
- B. ロールの権限と渡したポリシーの共通部分が、そのセッションの権限になる
- C. 明示的な Deny を上書きできる
- D. 平文で 6,144 文字まで渡せる

??? success "答えと解説"
    **正解: B**

    セッションポリシーは権限を絞るもので、増やせません。文字数は平文で合計 2,048 文字までです。

    - A: 誤り。権限は増えない。
    - B: 正しい。共通部分だけが有効になる。
    - C: 誤り。明示的な Deny は常に優先される。
    - D: 誤り。6,144 文字はカスタマー管理ポリシーの上限。

    **スキル:** C03 2.1.7 / **参照:** [セッションポリシー](../../../services/iam.md#session-policies)

### 問12 {#q12}

セッションポリシーとセッションタグをそれぞれ上限内で渡したのに、`AssumeRole` が `PackedPolicyTooLarge` で失敗しました。最も適切な説明はどれですか。

- A. セッショントークンのサイズが別の上限を超えている
- B. ロールの信頼ポリシーが 2,048 文字を超えている
- C. `ExternalId` が 1,224 文字を超えている
- D. HTTP 403 のアクセス拒否として返っている

??? success "答えと解説"
    **正解: A**

    セッションポリシーとタグは、セッショントークンのサイズにも加算されます。個別の上限内でも、このエラーになります。`PackedPolicySize` は非推奨になり、今は `SessionTokenUtilization` で使用率を確認します。

    - A: 正しい。ポリシーやタグを減らす。
    - B: 誤り。信頼ポリシーの長さとは別の問題。
    - C: 誤り。それならパラメータの検証で失敗する。
    - D: 誤り。`PackedPolicyTooLarge` は HTTP 400。

    **スキル:** C03 2.1.7 / **参照:** [セッションポリシー](../../../services/iam.md#session-policies)

### 問13 {#q13}

共有の管理者ロールを複数の担当者が使っています。セッション名は書き換えられるので、ロールチェーンの先まで「誰の操作か」を変更不可で追跡したいと考えています。最も適切なものはどれですか。

- A. `RoleSessionName` を担当者名にする
- B. `SourceIdentity` を設定し、信頼ポリシーで `sts:SourceIdentity` を要求する
- C. `ExternalId` を担当者ごとに変える
- D. `TransitiveTagKeys` に担当者のタグ名を入れる

??? success "答えと解説"
    **正解: B**

    ソースアイデンティティは一度設定すると変更できず、チェーンの先にも引き継がれ、CloudTrail に残ります。信頼ポリシーと呼び出し元には `sts:SetSourceIdentity` の権限が必要です。

    - A: 誤り。次のロールで別の名前を指定できる。
    - B: 正しい。
    - C: 誤り。`ExternalId` は混乱した代理の対策で、追跡の用途ではない。
    - D: 誤り。セッションタグは引き継げるが、変更不可の識別の用途ではない。

    **スキル:** C03 2.1.7 / **参照:** [ソースアイデンティティ](../../../services/iam.md#source-identity)

### 問16 {#q16}

開発者が CLI で Lambda 関数を作成すると、`iam:PassRole` についての `AccessDenied` になりました。実行ロールの信頼ポリシーには `lambda.amazonaws.com` が設定されています。必要な対応を選んでください。（2つ選択）

### 問17 {#q17}

サービスリンクロールについて正しいものはどれですか。

### 問20 {#q20}

新しいポリシーを本番に適用する前に確認したいと考えています。IAM の機能の説明として正しいものを選んでください。（2つ選択）

- A. ポリシーシミュレーターは実際に API を呼ばずに、許可か拒否かを評価する
- B. ポリシーシミュレーターは RCP も含めて完全に本番と同じ結果を返す
- C. IAM Access Analyzer は CloudTrail の履歴からポリシーを生成できる
- D. IAM Access Analyzer の外部アクセスの分析は全リージョンを 1 つで見られる
- E. `GetCallerIdentity` はポリシーの評価結果を返す
