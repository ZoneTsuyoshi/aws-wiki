## 学習の順番 {#study-order}

1. [署名付き URL](../../../../services/s3.md#presigned-urls): 認証情報ごとの最長期限と、権限が生成者に依存することを覚えます。
2. [CloudFront 署名付き URL との違い](../../../../services/s3.md#cloudfront-signed-urls): 署名に使うものと向く場面を比べます。
3. [暗号化](../../../../services/s3.md#encryption): 5 つの方式を、キーの管理者と暗号化する場所で見分けます。
4. [SSE-KMS の注意点](../../../../services/s3.md#sse-kms)と [S3 Bucket Key](../../../../services/s3.md#bucket-key): 必要な KMS の権限と、暗号化コンテキストの変化を押さえます。
5. [SSE-C の注意点](../../../../services/s3.md#sse-c): 2026 年 4 月からの既定のブロックと解除方法を確認します。
6. [デフォルト暗号化とポリシーによる強制](../../../../services/s3.md#enforcing-encryption): キーの指定と HTTPS を強制するポリシーを読めるようにします。
7. [クライアント側暗号化を選ぶとき](../../../../services/s3.md#client-side-encryption): 要件ごとの選び方を覚えます。
8. [バケットポリシー](../../../../services/s3.md#bucket-policies)、[ブロックパブリックアクセス](../../../../services/s3.md#block-public-access)、[オブジェクト所有者](../../../../services/s3.md#object-ownership): 4 つの設定と ACL が失敗する条件を確認します。

## こう問われたらこう考える {#decisions}

| 状況 | 判断 |
|---|---|
| 未ログインの相手に期限付きでダウンロードさせる | 署名付き URL。バケットポリシーの変更は不要 |
| ブラウザから S3 に直接アップロードする | `PUT` の署名付き URL と CORS |
| 署名付き URL が期限より早く切れる | 一時認証情報の失効。長く使うなら IAM ユーザーの認証情報か CloudFront |
| 署名付き URL が 403 になる | 生成したプリンシパルの権限不足 |
| 誰がいつ復号したかを監査する | SSE-KMS（CloudTrail に記録） |
| AWS に平文を渡したくない | クライアント側暗号化 |
| SSE-KMS で `PutObject` が 403 になる | `kms:GenerateDataKey` の不足。ダウンロードは `kms:Decrypt` |
| 毎秒多数のアップロードで KMS がスロットリングする | S3 Bucket Key |
| 指定のキー以外の `PUT` を拒否する | `s3:x-amz-server-side-encryption-aws-kms-key-id` の `StringNotEquals` で Deny |
| HTTP でのアクセスを拒否する | `aws:SecureTransport` が `false` なら Deny |
| 新しいバケットで SSE-C が 403 になる | 既定でブロックされている。`PutBucketEncryption` の `BlockedEncryptionTypes` を `NONE` にする |
| 公開 ACL 付きの `PutObject` を成功させつつ公開だけを防ぐ | `IgnorePublicAcls` |

## 引っかかりやすい点 {#traps}

- `PUT` の署名付き URL では、署名時に指定した `Content-Type` と違うものを送ると `SignatureDoesNotMatch` になります。
- 署名付き URL は期限内なら何度でも、持っている人なら誰でも使えます。漏えいに注意します。
- Bucket Key を有効にすると、暗号化コンテキストがバケットの ARN になります。オブジェクトの ARN を条件にしたポリシーは動かなくなります。
- デフォルト暗号化を変えても既存のオブジェクトは変わりません。S3 Batch Operations のコピーなどを使います。
- `aws/s3` を別アカウントに読ませることはできません。カスタマーマネージドキーを使います。
- SSE-KMS のオブジェクトはレプリケーションでオプトインが必要です。[設定](../../../../services/s3.md#replication)で `SseKmsEncryptedObjects` とロールの KMS 権限を確認します。
