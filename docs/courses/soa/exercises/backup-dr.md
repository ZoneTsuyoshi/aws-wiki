# バックアップと災害復旧の問題集

対象の解説: [AWS Backup](../../../services/resilience.md#backup)、[4 つの DR 戦略](../../../services/resilience.md#dr-strategies)、[RTO と RPO](../../../services/resilience.md#rto-rpo)

### 問1 {#q1}

本番の EBS、RDS、DynamoDB、EFS のバックアップをタグで指定し、別のリージョンにもコピーしたいです。どのサービスが適切ですか。

- A. Data Lifecycle Manager
- B. S3 のレプリケーション
- C. AWS Backup のバックアッププラン
- D. CloudFormation の `DeletionPolicy`

??? success "答えと解説"
    **正解: C**

    AWS Backup は複数のサービスを一元管理します。タグで割り当てると新しいリソースも対象になります。

    - A: 誤り。EBS のスナップショットと AMI が対象である。
    - B: 誤り。S3 のオブジェクトの機能で、他のサービスは対象にならない。
    - C: 正しい。
    - D: 誤り。スタックの削除時の動作の設定である。

    **スキル:** [2.3.1](../domain2.md#skill-2-3-1) / **参照:** [AWS Backup](../../../services/resilience.md#backup)、[リソースの割り当て](../../../services/resilience.md#backup-assignment)

### 問2 {#q2}

EBS のスナップショットだけを追加料金なしで、毎日自動で作って 7 日で消したいです。どれが最も適切ですか。

- A. Data Lifecycle Manager
- B. Lambda と EventBridge のスケジュールで、取得と削除の処理を自作する構成
- C. 毎日 AMI を手動で作成し、担当者が古い AMI を整理する構成
- D. 組織のバックアップポリシーを全アカウントに展開し、ボールトのロックもかける構成

??? success "答えと解説"
    **正解: A**

    EBS と AMI だけなら、Data Lifecycle Manager が追加料金なしで使えます。

    - A: 正しい。
    - B: 誤り。自作すると運用の負担が増える。
    - C: 誤り。手作業で、自動にならない。
    - D: 誤り。要件より大がかりである。

    **スキル:** [2.3.1](../domain2.md#skill-2-3-1) / **参照:** [AWS Backup](../../../services/resilience.md#backup)、[RDS](../../../services/databases.md#rds)

### 問3 {#q3}

AWS Backup のプランで、RPO を 1 時間にしたいです。現在のルールは毎日 1 回です。どう変えますか。

- A. Vault Lock を有効にして、バックアップを保護する
- B. コールドへの移行を 1 日に変更して、保持の期間を短くする
- C. ボールトのアクセスポリシーを変更して、コピーを増やす
- D. ルールの頻度を 1 時間ごとに変更する

??? success "答えと解説"
    **正解: D**

    毎日のバックアップでは RPO 1 時間を満たせません。

    - A: 誤り。削除の防止で、頻度は変わらない。
    - B: 誤り。頻度は変わらない。
    - C: 誤り。頻度は変わらない。
    - D: 正しい。

    **スキル:** [2.3.1](../domain2.md#skill-2-3-1) / **参照:** [バックアッププランとルール](../../../services/resilience.md#backup-plans)

### 問4 {#q4}

AWS Backup のルールで、コールドストレージへの移行を 30 日後、保持の期間を 60 日にしようとしたところ、設定できません。正しい理由はどれですか。

- A. コールドへの移行は、1 年より後にしか指定できないため
- B. コールドでは最低 90 日の保持が必要で、移行日数 + 90 日以上にするため
- C. バックアッププランのルールでは、コールドへの移行を指定できないため
- D. 保持の期間は、必ず 35 日以下に指定するため

??? success "答えと解説"
    **正解: B**

    この例では、保持は 120 日以上にします。

    - A: 誤り。そのような制限はない。
    - B: 正しい。
    - C: 誤り。ルールで指定できる設定である。
    - D: 誤り。継続的バックアップの上限と混同している。

    **スキル:** [2.3.1](../domain2.md#skill-2-3-1) / **参照:** [バックアッププランとルール](../../../services/resilience.md#backup-plans)

### 問5 {#q5}

監査の要件で、バックアップの削除や保持期間の短縮を管理者でもできないようにしたいです。どの機能を使いますか。

- A. AWS Backup Vault Lock
- B. バックアッププランのルールの頻度を増やす
- C. ボールトの KMS キーをカスタマー管理キーに変える
- D. Data Lifecycle Manager のポリシーを追加する

??? success "答えと解説"
    **正解: A**

    Vault Lock は削除や保持期間の短縮を防ぎます。

    - A: 正しい。
    - B: 誤り。削除の防止にはならない。
    - C: 誤り。暗号化の設定で、削除は防げない。
    - D: 誤り。EBS の管理の機能である。

    **スキル:** [2.3.1](../domain2.md#skill-2-3-1) / **参照:** [Vault Lock](../../../services/resilience.md#vault-lock)、[ランサムウェアと誤削除の防止](../../../services/resilience.md#immutable-compare)

### 問6 {#q6}

RDS の自動バックアップの保持期間の設定について正しいものを選んでください。（2つ選択）

- A. 自動バックアップは RDS の Multi-AZ だけで使える
- B. 保持期間が 0 だと、リードレプリカを作れない
- C. 保持期間を 0 と 0 以外の間で変更すると、停止が発生する
- D. 保持期間の上限は 90 日である
- E. 保持期間を 0 にしても、PITR は引き続き使える

??? success "答えと解説"
    **正解: B, C**

    保持期間の設定を変えるときの注意点です。

    - A: 誤り。Multi-AZ でなくても使える。
    - B: 正しい。
    - C: 正しい。
    - D: 誤り。上限は 35 日である。
    - E: 誤り。自動バックアップが無効になる。

    **スキル:** [2.3.1](../domain2.md#skill-2-3-1) / **参照:** [AWS Backup](../../../services/resilience.md#backup)、[RDS](../../../services/databases.md#rds)

### 問7 {#q7}

本番 12 台、DR に 2 台が常時稼働し、データは複製されています。どの DR 戦略ですか。

- A. パイロットライト
- B. バックアップと復元
- C. ウォームスタンバイ
- D. マルチサイトアクティブ/アクティブ

??? success "答えと解説"
    **正解: C**

    縮小した完全なコピーが稼働しているので、すぐ処理を始められます。

    - A: 誤り。アプリは停止か未作成である。
    - B: 誤り。待機側にアプリは稼働していない。
    - C: 正しい。
    - D: 誤り。全量が稼働する。

    **スキル:** [2.3.4](../domain2.md#skill-2-3-4) / **参照:** [4 つの DR 戦略](../../../services/resilience.md#dr-strategies)、[ウォームスタンバイ](../../../services/resilience.md#warm-standby)

### 問8 {#q8}

Aurora のセカンダリだけが動き、Auto Scaling グループは希望 0 台です。RTO を 30 分から 5 分へ短くするよう求められました。最小の変更はどれですか。

- A. Auto Scaling の起動テンプレートのバージョンを固定する
- B. データの複製をやめて、毎日のスナップショットのコピーに変える
- C. 2 リージョンで全量を動かす
- D. DR 側で少ない台数のアプリを常時動かす

??? success "答えと解説"
    **正解: D**

    今の構成はパイロットライトです。ウォームスタンバイへ変えると、数分で処理を始められます。

    - A: 誤り。起動の時間を待つことは変わらない。
    - B: 誤り。RTO がさらに伸びる。
    - C: 誤り。要件より費用が大きい。
    - D: 正しい。

    **スキル:** [2.3.4](../domain2.md#skill-2-3-4) / **参照:** [パイロットライト](../../../services/resilience.md#pilot-light)、[4 つの DR 戦略](../../../services/resilience.md#dr-strategies)

### 問9 {#q9}

RTO は 24 時間、RPO は数時間です。費用を最小にしたいです。どの DR 戦略を選びますか。

- A. パイロットライト
- B. バックアップと復元
- C. ウォームスタンバイ
- D. マルチサイトアクティブ/アクティブ

??? success "答えと解説"
    **正解: B**

    時間単位の RTO と RPO で費用を最小にするなら、バックアップと復元です。

    - A: 誤り。データの複製を動かし続けるので、この要件には費用が大きい。
    - B: 正しい。
    - C: 誤り。RTO の要件に対して費用が大きい。
    - D: 誤り。費用が最大である。

    **スキル:** [2.3.4](../domain2.md#skill-2-3-4) / **参照:** [4 つの DR 戦略](../../../services/resilience.md#dr-strategies)、[バックアップと復元](../../../services/resilience.md#backup-restore)

### 問10 {#q10}

災害復旧の手順についてのベストプラクティスとして正しいものを選んでください。（2つ選択）

- A. DR リージョンのクォータと容量を事前に確認する
- B. DR 側のインフラは手作業で作り直す手順を残す
- C. AWS Backup の復元テストで、復元できることを定期的に確かめる
- D. レプリケーションがあるので、時点復旧のバックアップは不要である
- E. 障害の発生の前に手順の演習をしない

??? success "答えと解説"
    **正解: A, C**

    試していないバックアップは当てにできません。

    - A: 正しい。
    - B: 誤り。CloudFormation などの IaC で再作成する。
    - C: 正しい。
    - D: 誤り。レプリケーションは破損も複製する。
    - E: 誤り。演習で問題を見つけるのが望ましい。

    **スキル:** [2.3.4](../domain2.md#skill-2-3-4) / **参照:** [復元テストと監査](../../../services/resilience.md#backup-testing)

### 問11 {#q11}

DR の手順の演習で、AZ の障害や API のエラーを制御された形で起こしたいと考えています。どのサービスを使いますか。

- A. AWS Fault Injection Service
- B. CloudWatch の複合アラーム
- C. AWS Compute Optimizer
- D. AWS Trusted Advisor

??? success "答えと解説"

    Fault Injection Service で障害を試せます。

    - A: 正しい。
    - B: 誤り。監視の機能で、障害を起こさない。
    - C: 誤り。サイズの推奨で、障害を起こさない。
    - D: 誤り。設定の助言で、障害を起こさない。

    **スキル:** [2.3.4](../domain2.md#skill-2-3-4) / **参照:** [AWS Fault Injection Service(FIS)](../../../services/resilience.md#fis)

### 問12 {#q12}

RTO と RPO の説明として正しいものはどれですか。

- A. RPO はバックアップの保持期間のことで、RTO はインスタンスの起動時間のことである
- B. RTO と RPO は同じ意味で、どちらかを決めれば他方も同じ値になる
- C. RTO は復旧までに許容する時間で、RPO は失ってよいデータの時間幅である
- D. RPO は復旧までに許容する時間で、RTO は失ってよいデータの量である

??? success "答えと解説"
    **正解: C**

    戦略はこの 2 つと費用で選びます。

    - A: 誤り。保持期間や起動時間だけでは決まらない。
    - B: 誤り。別の指標で、別々に決める。
    - C: 正しい。
    - D: 誤り。逆になっている。

    **スキル:** [2.3.4](../domain2.md#skill-2-3-4) / **参照:** [達成できるかの計算](../../../services/resilience.md#rto-rpo-budget)、[RTO と RPO](../../../services/resilience.md#rto-rpo)
