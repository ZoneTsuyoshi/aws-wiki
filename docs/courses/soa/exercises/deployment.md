# イメージとデプロイ戦略の問題集

対象の解説: [AMI の管理](../../../services/operations.md#amis)、[EC2 Image Builder](../../../services/operations.md#image-builder)、[ECR](../../../services/containers.md#ecr)、[デプロイ戦略の比較](../../../services/cicd.md#deployment-strategies)

### 問1 {#q1}

東京の AMI を大阪で使いたいです。また、コピー先で別のアカウントにも起動させます。正しいものを選んでください。（2つ選択）

- A. コピーした AMI で、改めて起動許可を付与する
- B. `copy-image` で大阪へコピーする
- C. コピーすると起動許可も引き継がれるので、追加の操作は不要である
- D. コピー先のスナップショットだけを相手に共有する
- E. AMI はリージョンをまたいで共通なので、そのまま大阪で使える

??? success "答えと解説"
    **正解: A, B**

    AMI はリージョンごとで、コピーしても起動許可は引き継がれません。

    - A: 正しい。
    - B: 正しい。
    - C: 誤り。起動許可は引き継がれない。
    - D: 誤り。AMI から起動させるには、AMI の起動許可が要る。
    - E: 誤り。AMI はリージョンごとのリソースである。

    **スキル:** [3.1.1](../domain3.md#skill-3-1-1) / **参照:** [AMI の管理](../../../services/operations.md#amis)

### 問2 {#q2}

暗号化された AMI を別のアカウントへ共有しましたが、相手が起動できません。AWS 管理キーで暗号化しています。どう直しますか。

- A. カスタマー管理キーで暗号化し直し、相手にキーの利用を許可する
- B. AMI を登録解除して、スナップショットだけを渡す
- C. 起動許可の付与を AWS 管理キーのポリシーの中に書き加える
- D. 相手のアカウントで EBS のデフォルト暗号化を無効にする設定を行う

??? success "答えと解説"
    **正解: A**

    AWS 管理キーで暗号化した AMI は共有できません。

    - A: 正しい。
    - B: 誤り。AWS 管理キーのスナップショットも共有できない。
    - C: 誤り。AWS 管理キーのポリシーは変更できない。
    - D: 誤り。相手がキーを使えない問題は解決しない。

    **スキル:** [3.1.1](../domain3.md#skill-3-1-1) / **参照:** [AMI の管理](../../../services/operations.md#amis)、[アカウントをまたぐ手順](../../../services/kms.md#cross-account-steps)

### 問3 {#q3}

EC2 Image Builder のビルドがタイムアウトで失敗します。コンポーネントの内容は正しいです。最初に確認することはどれですか。

- A. 配布設定に指定した全リージョンのクォータ
- B. ECR のライフサイクルポリシー
- C. インフラストラクチャ設定のロールと SSM への経路
- D. レシピのバージョンの付け方

??? success "答えと解説"
    **正解: C**

    ロールに `EC2InstanceProfileForImageBuilder` と `AmazonSSMManagedInstanceCore` があり、SSM に接続できることが必要です。

    - A: 誤り。ビルドのステップの失敗には関係がない。
    - B: 誤り。コンテナイメージの古いものの整理の設定である。
    - C: 正しい。
    - D: 誤り。タイムアウトの原因になりにくい。

    **スキル:** [3.1.1](../domain3.md#skill-3-1-1) / **参照:** [EC2 Image Builder](../../../services/operations.md#image-builder)

### 問4 {#q4}

Image Builder で、作ったイメージを別のリージョンへコピーし、別のアカウントに起動許可を与え、起動テンプレートも更新します。どの設定で行いますか。

- A. レシピ
- B. 配布設定
- C. インフラストラクチャ設定
- D. コンポーネント

??? success "答えと解説"
    **正解: B**

    配布設定で、コピー、起動許可、起動テンプレートの更新を指定します。

    - A: 誤り。レシピは内容の定義である。
    - B: 正しい。
    - C: 誤り。ビルド環境の条件の設定である。
    - D: 誤り。手順の定義で、配布は配布設定で行う。

    **スキル:** [3.1.1](../domain3.md#skill-3-1-1) / **参照:** [EC2 Image Builder](../../../services/operations.md#image-builder)

### 問5 {#q5}

ECR で古いイメージの費用を減らし、同じタグの上書きも防ぎたいです。組み合わせとして正しいものはどれですか。

- A. プルスルーキャッシュと OCI のアーティファクト
- B. `get-login-password` と基本スキャン
- C. レプリケーションとイメージスキャン
- D. ライフサイクルポリシーと不変タグ

??? success "答えと解説"
    **正解: D**

    古いイメージの整理はライフサイクルポリシー、上書きの防止は不変タグです。

    - A: 誤り。外部のイメージの取得などの話で、要件に合わない。
    - B: 誤り。認証と検査で、要件に合わない。
    - C: 誤り。リージョンへの複製と脆弱性の検査で、要件に合わない。
    - D: 正しい。

    **スキル:** [3.1.1](../domain3.md#skill-3-1-1) / **参照:** [ライフサイクルポリシー](../../../services/containers.md#ecr-lifecycle)、[タグと不変タグ](../../../services/containers.md#image-tags)

### 問6 {#q6}

`docker pull` で `no basic auth credentials` が出ます。プライベートの ECR からイメージを取得します。何をしますか。

- A. イメージスキャンを有効にする
- B. リポジトリを削除して作り直し、イメージをもう一度プッシュする
- C. イメージのタグを不変に変える
- D. `aws ecr get-login-password` でログインする

??? success "答えと解説"
    **正解: D**

    認証のトークンを取得して Docker にログインします。

    - A: 誤り。検査の機能で、認証に関係がない。
    - B: 誤り。認証の問題で、リポジトリを作り直す必要はない。
    - C: 誤り。タグの設定は認証に関係がない。
    - D: 正しい。

    **スキル:** [3.1.1](../domain3.md#skill-3-1-1) / **参照:** [ECR](../../../services/containers.md#ecr)

### 問7 {#q7}

最新の Amazon Linux の AMI の ID を、テンプレートに固定で書かずに参照したいです。AMI の ID はリージョンと時期で変わります。どれが適切ですか。

- A. AWS Config の AMI の準拠の結果を手で転記する方法
- B. Trusted Advisor のチェックの結果から、最新の ID を得る方法
- C. Parameter Store の公開パラメータ
- D. CloudTrail のイベント履歴を検索して、最新の ID を探す方法

??? success "答えと解説"
    **正解: C**

    AWS が公開している Parameter Store のパラメータで参照します。

    - A: 誤り。手作業が残る。
    - B: 誤り。AMI の ID を得る機能ではない。
    - C: 正しい。
    - D: 誤り。AMI の ID を調べる機能ではない。

    **スキル:** [3.1.1](../domain3.md#skill-3-1-1) / **参照:** [AMI の管理](../../../services/operations.md#amis)

### 問8 {#q8}

新しいバージョンをまず 10% の利用者に流して問題がなければ全体へ広げます。問題があればトラフィックをすぐ戻します。どの戦略ですか。

- A. ローリング
- B. カナリア
- C. バックアップと復元
- D. 一括

??? success "答えと解説"
    **正解: B**

    カナリアは一部へ流して確認した後に残りを移します。

    - A: 誤り。少しずつ更新するものの、確認のための割合の制御が主な目的ではない。
    - B: 正しい。
    - C: 誤り。DR の戦略である。
    - D: 誤り。全部を同時に更新するので、一部で確認できない。

    **スキル:** [3.1.5](../domain3.md#skill-3-1-5) / **参照:** [デプロイ戦略の比較](../../../services/cicd.md#deployment-strategies)

### 問9 {#q9}

新しい環境をあらかじめ用意し、問題があれば切り戻すだけで戻したいです。2 環境分の費用が一時的にかかることは許容します。どれを選びますか。

- A. Blue/Green
- B. インプレースでのデプロイ
- C. 一括
- D. ローリング

??? success "答えと解説"
    **正解: A**

    Blue/Green は別環境へ切り替えるので、戻すのも切り戻すだけです。

    - A: 正しい。
    - B: 誤り。別環境を持たないので、切り戻すだけにはならない。
    - C: 誤り。戻すのに再デプロイが必要で、ダウンタイムもありうる。
    - D: 誤り。戻すのにも再度ローリングが必要である。

    **スキル:** [3.1.5](../domain3.md#skill-3-1-5) / **参照:** [デプロイ戦略の比較](../../../services/cicd.md#deployment-strategies)、[ロールバックの方法](../../../services/cicd.md#rollback)

### 問10 {#q10}

Auto Scaling グループのインスタンスの更新で、自動ロールバックを有効にしたいです。起動テンプレートの指定として正しいものはどれですか。

- A. `$Latest` を指定する
- B. バージョン番号を明示する
- C. `$Default` を指定する
- D. 起動テンプレートを使わず、起動設定を使う

??? success "答えと解説"
    **正解: B**

    戻す先を特定できるように、バージョンを明示します。

    - A: 誤り。自動ロールバックでは使えない。
    - B: 正しい。
    - C: 誤り。自動ロールバックでは使えない。
    - D: 誤り。自動ロールバックの条件に合わない。

    **スキル:** [3.1.5](../domain3.md#skill-3-1-5) / **参照:** [インスタンスの更新](../../../services/operations.md#instance-refresh)

### 問11 {#q11}

新しい AMI を、Auto Scaling グループの全台へ順に適用します。何を使いますか。また、既定の最小正常割合はどれですか。

- A. ウォームプール。既定は 50%
- B. ライフサイクルフック。既定は 100%
- C. インスタンスの更新。既定は 90%
- D. 予測スケーリング。既定は 70%

??? success "答えと解説"
    **正解: C**

    インスタンスの更新の最小正常割合の既定は 90% です。

    - A: 誤り。起動を速くする機能である。
    - B: 誤り。起動や終了に処理を挟む機能である。
    - C: 正しい。
    - D: 誤り。負荷の予測の機能である。

    **スキル:** [3.1.5](../domain3.md#skill-3-1-5) / **参照:** [インスタンスの更新](../../../services/operations.md#instance-refresh)

### 問12 {#q12}

リージョン間でトラフィックの割合を少しずつ移します。DNS のキャッシュに影響されたくありません。どれを選びますか。

- A. Global Accelerator のトラフィックダイヤル
- B. Route 53 の加重ルーティング
- C. CloudFront のオリジンフェイルオーバー
- D. ALB のスティッキーセッション

??? success "答えと解説"
    **正解: A**

    トラフィックダイヤルでリージョンへの割合を変えられます。

    - A: 正しい。
    - B: 誤り。DNS のキャッシュに影響される。
    - C: 誤り。障害のときの切り替えで、割合は変えられない。
    - D: 誤り。同じターゲットへ送る機能で、リージョンの割合は変えられない。

    **スキル:** [3.1.5](../domain3.md#skill-3-1-5) / **参照:** [ルーティングポリシーの設定](../../../services/networking.md#routing-settings)、[Global Accelerator](../../../services/network-connectivity.md#global-accelerator)

### 問13 {#q13}

デプロイの手段の説明として正しいものを選んでください。（2つ選択）

- A. Elastic Beanstalk のイミュータブルは新しいインスタンスに更新する
- B. Route 53 の加重ルーティングでは割合を変更できない
- C. Elastic Beanstalk はローリングのみで、他の方式は選べない
- D. ECS はローリング、Blue/Green、カナリア、線形を選べる
- E. CodeDeploy は Lambda のデプロイに使えない

??? success "答えと解説"
    **正解: A, D**

    対象ごとに、実現の方法を押さえます。

    - A: 正しい。
    - B: 誤り。重みで割合を変えられる。
    - C: 誤り。一括、追加バッチ、イミュータブル、トラフィック分割などがある。
    - D: 正しい。
    - E: 誤り。EC2、Lambda、ECS に使える。

    **スキル:** [3.1.5](../domain3.md#skill-3-1-5) / **参照:** [デプロイポリシー](../../../services/ec2-beanstalk.md#deployment-policies)、[デプロイ](../../../services/containers.md#ecs-deployments)
