# EC2 と性能の最適化の問題集

対象の解説: [Compute Optimizer と適正サイズ](../../../services/cost-management.md#compute-optimizer)、[EC2 の運用](../../../services/operations.md#ec2-operations)、[プレイスメントグループ](../../../services/operations.md#placement-groups)、[代表的なメトリクスと原因](../../../services/observability.md#bottleneck-metrics)

### 問1 {#q1}

EC2 の適切なインスタンスタイプの推奨を、利用状況のメトリクスに基づいて得たいと考えています。これまで Compute Optimizer を使ったことがありません。最初に必要なことはどれですか。

- A. 全インスタンスに Run Command で Compute Optimizer のエージェントを導入して登録する
- B. Compute Optimizer にオプトインする
- C. CloudTrail のデータイベントを有効にする
- D. Cost Explorer で Savings Plans を購入して、推奨の計算の対象となるように設定する

??? success "答えと解説"
    **正解: B**

    Compute Optimizer はオプトインが必要です。

    - A: 誤り。必須のエージェントはない。メモリの値にだけ CloudWatch エージェントが役立つ。
    - B: 正しい。
    - C: 誤り。推奨の元は CloudWatch のメトリクスで、データイベントは使わない。
    - D: 誤り。購入は推奨を得る条件ではない。

    **スキル:** [1.3.1](../domain1.md#skill-1-3-1) / **参照:** [Compute Optimizer と適正サイズ](../../../services/cost-management.md#compute-optimizer)

### 問2 {#q2}

Compute Optimizer の EC2 の推奨で、メモリも考慮してほしいと考えています。どうしますか。

- A. Trusted Advisor の性能のチェックを有効にして、メモリの値を連携する設定を入れる
- B. 休止時に EBS へ保存したメモリの内容を使う
- C. 詳細モニタリングを有効にして、1 分間隔の `AWS/EC2` のメモリの値を収集させる
- D. CloudWatch エージェントでメモリの値を送る

??? success "答えと解説"
    **正解: D**

    メモリを含めた推奨には、CloudWatch エージェントのメトリクスが役立ちます。

    - A: 誤り。Trusted Advisor の設定で Compute Optimizer にメモリの値は渡らない。
    - B: 誤り。休止はメモリの使用率の測定の仕組みではない。
    - C: 誤り。`AWS/EC2` にメモリのメトリクスはない。
    - D: 正しい。

    **スキル:** [1.3.1](../domain1.md#skill-1-3-1) / **参照:** [Compute Optimizer と適正サイズ](../../../services/cost-management.md#compute-optimizer)

### 問3 {#q3}

次の要件と、使うツールの組み合わせとして正しいものを選んでください。（2つ選択）

- A. セキュリティグループの開放の点検: Compute Optimizer
- B. Lambda のメモリサイズの推奨を得る: Compute Optimizer
- C. Savings Plans の購入の推奨を得る: Cost Explorer
- D. 複数の推奨の取りまとめ: CloudTrail
- E. EBS のボリュームタイプの推奨を得る: AWS Health

??? success "答えと解説"
    **正解: B, C**

    推奨の出どころを選べることが問われます。

    - A: 誤り。Compute Optimizer はリソースのサイズの推奨で、セキュリティの点検はしない。
    - B: 正しい。
    - C: 正しい。
    - D: 誤り。API の記録であり、推奨をまとめない。推奨の取りまとめは Cost Optimization Hub である。
    - E: 誤り。AWS Health は AWS 側のイベントの通知である。

    **スキル:** [1.3.1](../domain1.md#skill-1-3-1) / **参照:** [推奨を出すサービスの違い](../../../services/cost-management.md#recommendation-tools)

### 問4 {#q4}

`t3.medium` の Web サーバーが、CPU を使い続ける処理の間だけ遅くなります。クレジットの指定は `standard` です。`CPUCreditBalance` が 0 まで減っています。適切な対処はどれですか。

- A. `unlimited` モードか、M 系などのタイプへ変更する
- B. 詳細モニタリングを有効にして、クレジットの消費を抑えるように設定する
- C. EBS を `gp2` から `gp3` へ変更する
- D. インスタンスを同じタイプの専有ホストへ移して、クレジットの残高を引き継がせる

??? success "答えと解説"
    **正解: A**

    クレジットが尽きると、standard モードではベースラインまで落ちます。

    - A: 正しい。
    - B: 誤り。監視の間隔を変えても消費は変わらない。
    - C: 誤り。原因は CPU のクレジットで、ストレージの変更では直らない。
    - D: 誤り。配置を変えてもクレジットの仕組みは変わらない。

    **スキル:** [1.3.1](../domain1.md#skill-1-3-1) / **参照:** [代表的なメトリクスと原因](../../../services/observability.md#bottleneck-metrics)、[リソース使用量の最適化](../../../services/observability.md#resource-optimization)

### 問5 {#q5}

Lambda の処理時間が長く、ログには CPU を使う処理が多いと表れています。外部の待ち時間はほとんどありません。設定だけで改善するにはどうしますか。

- A. エフェメラルストレージの容量だけを増やして、処理の待ち時間を短くする
- B. 予約済み同時実行を増やして、CPU の割り当てを増やす
- C. 関数のメモリの設定を増やし、比例して増える CPU を使う
- D. タイムアウトを延ばし、処理がゆっくり完了するまで待てるようにする

??? success "答えと解説"
    **正解: C**

    Lambda の CPU はメモリに比例して増えます。

    - A: 誤り。ディスクの容量は CPU の処理時間と関係が薄い。
    - B: 誤り。同時実行は並列数の設定で、CPU は増えない。
    - C: 正しい。
    - D: 誤り。失敗は減っても、速くはならない。

    **スキル:** [1.3.1](../domain1.md#skill-1-3-1) / **参照:** [同時実行とスケーリング](../../../services/lambda.md#concurrency)、[Lambda の既定メトリクス](../../../services/observability.md#lambda-metrics)

### 問6 {#q6}

`Env=dev` のタグが付いた EC2 だけに診断のコマンドを実行します。対象は日々増減します。どの方法が適切ですか。

- A. Compute Optimizer の結果を CSV で取得して、対象の一覧を作ってから実行する
- B. インスタンス ID の一覧を毎朝手で更新して、その一覧に CLI でコマンドを送る
- C. 全台へ送り、スクリプトの中で環境を判定する
- D. Run Command の対象にタグを指定する

??? success "答えと解説"
    **正解: D**

    タグで Run Command や Automation の対象を指定できます。

    - A: 誤り。サイズの推奨であり、対象の選択の仕組みではない。
    - B: 誤り。手作業が残り、増減に追従しにくい。
    - C: 誤り。不要なインスタンスにも実行され、影響の範囲が広がる。
    - D: 正しい。

    **スキル:** [1.3.1](../domain1.md#skill-1-3-1) / **参照:** [タグ戦略](../../../services/governance.md#tagging-strategy)、[Run Command](../../../services/operations.md#run-command)

### 問7 {#q7}

HPC のジョブで、ノード間の遅延を最小にしたいと考えています。どのプレイスメントグループを選びますか。

- A. スプレッド
- B. クラスター
- C. パーティション
- D. どの戦略を選んでも同じ遅延になるので、既定の配置のままにする

??? success "答えと解説"
    **正解: B**

    クラスターは 1 つの AZ の中で近くに配置します。

    - A: 誤り。1 台ずつ別のラックに分ける戦略で、遅延を最小にするものではない。
    - B: 正しい。
    - C: 誤り。障害の影響の範囲を分ける戦略で、HDFS などに向く。
    - D: 誤り。戦略により配置が変わる。

    **スキル:** [1.3.6](../domain1.md#skill-1-3-6) / **参照:** [プレイスメントグループ](../../../services/operations.md#placement-groups)

### 問8 {#q8}

少数の重要なインスタンスを、ハードウェアの障害の影響を受けないように分けたいと考えています。1 つの AZ で 8 台を起動しようとするとエラーになりました。正しい説明はどれですか。

- A. スプレッドは AZ ごとに 7 台までなので、8 台目は別の AZ に置く
- B. パーティションは AZ ごとに 1 台までである
- C. クラスターは AZ ごとに 7 台までなので、8 台目は別の AZ に置く
- D. プレイスメントグループはアカウントで 7 台までなので、上限の引き上げを申請する

??? success "答えと解説"
    **正解: A**

    スプレッドは AZ ごとに 7 台までです。

    - A: 正しい。
    - B: 誤り。パーティションは複数のインスタンスを置ける。
    - C: 誤り。クラスターの説明として誤りで、この要件にも合わない。
    - D: 誤り。そのような上限ではない。

    **スキル:** [1.3.6](../domain1.md#skill-1-3-6) / **参照:** [プレイスメントグループ](../../../services/operations.md#placement-groups)

### 問9 {#q9}

クラスタープレイスメントグループへ追加で起動すると `InsufficientInstanceCapacity` になります。避け方として正しいものを選んでください。（2つ選択）

- A. グループの中で、異なるサイズのタイプを少しずつ追加する
- B. サービスクォータの引き上げを申請し、台数の上限を増やしてもらう
- C. パブリック IP を割り当てて、別のネットワークの容量を使う
- D. 全台を止めて再開し、別のハードウェアへ移す
- E. 必要な台数を 1 回のリクエストで、同じタイプで起動する

??? success "答えと解説"
    **正解: D, E**

    クラスターは近くのハードウェアに置くので、容量の確保が課題になります。

    - A: 誤り。同じタイプをまとめて起動するのが推奨である。
    - B: 誤り。クォータの問題ではなく、容量の問題である。
    - C: 誤り。IP の割り当ては容量に関係しない。
    - D: 正しい。
    - E: 正しい。

    **スキル:** [1.3.6](../domain1.md#skill-1-3-6) / **参照:** [プレイスメントグループ](../../../services/operations.md#placement-groups)、[インスタンスのトラブルシューティング](../../../services/operations.md#instance-troubleshooting)

### 問10 {#q10}

HBase のような分散ストアで、レプリカを別のハードウェアに分けたいと考えています。台数は 1 AZ あたり数十台です。どの戦略が適切ですか。

- A. 専有ホストに全台を並べる方式
- B. クラスター
- C. パーティション
- D. スプレッド

??? success "答えと解説"
    **正解: C**

    パーティションは AZ ごとに 7 個で、パーティションごとに別のハードウェアになります。

    - A: 誤り。ハードウェアを分ける方式ではなく、1 台の障害の影響が大きい。
    - B: 誤り。1 か所に集めるので、ハードウェアの障害に弱い。
    - C: 正しい。
    - D: 誤り。AZ ごとに 7 台までなので、数十台を置けない。

    **スキル:** [1.3.6](../domain1.md#skill-1-3-6) / **参照:** [プレイスメントグループ](../../../services/operations.md#placement-groups)

### 問11 {#q11}

同じ VPC 内の EC2 の間でジャンボフレームを使っています。インターネット宛の通信で、大きなパケットが届かないことがあります。正しい説明はどれですか。

- A. VPC 内のすべての経路は常に 9001 なので、MTU は原因ではない
- B. EFA を追加すると、インターネット宛の MTU も 9001 になる
- C. ENA を無効にすれば、MTU が自動で 1500 に変わる
- D. VPC の外の経路の MTU は 1500 なので、大きなパケットは通らない

??? success "答えと解説"
    **正解: D**

    ジャンボフレーム（MTU 9001）は VPC 内の話です。

    - A: 誤り。インターネットなど、経路の外では 1500 である。
    - B: 誤り。EFA は HPC のノード間通信向けのアダプターである。
    - C: 誤り。ENA を無効にしても解決しない。
    - D: 正しい。

    **スキル:** [1.3.6](../domain1.md#skill-1-3-6) / **参照:** [MTU とジャンボフレーム](../../../services/network-connectivity.md#mtu)

### 問12 {#q12}

ML の分散学習で、ノード間の通信の性能を高くしたいです。どのネットワークの機能が目的に合っていますか。

- A. NAT ゲートウェイ
- B. Elastic Fabric Adapter
- C. Elastic IP
- D. Egress-only インターネットゲートウェイ

??? success "答えと解説"
    **正解: B**

    Elastic Fabric Adapter（EFA）は、HPC や ML のノード間通信向けのアダプターです。

    - A: 誤り。プライベートサブネットから外へ出るためのゲートウェイである。
    - B: 正しい。
    - C: 誤り。固定のパブリック IP で、ノード間の性能は上がらない。
    - D: 誤り。IPv6 の外向きの通信に使うゲートウェイである。

    **スキル:** [1.3.6](../domain1.md#skill-1-3-6) / **参照:** [プレイスメントグループ](../../../services/operations.md#placement-groups)

### 問13 {#q13}

再生成できる一時データを扱うジョブで、最小の遅延のローカルストレージが必要です。インスタンスの停止でデータが消えてもかまいません。何を選びますか。

- A. `io2` の EBS ボリュームを複数に分けて RAID を組む
- B. EFS の Max I/O モードを使う
- C. インスタンスに付属のインスタンスストア
- D. S3 Express One Zone を Transfer Acceleration で使う

??? success "答えと解説"
    **正解: C**

    データが消えてよく、最小の遅延が必要ならインスタンスストアです。

    - A: 誤り。永続のストレージで、要件より費用がかかる。
    - B: 誤り。ネットワーク越しの共有ストレージで、最小の遅延にならない。
    - C: 正しい。
    - D: 誤り。ローカルのストレージではない。

    **スキル:** [1.3.6](../domain1.md#skill-1-3-6) / **参照:** [インスタンスストア](../../../services/storage-advanced.md#instance-store)

### 問14 {#q14}

スポットの中断と休止について正しいものを選んでください。（2つ選択）

- A. 休止には起動時の有効化とルートボリュームの暗号化が必要である
- B. 稼働中のインスタンスは、再起動なしにいつでも休止を有効にできる
- C. スポットの中断の通知は 24 時間前に届く
- D. スポットの中断は 2 分前に通知される
- E. 休止はインスタンスストアを使うルートボリュームだけが対象である

??? success "答えと解説"
    **正解: A, D**

    中断の通知と休止の条件を区別して覚えます。

    - A: 正しい。
    - B: 誤り。起動時に有効にする。
    - C: 誤り。通知は 2 分前である。
    - D: 正しい。
    - E: 誤り。ルートは EBS で暗号化されている必要がある。

    **スキル:** [1.3.6](../domain1.md#skill-1-3-6) / **参照:** [スポットの中断への対応](../../../services/operations.md#spot-interruptions)、[休止](../../../services/operations.md#hibernate)
