### 問1 {#q1}

利用者から「最初の文字が出るまで遅い」と苦情があります。`InvocationLatency` は許容範囲で、`TimeToFirstToken` が長いです。Guardrails を同期モードで使っています。最も適切な調査の対象はどれですか。

- A. `CacheWriteInputTokenCount` と TTL の延長だけ
- B. `InvocationThrottles` と Provisioned Throughput の購入の有無
- C. 入力の長さ、モデルの大きさ、Guardrails のバッファ
- D. `OutputTokenCount` と `maxTokens`

??? success "答えと解説"
    **正解: C**

    `TimeToFirstToken` の遅れには、入力の長さ、モデル、同期モードのバッファが関わります。

    - A: 誤り。キャッシュの書き込みは最初の文字までの遅れの主な調査対象ではない。
    - B: 誤り。スロットリングの話で、このメトリクスが示す遅れの調査ではない。
    - C: 正しい。
    - D: 誤り。出力の長さは全体の時間に効くが、最初の文字までの主因ではない。

    **スキル:** [4.2.1](../domain4.md#skill-4-2-1) / **参照:** [遅延の短縮](../../../services/genai-apps.md#latency)、[CloudWatch のメトリクス](../../../services/ai.md#bedrock-metrics)

### 問2 {#q2}

ストリーミングに変えたところ、体感は改善しましたが、バックエンドの処理全体の時間を指標にしている SLA は変わりません。上司は「ストリーミングで全体が速くなるはず」と考えています。正しい説明と、全体の時間を短くする手段の組み合わせはどれですか。

- A. ストリーミングで全体も短くなるので、計測の誤りとして SLA の計算を直す
- B. ストリーミングで全体を短くするには、`maxTokens` を増やす
- C. 全体の時間は容量だけで決まるので、Provisioned Throughput を購入する
- D. 改善するのは最初の応答までの時間で、全体の短縮には小さなモデルや短い入力を使う

??? success "答えと解説"
    **正解: D**

    ストリーミングで改善するのは `TimeToFirstToken` で、`InvocationLatency` は変わりません。

    - A: 誤り。`InvocationLatency` は変わらない。
    - B: 誤り。応答が長くなり、全体は短くならない。
    - C: 誤り。モデルや入力の長さでも決まる。
    - D: 正しい。

    **スキル:** [4.2.1](../domain4.md#skill-4-2-1) / **参照:** [遅延の短縮](../../../services/genai-apps.md#latency)、[キャッシュの種類](../../../services/genai-apps.md#caching)

### 問3 {#q3}

ニュースの要約の配信で、毎朝、よく読まれる上位 100 件の質問はほぼ決まっています。朝のピークに FM の呼び出しが集中します。回答は数時間古くてもかまいません。最も適切な方法はどれですか。

- A. 上位の質問の回答を事前に計算して DynamoDB や S3 に置く
- B. プロンプトキャッシュに上位の質問を入れて、朝の FM の呼び出しをなくす
- C. ピークの間だけ Priority ティアで同じ質問を毎回生成する
- D. `temperature` を下げて同じ回答を速く生成する

??? success "答えと解説"
    **正解: A**

    予測できる質問は事前に計算すれば、モデルを呼びません。鮮度は犠牲にします。

    - A: 正しい。
    - B: 誤り。入力の前半の再利用で、呼び出しそのものはなくならない。
    - C: 誤り。速くなっても毎回の費用がかかる。
    - D: 誤り。生成の速さには効かない。

    **スキル:** [4.2.1](../domain4.md#skill-4-2-1) / **参照:** [遅延の短縮](../../../services/genai-apps.md#latency)、[キャッシュの種類](../../../services/genai-apps.md#caching)

### 問4 {#q4}

1 つの依頼で、要約、翻訳、感情分析の 3 つの独立した処理を順に実行しており、15 秒かかります。処理の間に依存関係はなく、クォータには余裕があります。最も適切な改善はどれですか。

- A. それぞれの間に Wait 状態を入れてスロットリングを避ける
- B. Parallel で同時に実行し、同時に増えるトークンの消費がクォータに収まるかを確かめる
- C. 3 つを 1 つのプロンプトにまとめ、`maxTokens` を 3 倍にする
- D. Standard を Express に変えれば、順次のまま全体が半分になる

??? success "答えと解説"
    **正解: B**

    独立した処理は同時に実行できます。同時に消費するクォータに注意します。

    - A: 誤り。全体の時間が増える。
    - B: 正しい。
    - C: 誤り。速くなる保証がなく、形式の取り違えも増える。
    - D: 誤り。種類を変えてもモデルの処理時間は変わらない。

    **スキル:** [4.2.1](../domain4.md#skill-4-2-1) / **参照:** [遅延の短縮](../../../services/genai-apps.md#latency)、[Map の設定](../../../services/step-functions.md#map-settings)

### 問5 {#q5}

出力の消費率が 5 倍のモデルで、入力 1,000、`max_tokens` 8,000、実際の出力 100 の呼び出しです。開始時に差し引かれる量、完了時のクォータの消費、課金のトークン数の正しい組み合わせはどれですか。

- A. 9,000、1,500、1,100
- B. 1,100、1,500、9,000
- C. 41,000、1,500、1,100
- D. 9,000、1,100、1,500

??? success "答えと解説"
    **正解: A**

    開始時は入力 + `max_tokens`、完了時は入力 + 出力 × 消費率で、課金は実際のトークン数です。

    - A: 正しい。
    - B: 誤り。開始時には `max_tokens` の分が予約される。
    - C: 誤り。開始時の予約では消費率を掛けない。
    - D: 誤り。消費と課金が逆。消費は 1,000 + 100 × 5、課金は 1,000 + 100。

    **スキル:** [4.2.3](../domain4.md#skill-4-2-3) / **参照:** [クォータの計算例](../../../services/ai.md#quotas-detail)、[スループット](../../../services/genai-apps.md#throughput)

### 問6 {#q6}

SQS から Lambda で FM を呼ぶ処理と、Step Functions の Map で文書を処理する流れがあり、どちらもスパイク時にスロットリングが増えます。同時に FM へ向かう数を、処理の待ちを許容して制限します。最も適切な組み合わせはどれですか。

- A. Bedrock の `requestMetadata` に上限の値を入れる
- B. Lambda のタイムアウトを短くし、Map は Express に変える
- C. Lambda は予約済み同時実行、Map は `MaxConcurrency` で並列度を制限する
- D. Lambda のメモリを増やし、Map の `MaxConcurrency` は 0 にする

??? success "答えと解説"
    **正解: C**

    同時実行は Lambda の予約済み同時実行と Map の並列度で管理します。

    - A: 誤り。ログの絞り込み用で、流量の制限にならない。
    - B: 誤り。タイムアウトは同時実行を制限せず、失敗が増える。
    - C: 正しい。
    - D: 誤り。メモリは同時実行を制限しない。`MaxConcurrency` の 0 は上限なしの意味。

    **スキル:** [4.2.3](../domain4.md#skill-4-2-3) / **参照:** [予約済み同時実行](../../../services/lambda.md#reserved-concurrency)、[Map の設定](../../../services/step-functions.md#map-settings)

日中のチャットと、毎日の 50 万件の要約が同じモデルのクォータを取り合っています。要約は翌朝までに終わればよく、チャットの遅延は上げられません。最も適切な変更はどれですか。

- D. 要約をバッチ推論に分け、夜間に実行する

- A. 3 つとも 1 に揃えて多様性を確保する
