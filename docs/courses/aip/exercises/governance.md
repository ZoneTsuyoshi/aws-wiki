### 問1 {#q1}

規制当局への説明のために、社内で運用する複数のモデルの目的、学習データ、限界を統一の形式で文書化します。リリースのパイプラインから自動で作成したいと考えています。最も適切なものはどれですか。

- A. CloudTrail の管理イベントの記録から、モデルの目的を読み取る
- B. SageMaker Model Cards を API で作成する
- C. 各チームが Word で文書を作り、共有フォルダに置く
- D. モデル呼び出しログを 1 年分保存して、文書の代わりにする

??? success "答えと解説"
    **正解: B**

    Model Cards はモデルの文書化の仕組みで、API で作成できます。

    - A: 誤り。API の操作の記録で、目的は分からない。
    - B: 正しい。
    - C: 誤り。形式が揃わず、パイプラインから自動で作れない。
    - D: 誤り。入出力の記録で、目的や限界の文書にはならない。

    **スキル:** [3.3.1](../domain3.md#skill-3-3-1) / **参照:** [Model Cards](../../../services/sagemaker.md#model-cards)、[統治の仕組み](../../../services/genai-apps.md#governance-controls)

### 問2 {#q2}

規制の要件で、FM の入力データがどこから来て、どのジョブで加工されたかを示す必要があります。加工は Glue 5.0 の Spark ジョブで DataFrame を使っており、リネージの収集のために自作のコードを増やしたくありません。最も適切な方法はどれですか。

- A. Glue のクローラーをデータソースごとに毎日実行し、検出したスキーマの変更をリネージとして報告する
- B. Macie でデータソースを検出し、リネージとして報告する
- C. ジョブごとに入出力のテーブル名を CloudWatch Logs に手で書き出し、毎月集計する
- D. ジョブで「Generate lineage events」を有効にして、実行時に自動で集める

??? success "答えと解説"
    **正解: D**

    Glue 5.0 以降の Spark ジョブでこの設定を有効にすると、実行時にリネージを自動で集めて DataZone のドメインへ送ります。

    - A: 誤り。クローラーはスキーマの検出で、どのジョブで加工したかは分からない。
    - B: 誤り。Macie は機密データの発見で、加工の流れは分からない。
    - C: 誤り。手作業のコードが増え、抜けも起きやすい。
    - D: 正しい。

    **スキル:** [3.3.1](../domain3.md#skill-3-3-1) / **参照:** [Data Catalog](../../../services/data-engineering.md#glue-data-catalog)、[統治の仕組み](../../../services/genai-apps.md#governance-controls)

- A. モデル呼び出しログを有効にして、保持期間とアクセスを管理する

新しいアプリが本番に出るときに、ガードレールの設定とログの設定を必ず確認したいと考えています。人のレビューの漏れが続いています。プロンプトの変更時にも安全の指標を確かめます。適切なものを選んでください。（2つ選択）

- A. CI/CD の品質ゲートに `Harmfulness` などの評価を入れる
- B. 検査のためにガードレールの `DRAFT` を本番で指定する
- C. 全アプリのレビューを半年に 1 回の会議にまとめる
- D. 呼び出しログを無効にして、確認の対象を減らす
- E. Lambda でガードレールの有無とログの設定を自動で検査する

??? success "答えと解説"
    **正解: A, E**

    自動の確認と CI/CD の品質ゲートで、人の確認の漏れを防ぎます。

    - A: 正しい。
    - B: 誤り。編集がそのまま本番へ反映される。
    - C: 誤り。変更の時点で確認できない。
    - D: 誤り。監査の能力が下がる。
    - E: 正しい。

    **スキル:** [3.4.3](../domain3.md#skill-3-4-3) / **参照:** [テスト](../../../services/genai-apps.md#testing)、[Guardrails の実践](../../../services/genai-apps.md#guardrails-depth)

### 問18 {#q18}

社内で調整したモデルは、医療の用途に使わないことが条件で承認されました。この制限を、利用部門とモデルの開発者が同じ場所で確かめられるようにします。実行時の制御は別の仕組みで行います。最も適切なものはどれですか。

- A. 制限を CloudWatch アラームの説明欄に書く
- B. Model Cards に限界と想定外の用途を文書化する
- C. 制限を Provisioned Throughput のタグに入れる
- D. 制限をモデルの重みのファイル名に入れる

??? success "答えと解説"
    **正解: B**

    限界の文書化はモデルカードです。実行時の制御と分けて考えます。

    - A: 誤り。監視の設定で、モデルの文書にならない。
    - B: 正しい。
    - C: 誤り。容量のリソースで、モデルの文書にならない。
    - D: 誤り。文書として確かめられない。

    **スキル:** [3.4.3](../domain3.md#skill-3-4-3) / **参照:** [Model Cards](../../../services/sagemaker.md#model-cards)、[責任ある AI の 8 つの観点](../../../services/ai-fundamentals.md#rai-dimensions)
