# ワークフローとオーケストレーションの問題集

### 問1 {#q1}

監査の要件が厳しいエージェントを ReAct で作ります。各手順の入出力が実行履歴に残り、ツールの呼び出しに上限を明示する必要があります。短く書くことより、監査のしやすさを優先します。最も適切な実装はどれですか。

- A. Strands のエージェント 1 つに任せ、ループの回数はプロンプトで指示する
- B. 1 回の `Converse` に Chain-of-thought を指示し、ツールの結果を推測させる
- C. Step Functions の Standard で、Bedrock の呼び出し、`stopReason` の分岐、Lambda のツール実行を組む
- D. Lambda 1 つの中で `while True` のループを書き、結果を標準出力に出す

??? success "答えと解説"
    **正解: C**

    Step Functions は各手順が実行履歴に残り、上限や分岐を明示できます。

    - A: 誤り。短く書けるが、制御をプロンプトやコードに任せることになり、要件の優先順位と合わない。
    - B: 誤り。外部の情報が要るときは ReAct で、推測は監査に耐えない。
    - C: 正しい。
    - D: 誤り。上限が明示されず、最大 15 分でも止まり、履歴も残らない。

    **スキル:** [2.1.2](../domain2.md#skill-2-1-2) / **参照:** [構造のパターン](../../../services/genai-apps.md#workflow-patterns)、[ツール利用の流れ](../../../services/ai.md#tool-use-flow)

### 問2 {#q2}

Step Functions で ReAct のループを組みます。Bedrock の応答を受けたあと、次の状態を決める Choice の条件として正しいものはどれですか。

- A. `usage` の `totalTokens` の値が 0 ならツールの実行へ、それ以外なら最終の回答へ進む
- B. `stopReason` が `tool_use` ならツールの実行へ、`end_turn` なら回答へ進む
- C. 応答の本文に「ツール」の語があればツールの実行へ、なければ回答へ進む
- D. `metrics` の `latencyMs` が長ければツールの実行へ、短ければ回答へ進む

??? success "答えと解説"
    **正解: B**

    `stopReason` が `tool_use` ならモデルがツールの実行を要求しています。

    - A: 誤り。トークン数はツールの要求を示さない。
    - B: 正しい。
    - C: 誤り。文字列の一致は誤判定する。`stopReason` で判定する。
    - D: 誤り。遅延は次の行動と関係がない。

    **スキル:** [2.1.2](../domain2.md#skill-2-1-2) / **参照:** [ツール利用の流れ](../../../services/ai.md#tool-use-flow)、[構造のパターン](../../../services/genai-apps.md#workflow-patterns)

### 問3 {#q3}

2 つの問題があります。(a) 手元のデータだけで答えられる複雑な料金の計算で、途中の式が崩れる。(b) 最新の在庫を社内 API で調べながら、代替品を提案する。それぞれに合う手法はどれですか。

- A. (a) Chain-of-thought、(b) ReAct
- B. (a) セマンティックキャッシュ、(b) プロンプトキャッシュ
- C. (a) ファインチューニング、(b) バッチ推論
- D. (a) ReAct、(b) Chain-of-thought

??? success "答えと解説"
    **正解: A**

    Chain-of-thought は 1 回の呼び出しの中で段階的に考えさせます。外部の情報が要るなら ReAct です。

    - A: 正しい。
    - B: 誤り。どちらも費用と遅延の手法で、推論の品質の手法ではない。
    - C: 誤り。(a) は段階的に考えさせれば足り、(b) は対話の中でツールが要る。
    - D: 誤り。(b) は外部の情報が要るので、1 回の呼び出しの中で考えるだけでは足りない。

    **スキル:** [2.1.2](../domain2.md#skill-2-1-2) / **参照:** [プロンプトエンジニアリング](../../../services/ai-fundamentals.md#prompt-engineering)、[構造のパターン](../../../services/genai-apps.md#workflow-patterns)

### 問4 {#q4}

与信の判断の説明文を生成します。誤りのコストが非常に高く、処理は 1 日に数百件で、数分の遅延と費用の増加は許容されます。別の処理である日次の問い合わせの分類は 100 万件で、費用が優先です。適切な設計はどれですか。

- A. 両方とも最も安いモデルを 1 つだけ使い、誤りは後で人が見つける
- B. 与信は最も安いモデル、分類は最上位のモデルにして、平均の費用を抑える
- C. 両方とも同じ 3 つのモデルで毎回アンサンブルを行い、多数決で最終の結果を 1 つに決める
- D. 与信は複数のモデルの結果を別のモデルで採点し、分類は小さなモデルを 1 つだけ使う

??? success "答えと解説"
    **正解: D**

    アンサンブルは品質を上げますが、呼び出しの数だけ費用が増えます。誤りのコストが高い処理に限定します。

    - A: 誤り。誤りのコストが高い与信に向かない。
    - B: 誤り。要件と逆の割り当てになっている。
    - C: 誤り。分類の費用が 3 倍になり、優先順位に反する。
    - D: 正しい。

    **スキル:** [2.1.4](../domain2.md#skill-2-1-4) / **参照:** [構造のパターン](../../../services/genai-apps.md#workflow-patterns)、[動的なモデル切り替え](../../../services/genai-apps.md#dynamic-model-selection)

### 問5 {#q5}

文書処理で、言語の判定、項目の抽出、法的なリスクの推論を行います。判定と抽出は単純で、件数も多いです。推論だけ高い品質が必要です。今は最上位のモデル 1 つで全部を処理しています。最も適切な変更はどれですか。

- A. 3 つの処理を 1 つの長いプロンプトにまとめ、呼び出しの回数を減らす
- B. 全部を小さなモデルへ移し、推論の品質はプロンプトの工夫で補う
- C. 全部をさらに上位のモデルへ移し、品質の余裕で再試行を減らす
- D. 判定と抽出は小さなモデル、推論は上位のモデルに分担させる

??? success "答えと解説"
    **正解: D**

    仕事ごとに最適なモデルを使います。Step Functions や Lambda で組めます。

    - A: 誤り。単純な処理にも上位のモデルを使うことになり、費用が残る。
    - B: 誤り。高い品質が必要な推論を小さなモデルで補える保証がない。
    - C: 誤り。単純な処理の費用が増える。
    - D: 正しい。

    **スキル:** [2.1.4](../domain2.md#skill-2-1-4) / **参照:** [構造のパターン](../../../services/genai-apps.md#workflow-patterns)、[動的なモデル切り替え](../../../services/genai-apps.md#dynamic-model-selection)

### 問6 {#q6}

3 つの FM に同じ質問を並列で投げ、結果を統合するワークフローを作りました。ピーク時に応答が遅いと報告されています。各モデルの遅延を調べると、1 つだけ極端に遅いモデルがあります。統合の品質はそのモデルなしでも許容範囲です。最も適切な対応はどれですか。

- A. 遅いモデルを外す。アンサンブルの遅延は最も遅いモデルに引きずられる
- B. 並列を順次の実行に変えて、1 つずつ確実に待つ
- C. 3 つすべてに `maxTokens` の最大値を指定して、統合の情報量を増やす
- D. `Parallel` の前に Wait 状態を入れて、モデルの準備ができるまで待つ

??? success "答えと解説"
    **正解: A**

    並列の遅延は最も遅い呼び出しで決まります。

    - A: 正しい。
    - B: 誤り。全体の時間は合計になり、さらに遅くなる。
    - C: 誤り。応答が長くなり、遅延は改善しない。
    - D: 誤り。遅延が増える。

    **スキル:** [2.1.4](../domain2.md#skill-2-1-4) / **参照:** [構造のパターン](../../../services/genai-apps.md#workflow-patterns)

### 問7 {#q7}

エージェントが 100 万円を超える支払いを行う前に、経理担当の承認を得ます。承認者が休みの場合は最大 3 日で別の担当に回します。Step Functions を使います。最も適切な実装はどれですか。

- A. Standard の `.waitForTaskToken` で通知し、タイムアウトは設定せずに承認者の応答を待つ
- B. Standard の `.waitForTaskToken` で通知し、`TimeoutSeconds` で別の担当へ回す
- C. Express の `.waitForTaskToken` で通知し、`TimeoutSeconds` を 3 日に設定する
- D. Lambda で 3 日間スリープして、データベースの承認の列を確かめる

??? success "答えと解説"
    **正解: B**

    承認は Standard の `.waitForTaskToken` です。タイムアウトかハートビートを必ず設定します。

    - A: 誤り。応答がないまま止まり続ける。
    - B: 正しい。
    - C: 誤り。Express は `.waitForTaskToken` に対応せず、最大 5 分。
    - D: 誤り。Lambda は最大 15 分で、スリープにも費用がかかる。

    **スキル:** [2.1.5](../domain2.md#skill-2-1-5) / **参照:** [人の承認](../../../services/step-functions.md#human-approval)、[タイムアウト](../../../services/step-functions.md#timeouts)

### 問8 {#q8}

承認の画面を社内ポータルに作ります。承認者がボタンを押した結果を、待機中のワークフローに返す必要があります。承認者に AWS の権限は渡しません。最も適切な構成はどれですか。

- A. 結果を S3 に保存し、ワークフローに自動で読み取ってもらう
- B. 承認者のボタンでワークフローを再起動し、最初から処理をやり直す
- C. API Gateway と Lambda で受け、Lambda からタスクトークンで `SendTaskSuccess` を呼ぶ
- D. 承認者に IAM ユーザーを作り、CLI で `SendTaskSuccess` を実行してもらう

??? success "答えと解説"
    **正解: C**

    バックエンドからタスクトークンを返します。トークンは通知に入れて渡します。

    - A: 誤り。`.waitForTaskToken` は S3 を見ない。トークンを返さないと進まない。
    - B: 誤り。無駄な処理が増え、ツールの二重実行の恐れがある。
    - C: 正しい。
    - D: 誤り。権限を渡さない条件に反する。

    **スキル:** [2.1.5](../domain2.md#skill-2-1-5) / **参照:** [人の承認](../../../services/step-functions.md#human-approval)、[人による確認](../../../services/genai-apps.md#human-in-the-loop)

### 問9 {#q9}

契約書の要約で、グラウンディングのスコアが低い回答だけを専門家が確認します。全件の確認は費用が合いません。確認の結果は評価データにも使います。新規の設計です。最も適切なものはどれですか。

- A. 全件を専門家に回し、確認が終わるまで利用者を待たせる
- B. スコアの低い回答を自動で削除して、利用者には回答なしと返す
- C. 新しく Amazon Augmented AI を契約し、新規の人のレビューの基盤を構築する
- D. しきい値を下回る回答だけを Step Functions の承認に回し、結果を保存する

??? success "答えと解説"
    **正解: D**

    信頼度のしきい値で人に回します。新規の設計では Step Functions の人の承認で組めます。

    - A: 誤り。費用が合わないという条件に反する。
    - B: 誤り。確認も評価データの蓄積もできない。
    - C: 誤り。A2I は新規顧客を受け付けていない。
    - D: 正しい。

    **スキル:** [2.1.5](../domain2.md#skill-2-1-5) / **参照:** [人による確認](../../../services/genai-apps.md#human-in-the-loop)、[A2I](../../../services/ai-managed-services.md#a2i)

### 問10 {#q10}

次の 3 つのアプリの実装方式を選びます。(a) 抽出、要約、翻訳の決まった 3 手順で、プロンプトの担当者が調整する。(b) 監査と補償処理、人の承認が要る融資の手続き。(c) 調査の手順が質問によって変わり、事前に決められない。最も適切な組み合わせはどれですか。

- A. (a) Flows、(b) Step Functions、(c) Strands Agents
- B. (a)〜(c) すべてを 1 つの Strands Agents で実装する
- C. (a) Step Functions、(b) Strands Agents、(c) Flows
- D. (a) Strands Agents、(b) Flows、(c) Step Functions の Standard

??? success "答えと解説"
    **正解: A**

    決められる手順はワークフローで書き、判断が必要な部分だけをエージェントに任せます。

    - A: 正しい。
    - B: 誤り。決められる手順まで予測しにくくなる。
    - C: 誤り。(b) の監査と補償処理をモデルに任せるのは危険で、(c) は手順を事前に書けない。
    - D: 誤り。手順が決まった (a) にエージェントは不要で、(c) は手順を事前に書けない。

    **スキル:** [2.5.5](../domain2.md#skill-2-5-5) / **参照:** [構造のパターン](../../../services/genai-apps.md#workflow-patterns)、[Bedrock Flows](../../../services/genai-apps.md#flows)

### 問11 {#q11}

請求、技術、解約の専門エージェントがすでにあり、利用者の問い合わせの窓口を 1 つにしたいと考えています。問い合わせごとに適切なエージェントへ渡し、会話の途中で担当が変わっても文脈を保つ必要があります。追加の実装は小さくしたいです。最も適切なものはどれですか。

- A. 利用者に画面で担当のエージェントを選ばせ、途中の変更は再入力してもらう
- B. Agent Squad で問い合わせを振り分ける
- C. 3 つのエージェントのプロンプトを 1 つに連結し、全ツールを登録する
- D. 問い合わせごとに 3 つのエージェントを全部呼び、最も長い回答を返す

??? success "答えと解説"
    **正解: B**

    Agent Squad は問い合わせを適切なエージェントへ振り分け、文脈を保ちます。

    - A: 誤り。文脈を保つ要件を満たさない。

    - C: 誤り。指示とツールが増えて選択の誤りが増え、専門の分担の利点を失う。
    - D: 誤り。費用が 3 倍になり、長さは正しさと関係がない。

    **スキル:** [2.5.5](../domain2.md#skill-2-5-5) / **参照:** [マルチエージェント](../../../services/genai-apps.md#multi-agent)、[構造のパターン](../../../services/genai-apps.md#workflow-patterns)

### 問12 {#q12}

自律的なエージェントで問い合わせの全手順を処理したところ、費用が読めず、同じ問い合わせでも手順が毎回変わって、監査で説明が難しくなりました。手順のうち受付、本人確認、記録は常に同じで、調査の部分だけが場合によって変わります。最も適切な変更はどれですか。

- A. エージェントをやめ、すべての調査の分岐を人が事前に書き出す
- B. モデルを上位に変えて、手順のばらつきをなくす
- C. 決まった手順はワークフローに書き、調査の部分だけをエージェントに任せる
- D. 全手順をエージェントのまま、プロンプトに手順の順序を詳しく何度も書き足す

??? success "答えと解説"
    **正解: C**

    自律性を上げるほど、予測しにくく費用も読みにくくなります。必要な部分に限定します。

    - A: 誤り。場合によって変わる調査を網羅できない。
    - B: 誤り。上位のモデルでも手順のばらつきは残り、費用も増える。
    - C: 正しい。
    - D: 誤り。順序を保証できず、費用も読みにくいまま。

    **スキル:** [2.5.5](../domain2.md#skill-2-5-5) / **参照:** [構造のパターン](../../../services/genai-apps.md#workflow-patterns)
