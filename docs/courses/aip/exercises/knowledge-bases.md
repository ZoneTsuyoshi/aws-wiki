# Knowledge Bases と検索の問題集

### 問1 {#q1}

ある企業は、Customer-managed のナレッジベースと OpenSearch を運用しています。CRM の SaaS にある問い合わせ記録も毎晩 RAG の対象にしたいと考えています。ナレッジベースの方式は変えたくありません。カスタムのコードは最小にします。最も適切な方法はどれですか。

- A. Customer-managed のナレッジベースに、CRM 用のコネクタをコンソールで追加する
- B. AppFlow で SaaS のデータを毎晩 S3 に転送し、S3 のデータソースとして同期する
- C. CRM の全データを Lambda で毎晩読み出すコードを書き、ベクトルストアに直接書き込む
- D. DataSync で SaaS の API に接続し、Knowledge Bases へ直接転送する

??? success "答えと解説"
    **正解: B**

    AppFlow で SaaS のデータを S3 へ転送すれば、既存のデータソースの仕組みのまま取り込めます。

    - A: 誤り。Customer-managed のコネクタは S3 と Custom だけで、2026-09-30 以降は Salesforce などのコネクタを新しく作れない。
    - B: 正しい。
    - C: 誤り。カスタムのコードが増え、チャンクや埋め込みも自分で実装することになる。
    - D: 誤り。DataSync はファイルやオブジェクトの転送サービスで、Knowledge Bases へは直接転送しない。

    **スキル:** [1.4.4](../domain1.md#skill-1-4-4) / **参照:** [AppFlow](../../../services/data-engineering.md#appflow)、[Managed と Customer-managed](../../../services/genai-apps.md#managed-kb)

### 問2 {#q2}

工場のオンプレミスのファイルサーバーにある手順書を RAG の対象にします。更新されたファイルを毎日 S3 へ転送したいと考えています。取引先は別に SFTP でしかファイルを送れません。どの組み合わせが最も適切ですか。

- A. どちらも S3 のマルチパートアップロードをスクリプトで書き、Lambda で再試行を実装する
- B. ファイルサーバーは Transfer Family、取引先の SFTP は DataSync のエージェント
- C. ファイルサーバーは DataSync、取引先の SFTP は Transfer Family
- D. どちらも AppFlow のスケジュールで転送する

??? success "答えと解説"
    **正解: C**

    オンプレミスのファイルは DataSync、SFTP の受け口は Transfer Family で S3 へ集めます。

    - A: 誤り。差分の転送と SFTP の受け口を自分で作ることになる。
    - B: 誤り。役割が逆で、取引先に DataSync のエージェントを置くことになる。
    - C: 正しい。
    - D: 誤り。AppFlow は SaaS との連携のサービスで、ファイルサーバーや SFTP の受け口には向かない。

    **スキル:** [1.4.4](../domain1.md#skill-1-4-4) / **参照:** [DataSync](../../../services/migration.md#datasync)、[Transfer Family](../../../services/migration.md#transfer-family)

### 問3 {#q3}

独自の社内 wiki に文書があり、更新は専用の API からしか取得できません。更新を検知したらすぐに、S3 を経由せず 1 件ずつナレッジベースへ入れたいと考えています。最も適切なデータソースはどれですか。

- A. Web Crawler のデータソースに社内 wiki の認証情報を入れて巡回する
- B. S3 のデータソースを作り、wiki のエクスポートを週に 1 回置く
- C. Google Drive のコネクタに wiki の API を登録する
- D. Custom のデータソースを作り、Lambda から `IngestKnowledgeBaseDocuments` で 1 件ずつ送る

??? success "答えと解説"
    **正解: D**

    Custom のデータソースは、API で文書を直接送れます。独自の wiki に向きます。

    - A: 誤り。巡回は即時の反映に向かず、API からしか取得できないという条件にも合わない。
    - B: 誤り。S3 を経由しない条件と即時の要件に反する。
    - C: 誤り。Google Drive 用のコネクタで、独自の API は登録できない。
    - D: 正しい。

    **スキル:** [1.4.4](../domain1.md#skill-1-4-4) / **参照:** [Managed と Customer-managed](../../../services/genai-apps.md#managed-kb)、[Knowledge Bases](../../../services/genai-apps.md#knowledge-bases)

- A. チャンクなしにして、1 文書を 1 チャンクで取り込む
- B. 階層チャンクにして、小さな子チャンクで検索し、親チャンクに置き換えて返す
