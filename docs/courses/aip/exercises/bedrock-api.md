# Bedrock の API 統合の問題集

### 問1 {#q1}

問い合わせの要約を、API で受けて SQS 経由で Lambda から FM に送っています。応答に最大 5 分かかるようになったので、イベントソースマッピングを作ったあとで Lambda のタイムアウトだけを 6 分に延ばしました。可視性タイムアウトは既定の 30 秒のままです。その後、同じ要約が重複して行われ、費用が増えています。最も適切な修正はどれですか。

- A. Lambda のタイムアウトを既定の 3 秒に戻し、処理が終わらないものはすぐに失敗させる
- B. SQS を FIFO キューに変えれば、可視性タイムアウトに関係なく二重の処理がなくなる
- C. FM の呼び出しに `ConverseStream` を使い、処理中のメッセージを見えない状態に保つ
- D. キューの可視性タイムアウトを Lambda のタイムアウトより長くする（公式の推奨は 6 倍以上）

??? success "答えと解説"
    **正解: D**

    可視性タイムアウトが短いと、処理中のメッセージが再び見えるようになり、FM を二重に呼びます。Lambda はイベントソースマッピングの作成時と更新時に、関数のタイムアウトが可視性タイムアウト以下であることを検証します。後から関数だけを延ばすと、このずれが起きます。

    - A: 誤り。FM の応答を待てなくなる。
    - B: 誤り。可視性タイムアウトが短ければ、FIFO でも処理中のメッセージが再び見えるようになる。
    - C: 誤り。応答の受け取り方の違いで、メッセージの可視性とは関係がない。
    - D: 正しい。

    **スキル:** [2.4.1](../domain2.md#skill-2-4-1) / **参照:** [SQS と Lambda の設定](../../../services/messaging.md#sqs-lambda-settings)、[非同期と統合](../../../services/genai-apps.md#async-integration)

### 問2 {#q2}

FM を呼ぶ API に、必須項目のない不正なリクエストが多く届き、Lambda と FM の費用が無駄になっています。バックエンドのコードを増やしたくありません。形式の検査だけを前段で行います。最も適切なものはどれですか。

- A. API Gateway のリクエスト検証でモデルのスキーマを検査する
- B. Lambda の先頭で全項目を検査するコードを書き、不正なら 400 を返す
- C. WAF のレートベースのルールで全リクエストの回数を制限する
- D. Bedrock のガードレールに必須項目のルールを書き、不正なリクエストを止める

??? success "答えと解説"
    **正解: A**

    API Gateway のリクエスト検証なら、バックエンドに届く前に不正な形式を止められます。

    - A: 正しい。
    - B: 誤り。動くがバックエンドのコードが増え、Lambda の起動の費用も残る。
    - C: 誤り。回数の制限で、形式の検査にならない。
    - D: 誤り。ガードレールは内容の検査で、API の形式は検査しない。

    **スキル:** [2.4.1](../domain2.md#skill-2-4-1) / **参照:** [リクエストの検証](../../../services/api-gateway.md#request-validation)、[非同期と統合](../../../services/genai-apps.md#async-integration)

### 問3 {#q3}

Lambda と ECS で動くアプリから Bedrock を呼びます。担当者はアクセスキーを環境変数に入れる案を出しました。セキュリティの基準で、長期の認証情報はコードにも設定にも置けません。正しい方法はどれですか。

- A. `AWS_ACCESS_KEY_ID` を Lambda の環境変数に暗号化して入れる
- B. 実行ロールを付け、SDK の認証情報チェーンに任せる
- C. アクセスキーを Secrets Manager に入れ、起動時に読み込んで SDK に渡す
- D. Bedrock の長期の API キーをコードに書き、90 日ごとに手で交換する

??? success "答えと解説"
    **正解: B**

    SDK は実行ロールの一時的な認証情報を自動で使います。

    - A: 誤り。暗号化しても長期の認証情報を設定に置いている。
    - B: 正しい。
    - C: 誤り。長期の認証情報そのものが残り、IAM ロールで足りる。
    - D: 誤り。長期の認証情報をコードに置いている。長期キーは検証用。

    **スキル:** [2.4.1](../domain2.md#skill-2-4-1) / **参照:** [SDK の基本](../../../services/sdk-resilience.md#sdk-basics)、[非同期と統合](../../../services/genai-apps.md#async-integration)

### 問4 {#q4}

1 つのアプリに 3 種類の処理があります。(a) 画面で待つ質問応答、(b) 不定期に急増するアップロードの要約で数分は待てる、(c) 夜間の 50 万件の分類で翌朝までに終えればよい。最も適切な呼び方の組み合わせはどれですか。

- A. (a) バッチ推論、(b) 同期呼び出し、(c) SQS と Lambda で非同期
- B. (a) SQS と Lambda で非同期、(b) バッチ推論、(c) 同期呼び出し
- C. (a) 同期呼び出し、(b) SQS と Lambda で非同期、(c) バッチ推論
- D. (a)〜(c) すべて Provisioned Throughput を使った同期呼び出し

??? success "答えと解説"
    **正解: C**

    待てるかどうかと量で分けます。バッチ推論は対象のモデルで 50% 引きです。

    - A: 誤り。(a) は画面で待てず、(b) の急増を同期では受けられない。
    - B: 誤り。(a) は応答を待つ必要があり、(c) に同期呼び出しは費用とスロットリングの点で不利。
    - C: 正しい。
    - D: 誤り。処理の性質の違いを無視しており、使用率が低い時間に費用がかかる。

    **スキル:** [2.4.1](../domain2.md#skill-2-4-1) / **参照:** [スループットの選択肢](../../../services/ai.md#throughput-options)、[非同期と統合](../../../services/genai-apps.md#async-integration)

### 問5 {#q5}

チャットを REST API と Lambda の非プロキシ統合で提供しています。回答に 1 分近くかかり、API がタイムアウトします。応答の変換は統合レスポンスの VTL で行っていて、エンドポイントのキャッシュも有効です。段階的に表示したいと考えています。正しい変更はどれですか。

- A. CloudFront を前に置いて、CloudFront のキャッシュでストリーミングを実現する
- B. REST API のまま統合のタイムアウトを 15 分に設定して、完成した応答を一度に返す
- C. `responseTransferMode` を `STREAM` にし、非プロキシ統合の VTL の変換とエンドポイントのキャッシュはそのまま使う
- D. 統合を Lambda プロキシに変え、`STREAM` モードにして、VTL の変換とキャッシュをやめる

    - B: 誤り。段階的な表示にならず、完成まで利用者を待たせる。
    - C: 誤り。ストリーミングは `HTTP_PROXY` か `AWS_PROXY` だけで、VTL での応答の変換とエンドポイントのキャッシュも使えない。

- B. API Gateway の WebSocket API で接続し、バックエンドから `@connections` で返す

### 問7 {#q7}

`ConverseStream` でチャットを実装しました。利用者が途中で画面を閉じたとき、ループを抜けて接続を切ります。翌月の集計で、一部の呼び出しのトークン数がアプリの記録にないことが分かりました。原因として正しいものはどれですか。

- A. `messageStart` の `usage` を読む必要があるが、実装で読み飛ばしている
- B. `contentBlockDelta` の各イベントに `usage` が入っているが、ループの途中では読めない

??? success "答えと解説"

    - A: 誤り。`messageStart` は `role` で、`usage` は入らない。
    - B: 誤り。差分のイベントに `usage` は入らない。
    - C: 正しい。
    - D: 誤り。ストリーミングでも課金される。

### 問9 {#q9}

Bedrock の呼び出しに再試行を実装します。`ThrottlingException`、`ValidationException`、`ServiceUnavailableException`、`AccessDeniedException` が発生しています。再試行の対象を正しく選んでいるものはどれですか。

- A. どれも再試行せず、すべてを別リージョンの呼び出しに切り替える
- B. 4 つすべてを、指数バックオフとジッターで同じ回数まで再試行する

??? success "答えと解説"
    **正解: D**

    - B: 誤り。`ValidationException` と `AccessDeniedException` は再試行しても成功しない。
    - C: 誤り。再試行で直らないものを選んでいる。
