# ログの仕組みの問題集

対象の解説: [CloudTrail](../../../services/observability.md#cloudtrail)、[CloudWatch Logs](../../../services/observability.md#cloudwatch-logs)、[Security Lake](../../../services/threat-detection.md#security-lake)、[VPC フローログ](../../../services/networking.md#flow-logs)

### 問1 {#q1}

ある金融機関は、監査のために API の記録を 7 年間保持し、保持期間中は誰にも消されないようにする必要があります。検索は監査のときに年に数回だけで、費用はできるだけ抑えます。

最も適切な保存先の構成はどれですか。

- A. CloudWatch Logs のロググループの保持期間を 7 年にし、IAM で削除の権限を制限して、メトリクスフィルターで削除の操作を監視する
- B. ログ保管アカウントの S3 に出力し、ライフサイクルで安いクラスへ移して Object Lock で保護する
- C. OpenSearch Service のドメインに取り込み、UltraWarm へ移して 7 年間保持する
- D. CloudTrail の Event history を監査のときに検索し、結果を S3 へダウンロードする

??? success "答えと解説"
    **正解: B**

    検索の頻度が低い長期の保管は S3 が向いています。Object Lock で削除を防ぎ、ライフサイクルで費用を下げられます。

    - A: 誤り。取り込みと保管の費用が高く、IAM の制限だけでは権限を持つ人に消される余地が残ります。
    - B: 正しい。
    - C: 誤り。クラスターの運用と費用がかかり、低頻度の検索には過剰です。
    - D: 誤り。Event history は直近 90 日の管理イベントだけです。

    **スキル:** [1.2.1](../domain1.md#skill-1-2-1) / **参照:** [どのログを見るか](../../../services/threat-detection.md#log-sources)、[Object Lock](../../../services/s3.md#object-lock)

### 問2 {#q2}

ある企業は CloudWatch Logs の費用を下げるため、2 種類のログの保存先を見直しています。1 つは認証のログで、メトリクスフィルターでアラームを作り、サブスクリプションフィルターで SIEM に送っています。もう 1 つは調査のときにだけ検索する大量のデバッグログです。

ログクラスの選択として正しいものはどれですか。

- A. 両方を新しい Essentials のロググループへ移す。必要な機能は Essentials でも使える
- B. 認証のログのロググループを `update-log-group` で Essentials へ変更し、フィルターは Logs Insights の定期クエリに置き換える
- C. 両方を Standard のまま、ロググループの KMS 暗号化をやめて費用を下げる
- D. 認証のログは Standard のままにし、デバッグログは新しい Essentials のロググループへ出力する

??? success "答えと解説"
    **正解: D**

    Essentials は取り込みの費用が安い代わりに、メトリクスフィルターとサブスクリプションフィルターを使えません。ログクラスは作成後に変更できないので、新しいロググループを作ります。

    - A: 誤り。認証のログで必要なフィルターが使えません。
    - B: 誤り。作成後に変更できず、変更しても必要な機能を失います。
    - C: 誤り。暗号化をやめても取り込みの費用の問題は解決しません。
    - D: 正しい。

    **スキル:** [1.2.1](../domain1.md#skill-1-2-1) / **参照:** [ログクラス](../../../services/observability.md#log-classes)

### 問3 {#q3}

大量の VPC フローログを 3 年間保管します。月に数回、特定の期間だけを SQL で調べます。既存のフローログはなく、これから作成します。クエリの速度と費用を重視しています。

最も適切なものはどれですか。

- A. CloudWatch Logs に配信し、Logs Insights で 3 年分を検索する
- B. Kinesis Data Streams に配信し、コンシューマーがテキストのまま RDS へ保存する
- C. S3 に Parquet 形式と Hive 互換のプレフィックスで配信し、Athena で検索する
- D. S3 にテキスト形式で配信し、調査のときに全ファイルをダウンロードして grep で検索する

??? success "答えと解説"
    **正解: C**

    フローログは S3 に Parquet で配信でき、テキストより高速に検索できて容量も減ります。Hive 互換のプレフィックスは Athena のパーティションに使えます。

    - A: 誤り。長期の保管では取り込みと保管の費用が高くなります。
    - B: 誤り。フローログの配信先は CloudWatch Logs、S3、Firehose で、Kinesis Data Streams には直接配信できません。RDS も不向きです。
    - C: 正しい。
    - D: 誤り。SQL の要件を満たさず、調査に時間もかかります。

    **スキル:** [1.2.1](../domain1.md#skill-1-2-1) / **参照:** [VPC フローログ](../../../services/networking.md#flow-logs)、[Athena のパーティション](../../../services/streaming.md#athena-partitions)

### 問4 {#q4}

CloudWatch Logs の費用が毎月増えています。調べると、作成時に何も指定していないロググループが多数ありました。担当者が保持期間を 90 日に設定した翌日に、90 日より古いログがまだ残っていることに気づきました。

正しい説明はどれですか。

- A. 既定の保持期間は無期限である。保持期間を超えたログは印が付けられ、実際の削除は通常 72 時間以内に行われる
- B. 既定の保持期間は 90 日である。今回の設定は新しいログにだけ適用される
- C. 既定の保持期間は無期限である。古いログを消すには別途 `DeleteLogStream` を実行する必要がある
- D. 既定の保持期間は 30 日である。残っているのは S3 エクスポートのコピーである

??? success "答えと解説"
    **正解: A**

    既定ではログは無期限に保存されます。保持期間を超えたログはすぐには消えず、通常 72 時間以内に削除されます。削除の印が付いたあとは、アーカイブの保管料金の対象外です。

    - A: 正しい。
    - B: 誤り。既定は無期限で、設定は既存のログにも効きます。
    - C: 誤り。保持期間の設定で自動的に削除されます。
    - D: 誤り。既定は無期限で、エクスポートの有無は関係ありません。

    **スキル:** [1.2.1](../domain1.md#skill-1-2-1) / **参照:** [ログの保持](../../../services/observability.md#log-retention)

### 問5 {#q5}

組織の全アカウントの API を記録し、ログ保管アカウントの S3 に集めます。個別のメンバーアカウントの管理者が記録を止められないようにし、各アカウントでの作業は増やしたくありません。

最も適切なものはどれですか。

- A. 各メンバーアカウントで証跡を作り、ログ保管アカウントのバケットへ出力して IAM で変更を制限する
- B. 各アカウントの Event history を日次で S3 にエクスポートする Lambda を StackSets で配布する
- C. ログ保管アカウントで単一アカウントの証跡を作り、すべてのアカウントのイベントを読み取る権限を与える
- D. 管理アカウントか委任管理者で組織の証跡を作る。メンバーのユーザーは証跡を削除したりログ記録を止めたりできない

??? success "答えと解説"
    **正解: D**

    組織の証跡は全メンバーのイベントを記録し、コピーが各アカウントに作られます。メンバーのユーザーは見ることはできますが、削除や停止はできません。

    - A: 誤り。動きますが、各アカウントでの作業が増え、管理者が止められる余地も残ります。
    - B: 誤り。保守が必要で、データイベントも記録できません。
    - C: 誤り。単一アカウントの証跡は他のアカウントのイベントを記録しません。
    - D: 正しい。

    **スキル:** [1.2.2](../domain1.md#skill-1-2-2) / **参照:** [証跡](../../../services/observability.md#cloudtrail-trails)、[マルチアカウントのパターン](../../../services/governance.md#multi-account-patterns)

### 問6 {#q6}

機密データのバケットは 2 つだけで、読み取りと削除の操作を記録する必要があります。組織の証跡はありますが、S3 のオブジェクトの操作が記録されていません。全バケットを対象にすると費用が大きくなるので避けます。

どの設定を追加しますか。

- A. 高度なイベントセレクターで、2 つのバケットの S3 データイベントを記録する
- B. 証跡の管理イベントの読み取りを有効にする
- C. CloudTrail Insights を有効にして S3 の操作の基準を作らせる
- D. S3 のサーバーアクセスログを全バケットで有効にして証跡に統合する

??? success "答えと解説"
    **正解: A**

    オブジェクトの `GetObject` や `DeleteObject` はデータイベントで、既定では記録されません。イベントセレクターで対象のバケットだけに絞れば、費用を抑えられます。

    - A: 正しい。
    - B: 誤り。オブジェクトの操作は管理イベントではありません。
    - C: 誤り。Insights は通常と違う量を示すもので、操作の記録を増やしません。
    - D: 誤り。全バケットが対象で要件に反し、証跡に統合する機能もありません。

    **スキル:** [1.2.2](../domain1.md#skill-1-2-2) / **参照:** [イベントの種類](../../../services/observability.md#cloudtrail-events)

### 問7 {#q7}

30 のアカウントのアプリのロググループを、ログ専用アカウントへほぼリアルタイムで集めます。送信元のアカウントの権限をログ専用アカウントに持たせることは避け、ログ専用アカウントの Firehose で S3 に保存します。

構成として正しいものはどれですか。

- A. ログ専用アカウントがロググループの ACL を変更し、各アカウントのログを定期的に読み取る
- B. 各アカウントで毎時 `CreateExportTask` を実行し、ログ専用アカウントのバケットへ直接エクスポートする
- C. 各アカウントの Lambda で `FilterLogEvents` を定期実行して、ログ専用アカウントの API を呼ぶ
- D. ログ専用アカウントに論理的な宛先とアクセスポリシーを作り、各アカウントのサブスクリプションフィルターの宛先にする

??? success "答えと解説"
    **正解: D**

    クロスアカウントの共有は、受信側で宛先（`PutDestination`）とアクセスポリシー（`PutDestinationPolicy`）を作り、送信側がサブスクリプションフィルターを作ります。

    - A: 誤り。ロググループに ACL の仕組みはありません。
    - B: 誤り。エクスポートはバッチで、ほぼリアルタイムになりません。
    - C: 誤り。実装と保守が必要で、遅延も大きくなります。
    - D: 正しい。

    **スキル:** [1.2.2](../domain1.md#skill-1-2-2) / **参照:** [サブスクリプションフィルターの設定](../../../services/observability.md#subscription-settings)

東京のロググループのログを、別のアカウントのバージニア北部にある Firehose へ送りたいと考えています。担当者はバージニア北部に論理的な宛先を作り、東京のロググループから指定しましたが、サブスクリプションフィルターを作成できません。

適切な修正はどれですか。

- A. Firehose を東京に作り直し、宛先も同じ東京に作る。宛先の先のリソースは同じリージョンでなければならない

数百台の EC2 の OS ログとメモリの使用率を CloudWatch に集め、設定を全台で同じに保ちます。設定ファイルを各インスタンスに配る作業は避け、インスタンスに付与する権限は最小にします。

### 問10 {#q10}

調査のために、CloudTrail のログが配信後に変更されていないことを示す必要があります。担当者が「ログファイルの検証を有効にしたので、自動で改ざんが通知される」と話しています。

正しい理解はどれですか。

- A. 検証を有効にすれば、変更があると EventBridge に自動で通知される
- B. 検証を有効にすると 1 時間ごとにダイジェストファイルが配信される。確認には `validate-logs` の実行が必要である
- C. 検証を有効にすると S3 のオブジェクトが自動で書き込み禁止になるので、ルートユーザーを含めて改ざんそのものができなくなる
- D. 検証はルートユーザーでの実行が必須で、それ以外の主体はダイジェストファイルを使えない

    有効にするとログファイルのハッシュと、それを参照する署名付きのダイジェストファイルが 1 時間ごとに配信されます。有効にするだけでは検証されません。実際の確認は `validate-logs` で行います。

    - A: 誤り。自動の通知はありません。
    - B: 正しい。
    - C: 誤り。検証は変更を検出するもので、防ぐのは Object Lock などの別の機能です。
    - D: 誤り。CLI の権限があれば実行できます。

### 問11 {#q11}

複数のアカウントと 4 つのリージョンの CloudTrail、VPC フローログ、WAF ログを、他社の SIEM に共通の形式で渡します。独自の変換処理を作らず、SIEM は新しいファイルを SQS の通知で知って取り込みます。

最も適切な構成はどれですか。

- A. Security Lake の各リージョンに 1 つずつデータアクセスのサブスクライバーを作り、東京の通知だけを SIEM で読む
- B. Security Lake を東京で有効にし、東京にクエリアクセスのサブスクライバーを作る
- C. 各ログを CloudWatch Logs に集め、Lambda で共通の形式へ変換してから SIEM に送る
- D. Security Lake で 1 つのロールアップリージョンに集約し、そのリージョンでデータアクセスのサブスクライバーを作る

??? success "答えと解説"
    **正解: D**

    Security Lake は OCSF と Parquet に変換します。サブスクライバーは作成したリージョンのデータだけを見られるので、複数のリージョンを渡すにはロールアップリージョンで作ります。データアクセスは SQS か HTTPS で通知を受けます。

    - A: 誤り。東京の通知だけでは他のリージョンのデータが届きません。
    - B: 誤り。クエリアクセスは通知による取り込みではなく、東京のデータだけになります。
    - C: 誤り。独自の変換処理が必要で、要件に反します。
    - D: 正しい。

    **スキル:** [1.2.3](../domain1.md#skill-1-2-3) / **参照:** [Security Lake](../../../services/threat-detection.md#security-lake)

### 問13 {#q13}

オンプレミスのファイアウォールのログを Security Lake に取り込みます。カスタムソースを作り、JSON Lines のファイルを 1 日分まとめて書き込みました。1 つのファイルには、ネットワークの活動と認証の 2 種類の OCSF クラスの記録が混ざっています。クエリの結果が正しく返りません。

修正として適切なものはどれですか。

- A. ファイルのサイズを 5 MB 以下にする。Security Lake は小さいファイルだけを受け付ける

### 問14 {#q14}

すでに VPC フローログを S3 に出力しています。Security Lake を導入するとき、フローログをソースに追加します。チームは既存のログの構成が壊れないか心配しています。

正しい説明はどれですか。
