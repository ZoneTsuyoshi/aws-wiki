# Organizations と Control Tower の問題集

対象の解説: [Organizations](../../../services/governance.md#organizations)、[Control Tower](../../../services/governance.md#control-tower)、[委任管理者](../../../services/governance.md#delegated-admin)

### 問1 {#q1}

合併で引き継いだ組織に SCP を適用しようとしましたが、ポリシーの作成や適用の画面が使えません。この組織は一括請求だけを目的に作られました。メンバーアカウントは 30 あります。最初に必要な操作はどれですか。

- A. 全メンバーアカウントを組織から外し、管理アカウントを作り直して、新しい組織に招待し直す
- B. 管理アカウントの IAM ポリシーに `organizations:*` を付けて、SCP の画面の表示の権限を与える
- C. 各メンバーアカウントに `FullAWSAccess` の IAM ポリシーを付けて、SCP の適用を受け入れる準備をする
- D. 機能セットをすべての機能に変更し、ルートで SCP のポリシータイプを有効にする

??? success "答えと解説"
    **正解: D**

    一括請求のみの機能セットでは SCP を使えません。すべての機能への変更は、組織を作り直さずにできます。

    - A: 誤り。作り直す必要はありません。
    - B: 誤り。権限の問題ではなく、機能セットの問題です。
    - C: 誤り。IAM ポリシーは SCP の有効化に関係しません。
    - D: 正しい。

    **スキル:** [6.1.1](../domain6.md#skill-6-1-1) / **参照:** [機能セット](../../../services/governance.md#org-feature-sets)

### 問2 {#q2}

人事の部署ごとに OU を作っていた会社で、同じ部署の本番と開発に別々の SCP を適用できず困っています。新しいポリシーで本番を止めた事故もありました。OU の設計を見直すときの方針として最も適切なものはどれですか。

- A. 組織図と同じ階層を維持し、例外があるアカウントには個別に IAM ポリシーで拒否を書く
- B. 全アカウントを 1 つの OU に集め、SCP の条件でアカウント ID を 1 つずつ列挙して分岐させる
- C. 適用したいポリシーの違いで OU を分け、新しいポリシーは Policy Staging OU で試してから広げる
- D. 本番のアカウントを管理アカウントに統合し、SCP の影響を受けないようにする

??? success "答えと解説"
    **正解: C**

    OU は組織図ではなく、適用したいポリシーの違いで分けます。新しいポリシーをステージングの OU で試すのが公式の推奨です。

    - A: 誤り。本番と開発の分離の問題が解決しません。
    - B: 誤り。SCP の条件が複雑になり、サイズの上限にも当たります。
    - C: 正しい。
    - D: 誤り。管理アカウントにワークロードを置かないのが原則です。

    **スキル:** [6.1.1](../domain6.md#skill-6-1-1) / **参照:** [OU の設計](../../../services/governance.md#org-ous)

### 問3 {#q3}

SCP で全リージョンの操作を東京だけに制限しました。監査で、管理アカウントの IAM ユーザーがオレゴンで EC2 を起動していたことが判明しました。担当者は SCP の不具合だと報告しています。正しい説明と対策はどれですか。

- A. SCP は管理アカウントに効かないので、管理アカウントの権限を IAM で絞り、ワークロードを置かない
- B. SCP の反映の遅れなので、もう一度適用すれば管理アカウントも制限される
- C. EC2 の操作はサービスリンクロールの扱いなので SCP の対象外であり、宣言型ポリシーに切り替える
- D. SCP はルートに付けないと効かないので、管理アカウントのルートに直接付けて再評価する

??? success "答えと解説"
    **正解: A**

    SCP は管理アカウントのユーザーとロールに影響しません。管理アカウントを小さく保つ理由の 1 つです。

    - A: 正しい。
    - B: 誤り。設計どおりの動きで、遅れではありません。
    - C: 誤り。IAM ユーザーの操作の話で、サービスリンクロールの話ではありません。
    - D: 誤り。ルートに付けても管理アカウントには効きません。

    **スキル:** [6.1.1](../domain6.md#skill-6-1-1), [6.1.3](../domain6.md#skill-6-1-3) / **参照:** [SCP](../../../services/governance.md#scp)

### 問4 {#q4}

Organizations のアカウントの組織設計で、AWS の推奨に合う分け方を確認します。セキュリティの統制のためのアカウント、共有のネットワーク、業務のワークロード、実験の環境を分けます。推奨の説明として適切なものはどれですか。

- A. すべての機能を管理アカウントに集め、ログの保管もそこに置くことで管理の入口を 1 つにする
- B. 部署ごとの OU の中に、ログの保管、監査、ネットワーク、本番、開発を入れて、部署ごとにコピーする
- C. Security、Infrastructure、Workloads、Sandbox などの OU に分ける
- D. OU の階層は使わず、アカウント名の接頭辞でセキュリティの統制を切り替える

??? success "答えと解説"
    **正解: C**

    AWS の推奨の基礎的な OU は Security と Infrastructure で、Workloads や Sandbox などを追加します。

    - A: 誤り。管理アカウントには最小限のものだけを置きます。
    - B: 誤り。共有の統制のアカウントの重複が増えます。
    - C: 正しい。
    - D: 誤り。統制はポリシーで行い、名前の規約では効きません。

    **スキル:** [6.1.1](../domain6.md#skill-6-1-1) / **参照:** [マルチアカウントのパターン](../../../services/governance.md#multi-account-patterns)

### 問5 {#q5}

既存の組織に Control Tower を導入します。予防的、検出的、プロアクティブの 3 種類のコントロールを説明します。CloudFormation で不適合なリソースを作らせない統制を追加したいとき、選ぶ種類と実装の組み合わせはどれですか。

- A. 検出的コントロールで、Config ルールが作成前に CloudFormation を拒否する
- B. 予防的コントロールで、CloudFormation の StackSets を組織に展開してテンプレートを検証する
- C. 検出的コントロールで、Security Hub がテンプレートを評価して、不適合なら作成を取り消す
- D. プロアクティブコントロールで、CloudFormation Hooks が作成前に確認して不適合なら作らせない

??? success "答えと解説"
    **正解: D**

    プロアクティブコントロールは CloudFormation Hooks で実装され、不適合なリソースをプロビジョニングさせません。

    - A: 誤り。検出的は作成後に見つけるものです。
    - B: 誤り。予防的は SCP、RCP、宣言型ポリシーで実装され、StackSets ではありません。
    - C: 誤り。Security Hub はそのような取り消しをしません。
    - D: 正しい。

    **スキル:** [6.1.2](../domain6.md#skill-6-1-2) / **参照:** [コントロール](../../../services/governance.md#ct-controls)

### 問6 {#q6}

Control Tower のランディングゾーンで、独自の SCP とテンプレートを追加で展開します。チームは CloudFormation を使っており、Git で変更を管理したいと考えています。また別のチームは Terraform でアカウントを発行します。組み合わせとして適切なものはどれですか。

- A. CfCT で SCP とテンプレートを追加し、Terraform のチームは AFT を使う
- B. 各アカウントの管理者が SCP を直接編集し、Terraform のチームは Control Tower を使わない
- C. Control Tower の必須コントロールを書き換え、Terraform の状態ファイルを管理アカウントの S3 に置く
- D. CfCT で Terraform の状態を管理し、CloudFormation のチームは AFT を使う

??? success "答えと解説"
    **正解: A**

    Customizations for Control Tower はテンプレートとポリシーの追加の展開に使います。Account Factory for Terraform は Terraform でアカウントを発行します。

    - A: 正しい。
    - B: 誤り。SCP の直接編集はドリフトの原因で、Control Tower の統制も外れます。
    - C: 誤り。必須コントロールは書き換えません。
    - D: 誤り。役割が逆です。

    **スキル:** [6.1.2](../domain6.md#skill-6-1-2) / **参照:** [ドリフトと拡張](../../../services/governance.md#ct-drift)

既存の 100 アカウントの組織に Control Tower を導入します。アカウントを作り直さず、段階的に統制下に入れたいと考えています。また、OU に新しいコントロールを適用したときの範囲も確認しています。正しい説明はどれですか。（2つ選択）

- A. 既存の組織にランディングゾーンを作り、OU を登録して配下のアカウントを統制下に入れられる
- B. Control Tower は新しい組織でしか使えないので、新規の組織へアカウントを移す必要がある

### 問9 {#q9}

組織の外のパートナーが、S3 バケットのポリシーの誤りで組織のデータを読めていました。再発を防ぐ統制を追加します。担当者は SCP で `s3:GetObject` を組織外に拒否すると提案しました。提案の評価と代案はどれですか。

- A. 提案で十分。SCP は組織内のリソースへのアクセスをすべて制限するので、外部の主体も拒否される
- B. 提案は不適切で、外部の主体には SCP が効かない。RCP で外部の主体のアクセスを拒否する
- C. 提案は不適切で、代わりに各パートナーに IAM ユーザーを発行して SCP の対象にする

### 問10 {#q10}

組織全体で VPC からインターネットへの直接の出入りをなくします。サービスリンクロールが作るリソースも含めます。将来 AWS が新しい API を追加しても、基準を維持したいと考えています。最も適切なものはどれですか。
