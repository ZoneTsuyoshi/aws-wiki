# 転送時の暗号化の問題集

対象の解説: [転送時の TLS](../../../services/certificates.md#tls-in-transit)、[VPC エンドポイント](../../../services/networking.md#vpc-endpoints)、[保存時と転送時](../../../services/kms.md#at-rest-in-transit)

### 問1 {#q1}

CloudFormation で作った ALB の HTTPS リスナーに、セキュリティスキャンで TLS 1.0 と 1.1 が有効だと指摘されました。同じ日にコンソールで作った ALB は指摘されていません。テンプレートには `SslPolicy` の指定がありません。原因と修正の組み合わせとして正しいものはどれですか。

- A. CloudFormation で作った ALB は TLS を終端しないので、ターゲットの Web サーバーの設定を変えて TLS 1.2 以上にする必要がある
- B. 既定のセキュリティポリシーが作成方法で異なるので、テンプレートで `SslPolicy` を明示する
- C. ACM の証明書が古いアルゴリズムで発行されたので、新しい証明書に差し替えてリスナーを作り直す
- D. WAF のウェブ ACL をリスナーに関連付け、TLS のバージョンを条件にして古いクライアントを拒否する

??? success "答えと解説"
    **正解: B**

    コンソールの既定は `ELBSecurityPolicy-TLS13-1-2-Res-PQ-2025-09`、CLI や CloudFormation の既定は `ELBSecurityPolicy-2016-08` です。IaC では明示します。

    - A: 誤り。HTTPS リスナーは ALB で TLS を終端します。
    - B: 正しい。
    - C: 誤り。証明書は許可する TLS のバージョンを決めません。
    - D: 誤り。リスナーのポリシーを直すのが正しい方法です。

    **スキル:** [5.1.1](../domain5.md#skill-5-1-1) / **参照:** [転送時の TLS](../../../services/certificates.md#tls-in-transit)

### 問2 {#q2}

組織の全アカウントの S3 で、HTTPS 以外のアクセスを確実に拒否します。バケットは数千個あり、各チームが作成します。個別のバケットポリシーの設定漏れを許さず、新しいバケットにも自動で効くようにします。最も適切な方法はどれですか。

- A. Config ルールで `aws:SecureTransport` の条件がないバケットを週次で検出し、担当者に修正を依頼して、完了の期限を管理する
- B. すべてのバケットのデフォルト暗号化を SSE-KMS にして、KMS キーのキーポリシーで HTTPS を要求する
- C. S3 のパブリックアクセスブロックを組織で有効にして、HTTP での接続をネットワーク層で遮断する
- D. RCP で `aws:SecureTransport` が `false` のときの S3 へのアクセスを拒否する

??? success "答えと解説"
    **正解: D**

    RCP は組織のリソースへのアクセスの上限で、バケットポリシーに依存せず、新しいバケットにも効きます。管理アカウントのリソースには効かないので、管理アカウントにはワークロードを置きません。

    - A: 誤り。検出で後追いになり、設定漏れの間は HTTP を許します。
    - B: 誤り。保存時の暗号化の話です。
    - C: 誤り。パブリックアクセスブロックは公開の制御で、HTTP を拒否しません。
    - D: 正しい。

    **スキル:** [5.1.1](../domain5.md#skill-5-1-1) / **参照:** [RCP](../../../services/governance.md#rcp)

### 問3 {#q3}

RDS for PostgreSQL 14 の本番インスタンスで、暗号化しない接続を拒否するよう求められました。アプリの接続文字列には `sslmode=disable` のものが残っている可能性があります。デフォルトのパラメータグループを使っています。正しい進め方はどれですか。

- A. 接続設定を確認し、カスタムパラメータグループで `rds.force_ssl` を 1 にする
- B. デフォルトのパラメータグループの `rds.force_ssl` を直接 1 に変更し、再起動の後でアプリの接続設定を確認する
- C. セキュリティグループに TLS を条件とするルールを追加して、平文の接続を遮断する
- D. ストレージの暗号化を有効にすると、接続も自動で TLS を要求するようになる

??? success "答えと解説"
    **正解: A**

    14 以前は既定が 0 です。変更にはカスタムパラメータグループが必要です。有効にすると平文の接続は失敗するので、アプリの設定を先に直します。

    - A: 正しい。
    - B: 誤り。デフォルトのパラメータグループは変更できません。
    - C: 誤り。セキュリティグループは TLS を判定できません。
    - D: 誤り。保存時の暗号化は転送時とは別です。

    **スキル:** [5.1.1](../domain5.md#skill-5-1-1) / **参照:** [RDS の SSL/TLS](../../../services/databases.md#rds-ssl)

### 問4 {#q4}

EC2 と Fargate から EFS をマウントするアプリで、NFS の通信の暗号化を監査で確認されました。ファイルシステムは作成時に保存時の暗号化を有効にしています。通信の暗号化を実現する方法はどれですか。

- A. 保存時の暗号化が有効なら通信も自動で暗号化されるので、追加の作業は不要である
- B. EFS のファイルシステムを作り直して、転送時の暗号化を有効にする属性を指定する
- C. EFS マウントヘルパーのマウントオプション `tls` を指定する
- D. VPC 内の通信は常に暗号化されるので、監査には VPC の構成図を提出する

??? success "答えと解説"
    **正解: C**

    転送時の暗号化はマウント時のオプションです。マウントヘルパーを使うと TLS の接続を管理してくれます。

    - A: 誤り。保存時と転送時は別です。
    - B: 誤り。ファイルシステムの属性ではなく、マウントの設定です。
    - C: 正しい。
    - D: 誤り。インスタンスの種類や経路によって自動の暗号化の対象外になります。

    **スキル:** [5.1.1](../domain5.md#skill-5-1-1) / **参照:** [EFS の暗号化](../../../services/storage.md#efs-encryption)

### 問5 {#q5}

オンプレミスのサーバーが Direct Connect 経由で S3 に大量のファイルを送ります。インターネットには出したくありません。担当者が VPC に S3 のゲートウェイエンドポイントを作りましたが、オンプレミスからは届きません。正しい修正はどれですか。

- A. ゲートウェイエンドポイントのルートテーブルに、オンプレミスの CIDR を追加して経路を作る
- B. S3 のインターフェイスエンドポイントを作り、オンプレミスの DNS で名前解決できるようにする
- C. VPC に NAT ゲートウェイを追加し、オンプレミスからの通信を NAT 経由で S3 へ送る
- D. Transit Gateway を追加し、ゲートウェイエンドポイントをアタッチして経路を共有する

??? success "答えと解説"
    **正解: B**

    ゲートウェイエンドポイントは VPC の外から使えません。インターフェイスエンドポイントはプライベート IP を持ち、Direct Connect や VPN の先からも届きます。

    - A: 誤り。ゲートウェイエンドポイントは VPC の外から使えません。
    - B: 正しい。
    - C: 誤り。インターネットに出ることになり、要件に反します。
    - D: 誤り。ゲートウェイエンドポイントはアタッチできません。

    **スキル:** [5.1.2](../domain5.md#skill-5-1-2) / **参照:** [エンドポイントの選び方](../../../services/networking.md#endpoint-settings)

### 問6 {#q6}

VPC 内のアプリに機密データのバケットを読ませます。要件は 2 つです。バケットにはそのエンドポイント経由でしか届かないこと。そのエンドポイントからは承認済みのバケットにしか届かないこと。持ち出しの経路を減らす目的です。適切な組み合わせはどれですか。（2つ選択）

- A. バケットポリシーで、`aws:SourceVpce` が対象のエンドポイントでないアクセスを拒否する
- B. エンドポイントポリシーで、`Resource` を承認済みのバケットに限定する
- C. VPC のセキュリティグループのアウトバウンドで S3 のプレフィックスリストを拒否する
- D. S3 のパブリックアクセスブロックをアカウント全体で有効にする
- E. エンドポイントのルートを全サブネットのルートテーブルから外す

??? success "答えと解説"
    **正解: A, B**

    バケットポリシーで「このバケットへの経路」を、エンドポイントポリシーで「このエンドポイントから届く先」を絞ります。両方の方向が必要です。

    - A: 正しい。
    - B: 正しい。
    - C: 誤り。セキュリティグループに拒否のルールはありません。
    - D: 誤り。公開を防ぐ設定で、経路の制限ではありません。
    - E: 誤り。アプリがエンドポイントを使えなくなります。

    **スキル:** [5.1.2](../domain5.md#skill-5-1-2) / **参照:** [エンドポイントポリシー](../../../services/networking.md#endpoint-policies)

### 問7 {#q7}

自社の VPC の決済 API を、別の会社の VPC にだけ公開します。お互いの CIDR は重複しており、VPC 全体をつなぎたくありません。TLS は NLB の背後のアプリで終端しています。最も適切な構成はどれですか。

- A. 両社の VPC を VPC ピアリングでつなぎ、セキュリティグループで API のポートだけを許可する
- B. Transit Gateway を両社で共有し、ルートテーブルで API のサブネットだけを許可する
- C. 自社の NLB を使って PrivateLink のエンドポイントサービスを公開し、相手のアカウントを許可する
- D. API をインターネットに公開し、WAF の IP セットで相手の NAT の IP だけを許可する

??? success "答えと解説"
    **正解: C**

    PrivateLink なら VPC 全体をつながず、CIDR が重複していても、特定のサービスだけを公開できます。

    - A: 誤り。CIDR が重複しているとピアリングできません。
    - B: 誤り。CIDR の重複の問題が残り、ネットワークの接続になります。
    - C: 正しい。
    - D: 誤り。プライベートな接続の要件を満たしません。

    **スキル:** [5.1.2](../domain5.md#skill-5-1-2) / **参照:** [VPC エンドポイント](../../../services/networking.md#vpc-endpoints)

### 問8 {#q8}

インターフェイスエンドポイントを VPC に作りましたが、アプリは今も `secretsmanager` のパブリック IP を解決し、NAT 経由で通信しています。エンドポイントはサブネットに配置され、状態は Available です。まず確認すべきものはどれですか。

- A. エンドポイントのプライベート DNS 名が有効で、VPC の DNS の属性も有効か

同じ VPC の 2 台の EC2 は、自動で転送時に暗号化される対応インスタンスタイプです。担当者が負荷分散のため間に NLB を置きました。別の担当者は「暗号化は NLB を挟んでも続く」と説明しています。また、監査は全区間の暗号化を求めています。正しい判断はどれですか。

- A. 同じ VPC なら Nitro の暗号化は常に効くので、担当者の説明は正しく、追加の作業は不要である
- B. NLB を通る通信は対象外なので、経路を問わず暗号化するためアプリの TLS を使う

- A. S3 のデフォルト暗号化を SSE-KMS に変更し、学習データを暗号化する
